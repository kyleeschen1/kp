First decision: what is the unit of motion?

Proposed runtime pipeline
1. Semantic HTML
KaTeX source and target are already laid out in the DOM for accessibility.
->
2. Snapshot
Measure source and target token boxes, baselines, styles, and stable IDs.
->
3. WebGL Overlay
Hide visual HTML during motion; animate textured quads in screen space.
A

Semantic Tokens

Add stable token IDs while rendering math, then map those IDs onto KaTeX spans. Best for meaningful matches like "same x", "same row", or "same denominator". Recommended for V1 if we control the math source.

B

KaTeX DOM Groups

Group existing KaTeX spans by class/text/order after render. Faster to prototype, but brittle when KaTeX changes markup or when repeated symbols need semantic identity.

C

Large Texture Blocks

Rasterize whole subexpressions, rows, or equation lines. Highest visual fidelity at first, but less expressive: fewer tokens can independently move or match.

Recommendation

Use semantic tokens for identity and matching, but allow fallback block textures for complex KaTeX constructs that are hard to split safely.
