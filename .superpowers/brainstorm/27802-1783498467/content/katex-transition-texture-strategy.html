A

DOM Raster Token Textures

Snapshot each token/subexpression from the already-rendered KaTeX DOM into a texture atlas. Best V1 path: it preserves KaTeX's exact visual output and keeps WebGL as a compositor.

B

KaTeX SVG/MathML Texture Path

Ask KaTeX for SVG-ish output or reconstruct SVG snippets, then rasterize those. Cleaner than arbitrary DOM capture if viable, but may diverge from the visible HTML renderer.

C

Native WebGL Glyph Renderer

Render symbols from font atlases or SDF/MSDF glyphs. Potentially powerful long-term, but it means rebuilding a large part of KaTeX layout and typography in WebGL.

Recommendation

Use DOM raster textures for V1. Treat WebGL as a transition compositor, not a math typesetting engine.
