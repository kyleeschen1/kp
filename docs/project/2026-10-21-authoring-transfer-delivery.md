# Authoring transfer through an existing calculus owner

Approved by “go for as long as possible” after the proposed authoring path,
with explicit direction to commit coherent work. Theseus owns execution status.
This makes that direction concrete; it does not reopen completed performance
runs or accept the earlier calculus presentation.

Outcome: an author can discover, check, preview and reproduce a meaningful
calculus source variation through existing mathematics, with honest diagnostics
and measured source-to-host transfer. Establish what requires engine work and
what is source-only. No live-model accuracy or learning-effectiveness claim.

Learner assumption: familiar with single-variable derivatives and composition,
asking why zero derivative can coexist with nonzero finite change. Primary
mathematics: inner x², outer 3u, evaluated at x=0. First-order output prediction
is zero but finite output change is 3h². Transfer: inner -x², outer u², evaluated
at x=1; both local rates are negative and their product is positive. These must
pass the existing bounded expression/differentiation/interval owner before use.
This uses a model already available, not arbitrary symbolic chain-rule animation.

Canonical source authority: `compileChangeSource` and existing math expression,
differentiation and interval validation. Host `/experiments/change-propagation/`;
native KaTeX static notation plus existing parameter/comparison paint, shared
focus-deck input and clock. Preserve five-step projection, layout, timing and
controls. Do not promote its unaccepted aesthetics or claim a certified native
symbolic rewrite. Existing default source remains unchanged.

Required packages, ordered by dependency:

1. `source-audit`: write both selected sources and their short explanation brief;
   check their intended mathematical distinctions, characterize limitations and
   source effort. A rejected requested capability must remain a located gap.
2. `entrypoint`: connect the existing calculus owner to supported task discovery,
   cheap starter loading and read-only checking. Separate source/model authority
   from host presentation where required, retaining compatibility. Extend the
   complete task inventory and cost safeguards; no parallel registry/compiler.
3. `workflow`: make exact selected-source preview/recovery inspectable through
   the existing host. Repair demonstrated source coherence or failed-preview
   lifecycle bugs at their owners, preserving last valid output. Reuse existing
   session/staging helpers where their contract fits. No new editor framework.
4. `transfer`: exercise both sources and meaningful changed-task/invalid cases
   through actual CLI and browser; record exact applied source identity, source
   variation versus engine intervention, diagnostics, static reading and seek/
   reverse behavior. Keep editorial quality distinct from mathematical checks.
5. `integration`: concise domain packet, full relevant types/deterministic checks,
   production loading/cost evidence and a working local review packet. Record
   limitations and next decisions; commit and verify remote backup.

Each package is independently recoverable. Start with focused mathematical and
API checks; use the existing scope-specific browser command for actual host
acceptance. Run full suite/types/build at final integration after owner changes;
measure performance separately from expensive concurrent checks. Generated
inventories follow their generators, never hand editing. New browser checks use
committed entrypoints. Preserve all unrelated dirty files.

Allowed: the source cases, existing calculus authoring/model boundary, task
discovery/check/report adapters, measured import/type repairs, existing preview
lifecycle and exact revision behavior, tests/docs/measurement commands needed
for these outcomes. Excluded: arbitrary calculus proof coverage, universal
composition/API framework, new visual motifs, generalization of unreviewed
presentation, Gaussian work, public deployment, paid calls or agents.

Ceiling: six hours, last hour reserved for verification, review packet and backup.
Continue across technical packages without routine approval. Stop at delivered
technical outcomes, a genuine authority/external blocker, ceiling, user pause,
or a subjective change required to make the case usable. A required visual
change gets one reversible exemplar and human review before propagation.
Unaccepted presentation stays a named review dependency; independent authoring
checks may finish without treating it as accepted. No requirement to consume
unused time or manufacture a publication after this scope is complete.
