## Acceptance, rollback and execution limits

Source-only reuse must be an actual working preview, not merely a checker report.
Unsupported sequences retain typed repair gaps; no arbitrary chain guarantee.
Report startup and activated bytes separately from measured latency, and first
inspection separately from repeats. A measured investigation may justify keeping
an existing implementation; improvement is not assumed in advance.

For code/text, human judgment selects clarity, salience and reading continuity.
The review packet must show long prose, opening/closing at an interior position,
and exact return on the shared server. Rollback units are the verified package
commits; the code/text exemplar remains independently reversible from semantic
models and authoring contracts. After acceptance, continue remaining scope without
another routine approval.

Allowed repairs: integration, lifecycle, discovery, tests and measured budget
repairs needed for these outcomes. Exclude new mathematics, general solvers,
new language frontends, speculative renderers, curriculum-wide authoring,
deployment, paid model calls and wholesale historical-contract cleanup.

Work ceiling: six active execution hours before reassessing unresolved scope;
reserve the final 45 minutes for verification and resumable closeout. This is
an uncertain ceiling, not a utilization target or a token budget. Stop earlier
for completion, the required visual checkpoint, user pause, or a genuine
scope/safety/external blocker. Record incomplete work explicitly rather than
waiving checks. Commit verified reversible packages with their evidence.
