# Matrix resource in the notebook

The user approved this bounded successor with “go” after the independent lanes
handoff. Use the KP delivery loop; no further scope approval is needed here.

An author can edit a numerical 2×2 matrix and 2-vector in the existing notebook,
see their product symbolically and geometrically, add a linked graph, and retain
drafts, identities and local views through native undo and reload. This proves
the new resource API can serve a product consumer without another evaluator.

Canonical artifact: `content/notebooks/matrix-object-exemplar.json`.
Host: `/experiments/fraction-notebook/?notebook=matrix` on port 8000.
Semantic authority: `src/math-resources/public-api.ts`, its pinned
`matrix2.vector2@1` recipe, typed arithmetic and semantic dependency cache.
KaTeX and existing Graph2D SVG owners provide paint. Reuse notebook typography,
commands, storage, editor history and reading preview; no new animation motif.

Two implementation packages: (1) validated notebook storage/occurrences and
native-history conversion, (2) controller, linked views, commands and one review
fixture. Then G2 is a human checkpoint before promotion. Smallest rollback units
are the data adapter/tests and the visible host integration/tests respectively.
Preserve saved fraction/quadratic documents, chat, split, themes, scrolling and
copy versus linked-view semantics. Separate selected-fixture storage avoids a
migration. Repeated views share calculation but keep their own extent.

Checks: resource/round-trip/history/identity tests; existing notebook tests;
complete scoped TypeScript; one Chromium authoring, clipboard, reload, command,
