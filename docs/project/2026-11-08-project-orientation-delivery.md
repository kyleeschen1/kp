# Keep the product direction understandable

Authority: the user endorses authoring exceptional material, featured content,
learner adaptation and connected practice, then asks to establish the proposed
orientation infrastructure: “the main blocker for me is getting lost. go as long
as possible.” This approves this bounded delivery, not the product horizon.

## Outcome

The user and a fresh agent can find the destination, current approved commitment,
proposed successor, demonstrated progress and open decision in a few minutes.
The existing project dashboard is the canonical human surface at
`/?view=dashboard#project-vision`. Its existing HTML renderer and theme own the
presentation. Strategy/roadmap/accepted decisions own direction; Theseus owns
execution. The parallel agent retains task tracking and editor ownership.

## Work and verification

1. **Direction:** replace accumulated startup history with a concise charter,
   roadmap and active-thread index; retain exact historical snapshots, accepted
   constraints and discoverable provenance. Record the accepted change and its
   approval boundary. Update agent routing and handoff instructions.
2. **Safeguards:** extend existing project-vision validation to pressure approval
   distinctions, source closure, bounded startup reading and agreement between
   the roadmap and its dashboard projection. Provide a repeatable orientation
   command using the same data, with explicitly selected Theseus progress.
3. **Orientation:** reconcile the existing dashboard with the charter; show the
   current commitment separately from the proposed product milestone, recent
   capability evidence, uncertainty and next human judgment. Keep older detail
   reachable behind native disclosures. Check desktop/phone and both themes
   with the existing scoped browser entrypoint; stop for one human review.

Theseus owns slice status. Check each rollback unit with `npm run
test:project-vision`, affected types, scope-specific browser checks when visible
behavior changes, diff whitespace and Theseus validation. Inspect impact first.
Do not turn a planning check into a general repository certification campaign.

## Boundaries and finish

Preserve existing reader/explanation content, native semantics and motion, editor
ownership, prior accepted results and historical evidence. No new task database,
dashboard framework, model service, learner platform, publication or scheduling.
Do not treat a snapshot as live status or a product ambition as approved work.
The documentation reconciliation and the dashboard/validation changes are separate
recoverable commits; checked candidates are backed up before human review.

Four-hour resource ceiling, including a final 40-minute verification/backup
reserve. Stop earlier when the bounded outcome is ready for review. Proportional
repairs of observed orientation, source-link, browser setup and validation defects
are allowed; new product outcomes require selection. Completion requires short
authoritative entrypoints, repeatable drift checks, a working dashboard review
URL, measured context reduction, source-backed claims and recoverable commits.
The dashboard's clarity remains a human judgment, not an automated test result.
