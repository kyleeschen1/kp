## Outcome and explanation-first brief

Readers can follow **What can an output tell you about its input?**, inspect a
calculation locally, then return to the same claim without restarting or losing
their place. Authors connect ordinary prose, native equations and references to
existing mathematical explanations without copying an animation implementation.

Assume familiarity with coordinate pairs, multiplying a vector by a scalar and
adding vectors. Introduce the column interpretation explicitly; do not assume
kernel, linear dependence, inverse or solution-set vocabulary. The main path
explains why A = [[1,2],[2,4]] retains x+2y, why distinct inputs can agree, and
why an output determines a relation between inputs rather than a unique input.
One nearby map distinguishes the previously lost change; this alone does not
prove that it distinguishes every pair. No arbitrary inverse/solver is promised.

The static baseline is the full prose argument with native equations and both
numerical mappings. Existing animation earns its optional place by tracking
the original entries into weighted columns and cancellation. Opening is a reader
choice, not a compulsory tour. All inferential bridges remain on the main path.
A changed-input prediction tests the retained-weight idea; answers remain
readable. This is not a learner study or a proof of pedagogical effectiveness.

## Work packages

1. **composition** — draft the complete argument; separate comparison playback
   from global document/history ownership so the same player can be inspected
   locally. Keep source choices local and bounded. Check semantic relations,
   unsupported references, and original-player preservation.
2. **reader** — compose the source into a readable document with optional inline
   inspections. At most one live player; retain exact progress per inspection;
   cancel stale mounts; return keyboard focus and reading position. Reuse existing
   controls, native endpoints and viewport anchor. Check interruption, reopen,
   disposal, reduced motion, phone overflow, and static reasoning completeness.
3. **evidence** — inspect one Chromium exemplar and preservation checks; run
   affected types/build and architecture checks, assess added runtime/source
   cost and record actual authoring friction. Commit and back up. Stop for the
   new reading experience's human checkpoint before a second argument or broader
   abstraction. Passing structural checks cannot accept the prose or interaction.
