## Work packages and gates

1. **Explanation.** Preserve a free-standing baseline before translating it.
   Bind it to the existing algebra and accepted reader. Permit more prose units
   than mathematical states; do not abbreviate the argument to fill four stops.
   Record every omitted bridge and any engine intervention. Focused semantic,
   source-preservation and desktop/phone browser checks, affected types and
   Theseus validation. Stop with one concrete reading-review packet.
2. **Reuse, after that review.** Author a meaningfully different question or
   revision through the same path. Extract only assembly seams demonstrated by
   both callers. Aim for source-only edits, measuring remaining code/CSS work
   honestly. Standard checks; broaden browser/budget checks if shared runtime
   changes justify them. No general schema promotion from resemblance alone.
3. **Situated follow-up, after reuse.** Exercise one exact referent, follow-up
   and revision with recovery of the original reading. Coordinate with existing
   editor ownership before interface work; a file-based exchange is sufficient.
   Several-target commentary requires a concrete need and its own checkpoint.
4. **Transfer, after the path is demonstrated.** Pressure the boundary with a
   structurally different explanation using already supported domain capabilities.
   Keep domain validity with its owner. New renderer/motion requirements return
   a typed gap and a bounded recommendation, not an invented fallback.

Theseus owns order, live status and evidence. These are dependent outcomes,
not a promise to bypass the first review during one unattended session.
