## Accepted implementation direction

1. Strengthen the existing explanation-first worksheet and canonical LLM routing
   with compact doctrine, actionable critique and an annotated gradient
   before/after example. Do not add a competing rulebook.
2. Build a small review fixture set: accepted explanations, deliberately damaged
   reasoning, and harmless paraphrases or alternate valid sequences. Evaluate
   defect detection and false alarms, not keyword compliance alone.
3. Connect objective checks to existing authoring/runtime verification: stable
   references, declared prerequisite availability on the chosen reading path,
   preservation of required content, native mathematics, readable layout and
   declared stationary evidence. Prefer types for representable structural
   invariants; validators and browser tests cover external content and behavior.
4. Use fuzzy review for motivation, inferential sufficiency, interpretation cost
   and misleading implications. Findings identify location, missing bridge,
   likely reader consequence and smallest repair; avoid a single clarity score.
5. Pressure-test one structurally different explanation, such as economics or
   code, before promoting repeated patterns into shared contracts or a skill.
6. Keep routine checks automatic and consolidate human pedagogical/visual review.

Preserve the distinction between verified facts, reviewed declarations and
actual learner understanding. A dependency check can validate supplied metadata,
not prove that the explanation teaches its declared prerequisites. Do not create
a pedagogically-complete type, universal ontology, new runtime or mandatory
multi-agent review ceremony. A micro-intuition has no universal stop count.

Resume from `../authoring/explanation-first-worksheet.md`,
`2026-09-11-gradient-explanation-storyboard.md`, and the existing gradient and
stage-fit tests. The principle is: strict about truth, references and preservation;
explicit about explanatory judgments; empirical about comprehension.
