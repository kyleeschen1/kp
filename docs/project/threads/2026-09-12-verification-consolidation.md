# Evidence-led verification consolidation

Only demonstrated duplicate infrastructure was consolidated:

1. Gradient production now uses the same built-document/asset closure fixture
   as canonical tax. Its existing Apply, WebGL, revision, extraction/return,
   canvas-count and no-development-module assertions remain. Six tax/code/no-JS
   cases and the gradient case pass. Injected source-module and external-network
   fetches are rejected by the real browser fixture.
2. Two pairs of identical package command implementations now have one owner
   each. Both visual entrypoint names remain as argument-forwarding aliases:
   economics-demand-shift tutorial and animation-library display. The existing
   command manifest records the aliases. Actual Playwright list execution
   yields exactly the same 18 tests/1 file and 10 tests/2 files for alias versus
   canonical command. Injected no-match filters produce zero cases and exit 1,
   proving selection arguments are forwarded rather than silently ignored.

Thirty-six existing command/impact/CLI checks pass. Full TypeScript passes.
No production product code, scene, title, equation, or content assertion was
deleted. The 624 command names remain available; there are two fewer independent
command bodies and one fewer independently maintained production fixture.
Aliases add small npm dispatch overhead; this is configuration convergence, not
a browser speedup or measured reduction in total release duration.

## Deliberately retained

Source-ownership assertions are useful where they prevent duplicate renderers,
clocks, or dependency boundaries. Earlier input slices replaced obsolete
listener/timer spelling requirements with shared-owner checks, backed by actual
behavioral regressions. No further historical phrase/metadata test deletion
was justified by representative replacement evidence in this bounded cohort.
Likewise, generated declaration checks and executed browser certification are
different evidence: their overlap does not make either automatically redundant.

The productive next optimization is impact-aware cadence and profiling measured
release hotspots, not a blanket source-reading-test or CSS line-count quota.
The full release remains the authority for integration regressions.
