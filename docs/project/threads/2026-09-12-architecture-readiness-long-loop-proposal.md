## Why this loop is current

The audit found three concrete defects/cost boundaries: incomplete edition CSS
closure, eager loading of multiple capabilities on the tax host, and gradient
CPU sensitivity during active animation. It also demonstrated a mutable semantic
payload escape and independently owned input/budget policies. These are immediate
readiness issues for reusable mechanics content, not speculative abstractions.

Preserve the native renderers and domain semantics. Reduce independent ownership
of the same rule; do not maximize lines deleted. Every repair names a violated
invariant, the responsible owner, and what previous path or failure class it
retires. Add types first where they can prove the invariant, runtime validation
at external/temporal boundaries, and small executable negative checks.

## Verification vocabulary

Each row has one commit after its checks and Theseus evidence. A record-only
measurement slice still commits reproducible findings rather than a new subsystem.

- **F / focused:** smallest named regression, pure-law, manifest or metadata checks.
- **S / standard:** F plus `npm run typecheck` and Theseus workspace validation.
- **B / broad:** S plus affected integration/build/browser/closure checks. It does
  not mean repeating the entire repository test suite after every edit.
- **P / publication checks:** three existing publication suites plus new closure,
  missing-target, path safety and immutable-regeneration tests in those owners.
- **C / cost checks:** production builds and `npm run visual:architecture-cost`;
  preserve baseline scenarios and add cold-load/deferred-activation attribution.
- **G / gradient checks:** existing authoring/extraction/runtime tests,
  `npm run visual:gradient-contour:production`, extended cost probe.
- **O / ontology checks:** asset laws, correspondence composition, runtime laws,
  lineage tests and negative type/runtime construction checks.
- **I / interaction checks:** existing affected input suites and scoped browser
  probes for wheel, touch/pointer, keyboard/buttons, fractions/prose, endpoint
  ownership, reversal, interruption, disposal and URL restoration.
- **R / release:** `npm run test`, `npm run typecheck`, affected production builds,
  affected budget/closure gates, cost probes, representative Chromium/Firefox/
  WebKit preservation and `theseus workspace validate`.

Use `npm run verify:impact -- --path <changed-path>` to inspect selected checks
before running them. Reuse existing browser entrypoints; extend a stable
scope-specific command if a new probe is necessary. No scratch browser scripts
or full new certification framework. Put disposable traces/screenshots in
`tmp/codex/`; durable evidence cites commands and summarized observations.

## Performance success and honest limits

Deterministic acceptance:
- each edition resolves its supported local dependency closure and cannot silently
  publish a missing target;
- unrelated tax capabilities are not imported/mounted before their declared
  activation condition, and all remain usable after activation;
- complete requested initial and activated bytes are separately measured;
- mutable external input cannot alter the meaning of supported issued immutable
  semantic objects under the same identity;
- the migrated tax/code paths have one input policy owner;
- consolidated checks retain demonstrated failure protection.

Use the committed audit as historical baseline and remeasure matching cohorts.
Record medians, ranges, CPU rate and requests; do not compare a warm activation
sample with a cold baseline. The measurement tool currently waits for first tax
card readiness, not every sibling. Make that distinction explicit before relying
on lazy-load gains, and independently prove deferred cards' usable readiness.

Optimization aims, not claims or pre-approved ceiling increases:
- materially lower initial tax JS through actual capability exclusion;
- reduce delivered focused CSS without changing any supported state;
- materially reduce repeated gradient active script/frame cost at 6× and remove
  avoidable stalls without sacrificing native animation.

Do not invent a promised percentage before profiling. For noisy timing gates,
choose conservative, documented tolerances from repeated matched samples and
deterministic work-count/ownership invariants where possible. Failure to achieve
material improvement is a stop with evidence and alternatives, not a reason to
raise a ceiling and declare optimization complete.

If no physical lower-powered device is available, complete the bounded engineering
work and explicitly retain that manual release limitation. A hardware requirement
must not silently turn into a permanent blocker or a false pass.
