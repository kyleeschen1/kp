## Goal

Grow a broad, beautiful animation library through one canonical semantic,
presentation, and rendering path. Keep the promotion order persistent and
inspectable so humans and future model sessions retrieve it rather than
regenerate it.

## Ordering Authority

This thread is the sole living human-readable authority for animation promotion
rank and progress. The roadmap points here instead of duplicating the complete
order. Accepted decisions explain changes; Theseus run contracts authorize and
track only the currently approved implementation tranche.

Changing rank, inserting a new frontier exemplar, or removing an item requires
an explicit accepted project decision. An exemplar may expose a stop condition,
but a model must not silently recompute the sequence from older reviews.

Short harvest promotions may run after their prerequisite frontier exemplar is
approved. They expand a proven family without changing the frontier order.

## Completed Foundation

The following work is retained as foundation or canonical evidence rather than
queued again:

- canonical native-KaTeX construction and exclusive paint ownership;
- solve-x reference behavior;
- numerator split and merge;
- radical structural succession and promotion kit;
- foldable distribution and certified stage layout;
- canonical fraction composition for `2/3(x + 6) = 10`;
- role-complete, branded operation-presentation plans and exhaustive reader
  dispatch.

Catalog maturity remains evidence-derived. A completed foundation item is not
called fully promoted when its catalog certificate still records explicit
static checkpoints, compatibility paint, missing motif parity, or an unresolved
release gate.

## Composition Environment Sequence

The promotion order now deliberately pressures three composition environments:

1. equation succession, already proven by the canonical glyph and motif work;
2. persistent workspace algorithms, beginning with multi-digit addition;
3. synchronized model views, beginning with bounded economics and physics
   exemplars.

The current place-value repair may promote generic lifetime, semantic
destination, measured route, transit-ownership, and endpoint-handoff contracts
only where the ones-column failure demands them. It may not turn carry into a
generic domain operation or introduce a universal scene graph. Later columns
remain a separate generalization decision after the ones-column checkpoint.
The accepted cadence and forward-looking domain rationale are recorded in
`decisions/2026-07-30-kp-persistent-workspace-composition-sequence.md`.

## Platform Integration Milestones

These milestones are gates between promotions, not additional animation ranks.
They preserve the content-led frontier while putting generation, editorial
quality, and simplification work at the points where a real consumer can test
them.

| Milestone | Placement | Required outcome |
| --- | --- | --- |
| M0: promotion-memory repair | Before rank 1 | Reconcile roadmap, catalog, and Theseus state against this ledger; add a drift check so completed or reordered work cannot be reported as current. |
| M1: public API tiers | After rank 4 and before rank 5 | Declare a stable authoring facade, internal compiler/reader/rendering APIs, and experimental surfaces before a generated-problem caller becomes a durable integration. |
| M2: verified problem-to-animation bridge | After M1 and before rank 5 | Compile the existing verified linear-equation trace into canonical `KpAnimationAsset` output with stable selectors, lineage, instance-aware reader descriptors, conformance cases, and fail-closed unsupported presentations. |
| M3: deterministic explanation spine | Inside the first M2 exemplar | Add a minimal hand-authored `ExplanationSpineV1`, learner-state input, vocabulary contract, and verified claim references for one generated solve-x session. The spine remains deterministic and reviewable. |
| M4: context-safe generated-text boundary | Before any untrusted or model-produced editorial text ships | Replace repeated generic HTML sanitation at the generation boundary with context-specific text-node, attribute, and script-JSON encoders plus misuse checks. Do not pretend these contexts share one escaping operation. |
| M5: LLM editorial candidate service | After deterministic generated sessions are stable and human gold and negative examples exist | Let a model propose wording only from verified claims, learner state, approved vocabulary, available visual arguments, and the explanation spine. Human selection remains explicit; playback and editing do not depend on a live model call. |
| M6: versioned motif implementation boundary | At the first intentional redesign of a shared motif | Give the redesigned motif a versioned implementation reference, route certified callers through it, and prove the affected family centrally updates. Do not build a universal registry without that concrete pressure. |

Complexity-negative pruning is continuous but adjacent: when a promotion or
platform milestone migrates the last real caller, retire the matching
compatibility facade, legacy presentation metadata, or superseded display
route in the same bounded change. Preserve semantic fixtures, conformance
tests, and historical evidence. Do not schedule a broad rewrite detached from
a working exemplar.

## Promotion Meaning

“Promoted” means more than “an animation or semantic fixture exists.” A promoted
learner animation has:

- verified semantic operations and correspondence;
- one required animated presentation plan for every moving transition;
- one canonical paint owner and no simultaneous compatibility paint;
- deterministic direct seek and exact rewind;
- responsive, accessibility, static/export, and browser evidence;
- motif fidelity and human exemplar approval;
- evidence-derived catalog status and a completed release gate.

Explicit static checkpoints and diagnostic examples remain honest evidence, but
they do not satisfy animated promotion.

## Progress Update Protocol

After a promotion closes:

1. derive product maturity from catalog and release evidence;
2. update only the matching row status and evidence link here;
3. advance `Current Next Action` to the first unresolved rank;
4. update the roadmap summary without copying this table;
5. resolve the approved Theseus contract without automatically activating the
   next row.

`npm run check:promotion-memory` rejects a roadmap, queue, active Theseus phase,
or thread which disagrees with this table's first unresolved rank. It also
rejects a `promoted` row unless its catalog animation ID is evidence-derived as
`ported`; the catalog ID column is intentionally blank until that certificate
exists.
