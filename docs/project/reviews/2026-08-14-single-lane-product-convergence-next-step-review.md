# Single-Lane Product Convergence Next-Step Review

Date: 2026-08-14
Status: recommended operating plan

## Problem

KP contains many valuable artifacts, layout experiments, domain exemplars,
public routes, and architectural proofs. Their continued visibility makes them
feel like simultaneous commitments even though most are evidence rather than
active work. The resulting overwhelm is a control-plane problem: the project
has one unresolved product question but presents itself as many unfinished
products.

## Recommendation

Run one active lane and treat everything else as a frozen reference portfolio.

> Build and evaluate one three-to-five-minute eigenvector experience in which
> the learner never has to decide where to look.

Do not begin with implementation. First write a bounded exemplar spec with six
to nine attentional beats, one persistent vector identity across geometry and
notation, one prediction/manipulation, complete searchable truth, fixed minimal
transport controls, and one human checkpoint.

## One-Lane Sequence

### Gate 1: specify

Write one human-reviewable prototype specification. Name the exact beat
sequence, dominant attentional target at each beat, semantic handoffs,
interaction, searchable-text treatment, fixed controls, phone behavior,
acceptance criteria, preservation boundary, and rollback unit.

Stop for review. Do not create a generic `Beat` interface, vector library,
layout system, authoring grammar, or new LLM capability.

### Gate 2: build one reversible exemplar

After approval, implement only the specified eigenvector experience. Reuse the
existing semantic identity, deterministic clock, direct-state, salience,
native rendering, static publication, and URL seams. Hard-code local content
and choreography where the medium is still being discovered.

### Gate 3: evaluate the medium

Ask a small set of sharp questions:

- Did the learner ever wonder where to look or what to do next?
- Did the same vector feel continuous across geometry and `Av = lambda v`?
- Did prediction or manipulation reveal something passive viewing would not?
- Can the learner reconstruct the invariant-direction idea after a delay?
- Is the complete explanation still searchable and understandable without
  interaction?

Allow at most one bounded revision cycle before making an explicit product
decision. Do not convert a failed checkpoint into open-ended layout tuning.

### Gate 4: decide, then unlock only one branch

- **Pass:** promote the smallest demonstrated attentional grammar, add one
  compressed delayed-return cue, then pressure it with one existing contrasting
  caller such as economics.
- **Mixed:** make one named correction and repeat the same checkpoint.
- **Fail:** preserve the semantic/runtime work and reconsider the experience
  model. Do not respond by adding more layout variants or controls.

### Gate 5: make a tiny public proof

Only after the experience and second caller pass, package a mission page, the
two curated explanations, stable links, and one embed. Tutor, editor, SRS,
accounts, curriculum, and generalized authoring remain later product layers.

## Why This Is The Clear Path

The repo is not a list of products that all need finishing. It is a substantial
evidence base surrounding one present uncertainty: whether KP's semantic
machinery can produce a distinctly better short learning experience. One
exemplar can answer that. More infrastructure or inventory cannot.
