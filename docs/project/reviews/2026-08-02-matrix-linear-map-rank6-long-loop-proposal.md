# Rank-6 Matrix-To-Linear-Map Long-Loop Proposal

Date: 2026-08-02
Status: approved in conversation; executable order lives in Theseus

## Why This Loop Is Current

Rank 5 and the reversible Svelte 5 catalogue-shell gate are complete. The
persistent promotion ledger therefore makes `kp.promotion.matrix-linear-map`
the first unresolved content frontier. This is the required second content
pressure on the canonical Svelte host before SvelteKit or Internal Studio.

The work is not greenfield. KP already has:

- the exact generated matrix-vector asset
  `animation.generated.linear-algebra.matrix-vector.two-by-two`;
- row-ranked dot-product choreography and exact semantic duration;
- authored standalone dot-product products and partial sums;
- strict Matrix-to-LinearMap derivation with standard-basis provenance;
- a separate placeholder linear-map graph;
- composite equation/graph host dispatch under one player clock; and
- the promoted `kp.graph.dimensional-continuity.v1` visual language.

The loop must turn those parts into one canonical learner artifact and remove
only redundancy whose last caller has actually migrated.

## Canonical Exemplar And Pedagogy

The canonical exact fixture remains:

```text
A = [[2, 1], [0, 3]]
v = [4, 5]
Av = [13, 15]
```

The visual model adapts the operation-bank topology from BetterExplained's
"Pour" diagrams without copying their artwork or implying finite-fluid
conservation. Input values remain persistent sources. Contribution pulses flow
through matrix-row operations, generate products, gather into a sum, and
collapse into one output coordinate.

The three views have distinct jobs and advance sequentially under one clock:

1. operation-bank flow explains how information passes through matrix rows;
2. symbolic gather-and-collapse explains each dot product; and
3. mapped basis, vector, and grid explain the resulting linear map.

For the first row, the observable symbolic story is:

```text
pair                 multiply             gather       collapse
2 with 4, 1 with 5 -> 2·4 and 1·5 ->       8 + 5   ->     13
```

Rows compute output coordinates. Columns describe mapped basis vectors. The
animation must keep those claims distinct rather than turning one visual
analogy into semantic authority.

Primary inspiration:
`https://betterexplained.com/articles/linear-algebra-guide/`.

## Canonical Reference And Acceptance

The current symbolic reference is the generated two-by-two matrix-vector
asset. The visual reference is the approved vector projection composition and
`kp.graph.dimensional-continuity.v1`: warm orthographic 2D plane, sparse
construction grid, role-based hierarchy, inline KaTeX, restrained labels,
exact static truth, and compact catalogue controls.

Promotion requires:

- one upgraded canonical asset rather than parallel symbolic and geometric
  catalogue representations;
- exact row products, partial sums, result coordinates, and basis provenance;
- one renderer-neutral frame and one framework-neutral clock;
- persistent input sources with causal contribution lineage, not fake material
  consumption;
- native KaTeX settlement after gather-and-collapse;
- deterministic direct seek, exact rewind, reduced motion, and static states;
- compact wide and narrow catalogue composition;
- complete dynamic nonvisual descriptions;
- selected capability loading without eager KaTeX, graph, or diagnostics;
- no widened bundle, Core Web Vitals, or animation-frame ceiling;
- human approval of the first-row operation-bank checkpoint; and
- standalone dot-product and matrix-matrix callers proving the promoted seam.

## Preservation Boundary

The following remain framework-neutral and authoritative:

- the generated fixture's exact matrix, vector, result, selectors, and
  transformations;
- Matrix, LinearMap, derivation records, bases, and semantic lineage;
- animation assets, transformation trees, runtime samplers, and the player
  clock;
- equation and graph renderer ports;
- catalogue loading, URL, Review, and selected-capability services; and
- static/export truth and existing public or reader behavior.

The Pour topology is a presentation projection. It does not create a fluid
simulation, new semantic object family, universal renderer, or second runtime.

## Rollback And Promotion

Every slice is one independently reversible commit. Asset enrichment, host
composition, first-row visual treatment, post-approval generalization, and
placeholder retirement remain separate rollback units.

The loop stops at slice 16 for human approval. Slices 17 through 26 may run only
after that checkpoint. A shared dot-product gather seam may be promoted only
after the matrix-vector exemplar, standalone dot product, and matrix-matrix
cell caller demonstrate the same boundary without a second scheduler or frame
schema.

## Verification Cadence

Inner slices use focused semantic, runtime, renderer, and host tests through a
stable `npm run test:matrix-linear-map` command. The checkpoint adds stable
`npm run visual:matrix-linear-map` and
`npm run test:browser:matrix-linear-map` commands, typecheck, production build,
bundle, capability-attribution, and performance-regression gates.

The release boundary adds the full test suite; Chromium, Firefox, and WebKit;
production Review closure; promotion-memory alignment; final visual evidence;
Theseus workspace validation; and Git patch hygiene.

## Stop Conditions

Stop immediately when:

- slice 16 reaches the mandatory human checkpoint;
- the flow metaphor implies input depletion, fabricated material identity, or
  a false row/column claim;
- work would add a second loader, clock, URL state, Review history, scheduler,
  renderer authority, or frame schema;
- presentation geometry moves into Matrix, LinearMap, or other semantic truth;
- selected capability loading regresses or a production ceiling must widen;
- matrix-matrix pressure requires a speculative universal abstraction;
- a compatibility path still has a unique caller or conformance role; or
- verification evidence is missing, contradictory, or cannot be recorded.

## Explicit Deferrals

- SvelteKit, Internal Studio, and the typed authoring-session loop;
- editable matrix parameters or a general matrix editor;
- arbitrary-dimensional visualization;
- determinant, inverse, basis-change, eigenvector, Jacobian, or Hessian work;
- rank-7 derivative work;
- 3D graph rotation;
- a universal renderer, scene graph, layout engine, or motif registry;
- M4/M5 or other LLM editorial work;
- Public Web or the Public Editor; and
- unrelated catalogue dispositions, API cleanup, or compatibility pruning.
