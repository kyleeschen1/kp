# Fractional reader: inactive transition paint containment

The user reported remaining duplication when entering “multiply both sides by
two” after the [evaluation routing repair](2026-10-27-fractional-evaluation-routing.md).

## Reproduction and responsible boundary

Canonical exemplar: `/reader/solve-fractional-linear/`, using the fractional
linear animation asset and its semantic equation states. The host mixes the
canonical native KaTeX compositor for cancellations/evaluations with the
existing material renderer for introductions. This repair preserves those
programs, their timings, mathematical identities, authoring API and palette.

A direct load at progress 510 showed one equation. Scrolling from the preceding
evaluation to that position showed both equations: the previous compositor's
retained material still painted behind the multiplication source. Rewinding
from denominator cancellation into multiplication similarly exposed the later
step's material. The old smoke tests checked active owners but not paint from
inactive transitions, so they missed this history-dependent failure.

The shared surface keeps inactive transitions measurable with `display:block`
and `visibility:hidden`. Descendants with explicit `visibility:visible` can
still paint under that ancestor. Retaining the prepared canonical session is
intentional; allowing it to paint when inactive violates scene ownership.

## Repair and prevention

`canonical-equation-surface.css` now sets inactive transition opacity to zero
and active opacity to one, alongside the existing visibility rules. This is
an instantaneous presence gate, not a new fade or dimming treatment. Descendant
visibility cannot override ancestor opacity. Geometry remains measurable;
prepared sessions and the existing renderer handoff stay intact.

Rollback unit: the two shared transition opacity declarations. No equation-
specific selector, motif adjustment, session disposal or per-glyph workaround
was added.

The scoped browser command now captures entry playheads 500, 501, 510, 530,
550 and 583 through direct load, forward scroll and reverse scroll. It checks
effective glyph opacity through ancestors, rejects painted glyphs owned by an
inactive transition, and compares visible symbol/opacity signatures with direct
loads. This catches stale paint even when the active equation looks correct.
It does not claim pixel-perfect trajectory equivalence or universal compositor
certification.

## Evidence

Before the CSS repair, the expanded 41-sample Chromium smoke run failed with
114 inactive-paint/signature violations. The same command passed with zero
violations after the repair. Forward and reverse entry screenshots were
inspected: only the current equation remained.

npm run visual:fractional-linear-equation -- --smoke --base-url=http://127.0.0.1:8000

comparison checks 34 frames. Tooling typecheck covers the modified diagnostics.
Generated reports/captures are disposable and regenerated by those commands.
This is a Chromium check at 1280×900; no broader browser certification is claimed.
