# M1a common-factor baseline and ownership

Baseline: `d431adaab`; approved s01. No visual implementation changed.

Canonical existing factoring artifact:
`animation.generated.distribution.factor-common-a`, constructed by
`src/animation/distribution-adapter.ts` from the generated distribution fixture.
Its registered `factorCommonTerm` transformation uses
`definition.generated.distribution.factor-common-term`, a fan-in correspondence,
and the `merge-fan-in` motif. The native renderer has dedicated factoring binding
and choreography, plus the shared verified distribution/factoring presentation
plan. These declarations are not a claim of a new executed browser certification.

The proposed host `/experiments/reusable-reasoning/` is currently tied to the
authored fraction-composition asset. `native-surface.ts` fetches the structural
distribution preview, verifies actual endpoints against reasoning evidence, and
mounts the canonical equation shell/session with the fraction descriptor. The
host is not already a generic factoring mount. Preserve its default source and
exact checks; use a distinct opt-in factoring source/adapter in s12, not an asset
ID substitution. The new semantic authority must precede that adapter.

Existing proof boundary: `verifyKpDistributionRewrite` in
`src/semantic/structured-expression-rewrite.ts` checks ordered structured product
and sum roles, complete factor subtrees and corresponding addends. The factoring
verifier can authenticate the inverse equality using this owner without numeric
sampling or a new CAS. Its result is currently structural data, not a nominal
factoring capability: the new family must own issuance and authentication.
Generated tutorial fixtures construct related endpoints; they do not validate an
arbitrary caller's requested target. Do not confuse those two contracts.

The series registry has no common-factor validator. Correctly namespaced request
IDs reproduced the recorded baseline: `a*b+a*c` to `a*(b+c)` is compiled, as are
invalid `a*(b+d)` and `2*x+2*y` to `3*(x+y)`. Ordinary `ab+ac` to `a(b+c)` returns
`equation-series.endpoint.unsupported-syntax` at the target. These are candidate
results, not executed downstream proof or paint. An initial diagnostic invocation
used bare IDs and correctly failed request validation; corrected the probe IDs,
not the validator. s03 will commit the repeatable characterization harness.

Executed preservation: 14 tests passed in distribution animation assets,
distribution/factoring presentation plans and factoring motif bindings. Existing
coverage includes reference closure, seek/rewind declarations, exact fan-in roles,
structural-artifact separation and rejection of detached bindings. Browser
certification remains the later actual-runtime gate.

The bounded adapter path is plausible from these existing owners; no new motif
grammar or broad migration is authorized. If native execution disproves that
assumption, return a typed gap and invoke the scope stop.

Execution metadata correction: slice risk/check details were moved from long
titles into stored summaries after the 1,000-token status report rejected 1,037
tokens. No budget raised. The target's done contract and completed R4B dependency
were explicitly attached through Theseus; progress now reports zero blockers.
