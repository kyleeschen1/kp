# Role-Complete Operation Presentation Plans Closeout

Date: 2026-07-29
Status: complete

## Outcome

The canonical reader now accepts exactly one required, discriminated
presentation plan for every equation transition. A transition is either a
verified animated plan or an explicit static checkpoint. Independent optional
motif hints can no longer be assembled at the reader boundary, and catalog
promotion cannot describe a static fallback as ported animation.

The runtime path remains:

```text
semantic AST and correspondence
-> trusted compiler derives participant roles
-> validator and laws mint a branded presentation plan
-> required reader presentation-plan union
-> one exhaustive reader adapter dispatch
-> existing native compositor primitives
-> measured DOM paint and exact native endpoint
```

This migration added no second compositor, paint owner, lifecycle, scheduler,
or operation-specific timing category. The internal compositor primitives
remain separate because they are the implementation vocabulary; only the
exhaustive adapter may combine them, after receiving a verified union variant.

## Authoring Authority

LLM authoring stops at mathematical and semantic intent. Generated inputs may
describe the operation, AST, operands, and correspondence, but may not provide
selectors, presentation roles, DOM, geometry, paths, timing, keyframes, or
animation recipes. Trusted deterministic code derives roles and fails closed
when it cannot prove a complete plan.

The closed plan union covers default motion, a version-pinned visual motif,
successor synthesis, synchronized balanced introduction, inverse
cancellation, distribution, factoring, fraction fission/fusion, and
structural succession. Unsupported presentation is represented by a typed
static checkpoint rather than a generic fade or an implicit fallback.

## Runtime and Resource Closure

The nine shared equation-reader routes now measure 138,095 gzip bytes of
runtime closure. The route manifest records that exact accepted measurement,
and the budget checker retains its existing five-percent future-growth guard.
The catalog and property inspectors are test/tooling code and add no production
imports. The specialized distribution-area and quadratic-branching routes were
tightened to their measured 14,823-byte and 14,776-byte runtime closures
instead of retaining obsolete broad allowances.

`fraction-solve.step.divide-by-two`: its required fit scale is approximately
0.61 against the preferred 0.68 floor. It does not violate containment,
overlap, paint ownership, endpoint, or rewind assertions and was not introduced
by this plan migration. It remains a layout/readability follow-up rather than a
false presentation-plan pass.
