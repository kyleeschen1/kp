# Exact Fraction Quantity Promotion Long-Loop Proposal

Date: 2026-07-28
Status: approved by user for execution
Mode: long
Execution Contract:
`run-contract.kp.exact-fraction-quantity-promotion-v1`

## Objective

Promote one canonical exact-quantity animation for:

```text
1/3 + 1/6 = 1/2
```

The exemplar must show one conserved quantity identity through synchronized
native KaTeX, partitioned circles, fraction bars or area, and a number line.
It must introduce reusable partition refinement, common-denominator alignment,
and exact part-merge semantics without adding a second animation runtime,
renderer-owned arithmetic, or representation-specific mathematical truth.

The canonical path remains:

```text
verified exact quantity trace
-> immutable evaluation and view projection
-> one shared runtime frame and clock
-> native KaTeX plus deterministic SVG quantity views
-> exact settled and accessible state
```

## Why This Loop Is Current

The stable promotion ledger names exact fraction quantity as rank 1. The
canonical equation renderer, fraction structural motion, foldable evaluation,
certified responsive layout, exclusive paint ownership, lazy Animation Library
host, Review capture seam, and evidence-derived promotion gates are already in
place. This exemplar therefore tests whether that foundation can produce a new
multi-representation animation without another operation-specific compositor
program.

It also opens capabilities needed by later arithmetic, ratios, graphs, and
diagrams: exact conserved quantities, refinement provenance, cross-view
identity, and responsive focus among several synchronized views.

`theseus plan run` currently reports an empty executable queue, while
`theseus plan refill` offers stale revision-10 foundation work such as the
already completed radical phase. The first three slices repair that control
drift before content implementation. No executable run contract exists until
this proposal is explicitly approved.

## Canonical Reference And Observable Acceptance

The reviewed exemplar is the exact sequence:

1. establish `1/3` and `1/6` as portions of the same unit;
2. refine the third into `2/6` without changing its quantity or fading its
   persistent parts away;
3. align `2/6 + 1/6`;
4. merge the three sixths into `3/6`; and
5. recognize the same selected half as `1/2`.

Every view must make that same sequence legible:

- native KaTeX shows exact symbolic structure and owns settled typography;
- partitioned circles show refinement and selected sector provenance;
- fraction bars or area show the same unit, subdivisions, and merged extent;
- the number line shows the same exact lengths and addition endpoint.

Promotion requires:

1. normalized exact arithmetic at every state, with a typed unit identity;
2. proof-carrying conservation across refinement, merge, and simplification;
3. stable semantic IDs for persistent parts and explicit contributor lineage
   for fission and fusion;
4. no opacity choreography for exact persistent, fission, or fusion identity;
5. no unexplained digit, glyph, sector, bar, interval, or endpoint
   teleportation;
6. common-denominator alignment and simplification remain verified semantic
   operations, not renderer inference;
7. all four views sample one immutable trace and one shared clock;
8. direct seek, exact rewind, repeated scrubbing, and resize are
   history-independent;
9. wide presentation remains centered and uncrowded, while phone presentation
   uses deterministic view focus rather than shrinking all four views below a
   readable floor;
10. reduced motion, static/no-JavaScript, screen-reader, transcript, and export
    projections preserve the same causal explanation;
11. the single lazy Animation Library host exposes the exemplar and the Review
    capture box saves viewport, active view, phase, checkpoint, and progress;
12. catalog status is derived from passed evidence and human approval rather
    than an authorable `ported` or `promoted` flag;
13. the implementation adds no new runtime clock, lifecycle category,
    scheduler category, equation compositor, display page, or WebGL lease.

## Stop Conditions

Stop immediately if:

- exact value, unit identity, selected-part provenance, contributor lineage,
  fold truth, accessibility, export truth, or settled native authority changes;
- a visual projection becomes a mathematical source;
- persistent, fission, or fusion identity falls back to generic opacity;
- implementation requires a new clock, runtime, scheduler category, equation
  compositor, WebGL lease, display page, or representation-specific semantic
  exception;
- a certificate can be forged, a missing view can typecheck, or an authorable
  status flag can claim promotion;
- another canonical reader or the Review capture box regresses;
- unrelated user-owned files must be overwritten;
- the visual checkpoint is rejected or not explicitly approved.
