# Animation Governance Epoch v2 — approved long-loop proposal

Date: 2026-08-22  
Status: approved  
Executable target: `next-action.kp.animation.animation-governance-epoch-v2`

## Objective

Make evolving animation principles retroactive, inspectable, and enforceable. Every loadable animation will enter through one renderer-neutral governance route; equation animations will fully converge on a typed equation compiler while graph, code, and 3D artifacts retain domain-specific renderers. The loop returns to the derivative exemplar only after the governance route and current equation catalogue have converged.

The common route is:

```text
KpAnimationAsset
→ conformance manifest
→ semantic operation and projection compiler
→ domain-specific certified presentation plan
→ deterministic runtime session
→ renderer adapter
```

## Completion contract

- Every loadable animation has a generated conformance manifest.
- Every moving equation asset uses the v2 compiler or has an explicit static, unsupported, or compatibility disposition.
- Evaluation, wrapping, cancellation, successor, projection, and boundary behavior resolve through registries.
- Typography separates document flow, TeX math style, and optical scale.
- Promoted motif changes identify and recompile callers, and affected visual approvals become stale by policy.
- Specialized adapters cannot author raw equation motion outside the canonical route.
- Lazy bundle boundaries remain intact.
- The full log-product equivalence regression is repaired.
- The derivative exemplar is recompiled under v2 and returned for visual review.
- No new animation family is added before closure.

## Approved slices

5. Add policy epochs and resolved-profile provenance while preserving old-artifact reproducibility.

11. Make the evaluation registry mandatory for product, quotient, difference, sum, cancellation, identity, and successor operations. Reject generic fades and caller-authored evaluation.

30. Recompile the derivative exemplar under v2, compare it with commit `31a609b0`, record canonical URL and review provenance, run the release gate, and record the next animation-family expansion order. Stop for mandatory human review.

## Verification cadence

- Every slice receives focused verification and a dedicated commit with Theseus evidence.
- Use impact-scoped verification inside migrations.
- Run `npm run verify:equation:boundary` at architecture boundaries.
- Run `npm run verify:equation:promotion` before promotion.
- Run `npm run verify:equation:release`, `npm run build`, architecture checks, inference and bundle non-regression checks, and `theseus validate` at the final release gate.
- Use a single worker and one exemplar during visual discovery. Run supported-browser matrices only at promotion and release boundaries.
- Prefer mechanism certification to snapshot multiplication. Browser visual checks must use stable repository-owned scripts and scoped npm commands.

## Checkpoints and stop conditions

Slice 22 is the first mandatory `HUMAN_CHECKPOINT`; approval of this proposal authorizes execution up to, but not through, that visual decision. Slice 30 is the final `HUMAN_CHECKPOINT`.

Stop earlier for semantic or URL drift, raw coordinates or glyph inference in caller code, caller-authored timing, playback/seek disagreement, duplicate or blank paint, eager loading, inference or bundle regression, overlap with unrelated dirty work, an unapproved schema expansion, or scope broadening into general non-equation renderer migrations.

## Preservation and rollback

Preserve semantic operations, stable IDs, URLs, endpoint mathematics, and the deterministic clock. Introduce v2 beside v1, then delete each bypass with its last caller. Keep migrations family-sized and independently revertible. The log repair must be removable on its own. Commit `31a609b0` remains the derivative visual baseline. Unrelated dirty work remains untouched.

## Deferred work

New math families, public lesson layout, material-depth experiments, a universal renderer, full graph/code/WebGL migration, Svelte ownership changes, live LLM generation, automatic reapproval, and budget-ceiling increases are outside this loop.
