# Proof-Or-Simplify And Domain Expansion Next-Step Review

Date: 2026-07-29
Status: proposed; non-authorizing
Roadmap effect: none until explicit user approval
Theseus effect: none until explicit user approval

## Decision Context

KP has accumulated a strong renderer-neutral semantic trace, typed operation
authority, one shared player clock, deterministic seek/rewind, native
accessibility endpoints, review capture, and multi-surface projections. It has
not yet proved the promised reduction in marginal visual-animation cost.

The required slice-3 evaluation-reference checkpoint exposed a concrete
measurement-lifecycle defect: the current compositor stage was measured in one
container and then reparented into a narrower comparison panel. The automated
checks observed wrapper width, motion, opacity, and lifecycle, but not painted
ink containment or native-endpoint alignment. The checkpoint also compared a
historical choreography with known paint defects against an explicitly rejected
zero-area runtime, so it did not present one final-quality candidate for human
approval.

This is a valid stop condition, not authorization for another open-ended
infrastructure program. The current 26-slice contract remains paused at `s03`.
The stable promotion order remains unchanged:

1. exact fraction quantity;
2. place-value addition;
3. bounded economics equilibrium;
4. bounded constant-force work-energy;
5. the retained later frontier.

Programming remains retained in the stable ledger. Its position is not changed
by this proposal; a later explicit decision may reconsider an earlier bounded
code exemplar after the first four visible promotions.

## Recommendation

Replace “finish the infrastructure loop” as the success criterion with a
proof-or-simplify gate. Do not execute beyond the current human checkpoint
until one final-host evaluation animation is both visibly acceptable and
measured by tests that observe actual paint.

The semantic trace, typed motif selection, shared clock, accessibility/export
contracts, and canonical endpoint authority remain preserved regardless of the
renderer decision. The measured native-KaTeX compositor is provisional outside
already approved exemplars until it demonstrates reuse at lower marginal cost.

## Immediate Work: Bounded Checkpoint Rescue

This is a proposed short repair, not a new long loop.

### Phase 1: Freeze The Observable Reference

Canonical reference:
the last accepted gather-and-recognize evaluation choreography, corrected to
the current no-generic-fade and exact-native-endpoint standard.

Observable acceptance criteria:

- `1 + 2` begins at exact native source paint geometry;
- operands and operator participate in readable evaluation choreography;
- the result visibly follows from the contributor cohort;
- active paint stays inside the final dashboard panel;
- no generic fade, zero-area pulse, font substitution, endpoint jerk, or
  whole-expression replacement occurs;
- natural playback, direct seek, rewind, and replay agree; and
- the final frame equals native target paint.

Preservation boundary:
semantic operation, roles, lineage, player clock, accessibility, lesson
content, dashboard catalog identity, and already approved exemplars.

Rollback unit:
the development comparison harness and its evaluation-specific presentation
candidate. No reader, catalog family, or unrelated motif is generalized.

### Phase 2: Repair Measurement Ownership

Construct the final host layout before mounting or measuring the compositor.
Never reparent a measured stage. Bind an ephemeral measurement certificate to:

- host identity;
- container dimensions;
- device-pixel ratio;
- font-readiness revision; and
- renderer-session generation.

Reparent, resize, font revision, or host replacement invalidates the
certificate and requires settlement before animation resumes. Types may brand
the certificate, but runtime host checks remain authoritative because the DOM
can change outside the type system.

Tests must sample painted ink rather than wrapper rectangles:

- visible ink remains inside the panel with a declared margin;
- source paint at `0` is equivalent to native source;
- target paint at `1` is equivalent to native target;
- baseline, font, rule, silhouette, and inner-paint geometry agree;
- minimum meaningful ink never falls below the motif contract; and
- panel/viewport changes either remeasure or fail closed.

### Phase 3: Present One Final Candidate

The Animation Library should show one proposed canonical animation as the
primary review object. Historical and rejected variants may remain behind a
diagnostic disclosure, but they are not peer product candidates.

Stop for human approval. Do not add new motif-program types or migrate exact
fractions before this checkpoint passes.

## Architecture ROI Gate

After approval, prove marginal reuse before returning to the longer contract.
The exact same evaluation program, compiler route, and compositor adapter must
render:

1. `1 + 2 -> 3`;
2. `5 + 2 -> 7`; and
3. the exact quotient evaluation chosen by the active fraction exemplar.

The gate passes only when:

- callers add semantic content and bindings, not renderer mechanics;
- no numeral-, notation-, lesson-, browser-, or viewport-specific branch is
  added;
- no new runtime, scheduler, display page, or paint owner is introduced;
- all three share the same positive phase behavior and endpoint laws;
- the second and third examples are short marginal slices; and
- compatibility code decreases or remains flat.

Track the following leverage metrics:

- production animation paths added and retired;
- renderer/compositor files changed per new exemplar;
- caller-specific presentation branches;
- newly required visual exceptions;
- time and slices from semantic fixture to human-ready animation;
- recurrence of previously closed defect categories; and
- percentage of review findings about pedagogy versus engine correctness.

Passing tests is necessary but does not satisfy the ROI gate without human
visual approval and lower marginal implementation cost.

## Conditional Medium-Term Paths

### Path A: ROI Gate Passes

1. Resume only the exact-fraction portions of the approved contract that reuse
   the proven evaluation, identity-fission, and identity-fusion programs.
2. Promote `1/3 + 1/6 = 1/2` after its four-view human checkpoint.
3. Harvest nearby fraction animations as short content promotions; new
   compositor categories are stop conditions.
4. Advance place-value addition.
5. Advance the bounded economics equilibrium exemplar.
6. Advance the bounded constant-force work-energy exemplar.
7. After these four visible promotions, run the recorded API-tier and verified
   problem-to-animation milestones.
8. At that checkpoint, explicitly decide whether demo value justifies moving a
   bounded code/network exemplar earlier than its current stable rank.

Between ranks 1–4, platform work is limited to defects directly exposed by the
active exemplar. No platform-only compositor loop begins until at least three
visible domain exemplars ship, unless a named release blocker makes them
impossible.

### Path B: ROI Gate Fails

1. Retain semantic traces, typed motif selection, the shared clock,
   accessibility/export contracts, and native settled endpoints.
2. Retire the rejected zero-area evaluation strategy and stop broad rollout of
   the universal measured-paint compositor.
3. Use a simpler DOM-centric/FLIP renderer for ordinary algebra where it
   satisfies the approved reference.
4. Reserve measured glyph reconciliation for structural transitions, such as
   fractions and radicals, that have already proved a material benefit.
5. Keep renderer selection capability-driven and compiler-owned; callers and
   LLMs still cannot author geometry or timing.
6. Run a bounded compatibility-pruning pass adjacent to the renderer
   simplification.
7. Continue the same content promotion order rather than beginning another
   renderer redesign.

This is simplification behind stable semantic interfaces, not a return to
lesson-local animation implementations.

### Path C: Mixed Result

If evaluation generalizes but fission/fusion do not, promote evaluation as one
versioned capability and keep structural transformations on their last approved
renderer. Do not force unlike motifs through one successor abstraction merely
to preserve architectural symmetry.

## Default Work Cadence After The Gate

- Default to short loops of one visible exemplar or one failed generic
  invariant.
- Name the canonical reference, final host, acceptance criteria, preservation
  boundary, and rollback unit before implementation.
- Mount in the final product host before measuring or visually approving.
- Perfect one exemplar before family generalization.
- Treat types, tests, and telemetry as supporting evidence; human-observable
  behavior is the subjective promotion authority.
- A repeated defect category reopens the owning invariant, not every animation
  that once exposed it.
- A new exemplar should usually modify semantic content, presentation bindings,
  and tests—not shared renderer code.
- Long loops require an explicit capability-opening outcome and an early
  exemplar checkpoint. Completing slices is never itself the product goal.

## Definition Of Convergence

KP is converging when:

- the number of canonical runtime/render paths decreases;
- approved animation behavior survives new hosts and viewports without tuning;
- related animations become materially cheaper to add;
- domain exemplars compose stable capabilities without renderer changes;
- compatibility paths retire beside successful migrations;
- catalog status remains evidence-derived and visually honest; and
- review feedback shifts from recurring engine defects toward pedagogy,
  composition, and subject-specific design.
