# Canonical animation construction and governed round-trip long-loop proposal

Date: 2026-07-25
Status: approved on 2026-07-25 for chained execution after predecessor close
Predecessor:
`run-contract.kp.canonical-equation-renderer-convergence-v1`
Proposed target:
`next-action.kp.canonical-animation-construction-governed-round-trip-v0`

## Recommendation

Run a chained 30-slice long loop after the predecessor contract completes.
Do not append these slices to the open 28-slice control record: close its
release slice honestly, then create one successor contract from this reviewed
proposal. This preserves one executable authority and makes rollback and
handoff legible.

This is current because the renderer fork is closed enough to stop treating
rendering as the main research question. The next bottleneck is construction:
can a human or governed model select semantic objects, lawful operations,
lineage, explanatory emphasis, and composition while deterministic KP code
owns mathematics, timing, geometry, typography, renderer selection, repair,
accessibility, and export?

The fraction split/merge reader is the right product exemplar. Its semantic
asset, inverse transformations, native KaTeX endpoints, structural rules,
responsive layout, and shared reader route already exist. The just-completed
renderer loop has separately proved generic merge/split multiplicity and the
no-fade law. Migrating this one card therefore tests composition and authoring
without inventing a new animation family.

## Exact benefit

If the loop passes, KP will have:

- one documented construction contract from semantic draft to canonical trace,
  presentation plan, renderer session, reader, static/headless projection, and
  export;
- one real fraction split/merge reader using the canonical renderer by default
  with its compatibility paint retired for that transition;
- no fade for lineage-backed fission or fusion, including fraction rules and
  denominators;
- governed LLM drafts that can request approved mathematical operations and
  explanatory intent but cannot author DOM, glyphs, geometry, timing, CSS,
  typography, renderer modes, or unverified mathematics;
- a bounded proof cohort spanning fraction split/merge, exponent absorption,
  radical succession, and a compact compound transformation through the same
  compiler and renderer vocabulary;
- an in-browser review gallery that exposes live seek, rewind, wide/phone, and
  reduced-motion evidence without requiring the user to find PNG files;
- a concrete audit of repeated sanitation, clone, escaping, validation, and
  projection utilities, with only proven duplicate mechanisms consolidated;
  and
- a repeatable promotion rule for adding animation families without creating
  parallel implementations.

This is the point where progress becomes visible library growth rather than
continued endpoint debugging.

## Canonical reference and acceptance criteria

Product reference:
`/reader/split-merge-fractions/`

Renderer reference:
the approved solve-x gold transition and the generic fraction merge/split
fixtures from the predecessor contract.

The fraction exemplar passes only if:

- source and target remain on one motivated equation anchor;
- `x`, `y`, `+`, both denominators, and both fraction rules have correct native
  size at every endpoint and no start or end jerk;
- lineage-backed split and merge paint changes geometry without opacity fade;
- the expression remains readable through the midpoint without double ink,
  collision, clipping, or unexplained vertical travel;
- direct seek and rewind return pixel-stable ownership and semantic state;
- wide, phone, full-motion, and reduced-motion projections remain composed;
- native DOM alone owns focus, hover, annotations, Cloze, MathML, and
  interaction;
- the migrated transition constructs no compatibility paint; and
- ordinary reader routes remain outside the canonical chunk unless eligible.

## Overnight checkpoint policy

Repository policy normally stops after perfecting one visual exemplar. To make
an overnight run useful, approval must explicitly authorize bounded
post-exemplar continuation after slice 15 if all named acceptance criteria,
browser assertions, contact-sheet inspection, and release budgets pass.

This is not a global family-rollout waiver. It authorizes only the isolated
review-fixture and governed-variation slices 16–30 below. If approval does not
explicitly include this waiver, the contract must stop at slice 15 with
`HUMAN_CHECKPOINT`.

## Preservation boundary

Preserve:

- existing semantic animation assets, operation traces, lineage, clocks,
  authoring guidance, and accepted visual examples;
- non-migrated reader and editor animations as reference or compatibility
  coverage;
- native KaTeX endpoint typography and semantic authority;
- graph, diagram, code, table, balance, static/headless, iframe, and
  static-step outputs;
- the canonical renderer's five paint kinds, six lifecycles, three internal
  modes, and capability-based selection;
- the current quadratic work as retained diagnostic/product evidence without
  reopening its publication scope; and
- unrelated user drafts and dirty worktree changes.

## Allowed work

- One fraction split/merge reader-transition migration to the canonical
  equation session.
- Canonical semantic construction and governed-draft schemas, compilers,
  validation, repair, and deterministic projection.
- Isolated review fixtures for existing fraction, exponent, radical, and
  compound traces.
- A browser-native review gallery inside the existing review/Workbench
  architecture.
- Consolidation of proven duplicate low-level safety utilities when behavior
  and consumers are covered in the same slice.
- Exact project-memory, plan-authority, Theseus, and closeout updates needed to
  make the new direction durable.

## Disallowed work

- A second renderer, material layer, animation runtime, clock, or authoring
  artifact.
- Fraction-, glyph-, character-, KaTeX-class-, viewport-, route-, or
  operation-specific runtime corrections.
- Model-authored LaTeX truth, DOM, HTML fragments, selectors, geometry,
  coordinates, paths, keyframes, timing tables, styles, fonts, renderer modes,
  accessibility markup, or export code.
- Migration of a second product reader family.
- Global equation-family or editor-surface rollout.
- Quadratic redesign, derivative/FTC work, arithmetic quantity models,
  cross-domain exemplars, publication-platform work, or unrelated UI work.
- Broad “utils” extraction based only on similar names; consolidation requires
  identical authority, lifetime, error, and security contracts.

## Rollback units

- Slices 1–5: plan authority and construction-contract baseline.
- Slices 6–15: one fraction reader migration, reversible as one product
  exemplar while keeping semantic assets unchanged.
- Slices 16–22: governed authoring and bounded variation fixtures; no product
  route changes.
- Slices 23–27: compound composition, browser review, exports, and duplicate
  utility reconciliation.
- Slices 28–30: budgets, release, project memory, and contract closeout.

Every completed slice is one focused commit with its Theseus evidence. A failed
slice remains open only long enough to record its stop reason; it does not
silently advance.

## Contract stop conditions

Stop immediately if:

1. the predecessor release contract does not close cleanly;
2. plan authority cannot select this target without competing active work;
3. the fraction migration needs notation-, character-, route-, viewport-, or
   operation-specific renderer logic;
4. any migrated frame has both compatibility and canonical paint;
5. split or merge uses opacity fading for lineage-backed material;
6. native endpoint typography, mathematics, accessibility, or interaction must
   be mutated;
7. DOM, HTML, glyphs, geometry, timing, CSS, font, renderer, or unverified math
   enters a durable or provider-authored schema;
8. another product reader family must be migrated to prove the contract;
9. a new paint kind, lifecycle, renderer mode, semantic taxonomy, scheduler,
   runtime, or clock is required;
10. direct seek, rewind, reduced motion, responsive composition, static,
    headless, export, or production closure fails without one bounded generic
    repair;
11. ordinary route or payload ceilings regress and cannot be recovered through
    in-scope deletion;
12. visual inspection finds snap, wrong scale, double ink, clipping,
    unexplained line travel, unreadable overlap, or misleading pedagogy;
13. consolidation would merge helpers with different authority or security
    contracts;
14. work touches the deferred domains or unrelated user drafts; or
15. the context cannot safely complete the remaining contract and record an
    exact handoff.

## Verification and commit cadence

- One independently reversible commit per completed slice.
- Focused checks on every slice.
- Typecheck and Theseus validation at every standard boundary.
- Persistent browser/review entrypoints for recurring visual checks.
- Broad browser, production, and build checks at slices 6, 10–15, 21, 24–26,
  and 28–30.
- Full `npm test` only at release boundaries or when impact analysis requires.
- Progress heartbeat from `npm run --silent loop:status` at every slice start,
  completion, commit, and final/stop response.
- Disposable images and reports stay under `tmp/codex/`; the live review
  gallery and stable npm commands are the durable inspection path.

## Explicit deferrals

This loop does not:

- redesign or publish the quadratic tutorial;
- migrate the exponent or radical reader families to product defaults;
- build the derivative/FTC gold module;
- expand into arithmetic quantity models, vectors, matrices, code, economics,
  physics, or BFS;
- build a broad prompt UI, course generator, or learner model;
- change portable publication, hosting, CLI, Markdown, or Studio contracts;
- add media encoding or dynamic package loading; or
- generalize the canonical renderer across the editor catalog.
