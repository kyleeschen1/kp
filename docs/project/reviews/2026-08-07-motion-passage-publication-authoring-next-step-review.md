# Motion Passage, Publication, And Authoring Next-Step Review

Date: 2026-08-07
Status: accepted ordering authority; not an executable run contract

## Objective

Turn the economics lesson experiments into a calm, statically published,
projection-neutral reading system before expanding authoring and navigation.
The ranking below owns this workstream's order across future loops. The active
animation-library promotion rank remains a separate authority.

## Accepted Ranking

1. **Refine the stacked-projection station and progress-rail rhythm.** Perfect
   one reversible economics exemplar for `approach -> ready -> scrub -> settle
   -> handoff`, including entrance, ordinary cues, motion cues, long prose,
   reverse scroll, direct seek, mobile, and reduced motion.
2. **Repair static publication and the Svelte/CSS/JavaScript route boundary.**
   Publish meaningful prose, KaTeX HTML/MathML, initial SVG, semantic outline,
   and reserved controls before enhancement. Split route, graph, domain, and
   projection styles; load only the selected presenter and editor code.
3. **Port the approved progress grammar to the split projection.** Share the
   semantic phase and playhead, not layout geometry. Put the read-only
   horizontal progress rail above the active narrative passage.
4. **Complete the practical CodeMirror authoring loop.** Move from one-card
   proof to one whole-lesson structured buffer with stable IDs, incremental
   last-valid preview, repository-backed autocomplete, diagnostics,
   reversible passage commands, and explicit save state.
5. **Build robust floating TOC and motion-passage navigation.** Provide a
   semantic light-DOM outline, responsive disclosure, direct state
   transactions, previous/next/skip/settle/exit controls, URL and history
   parity, and no wheel interception or replay requirement.
6. **Build a multi-step algebra caller.** Use a nearer equation lesson to
   pressure repeated motion cues, KaTeX structure, and long/short prose rhythm.
7. **Extract the shared motion-passage and vignette authoring contract.** Share
   only boundaries proven by economics plus the algebra caller; keep renderer
   and domain truth local.
8. **Run named page-scale benchmarks.** Report `single-motion-passage` (1),
   `representative-document` (6), and `stress-document` (12), separately
   recording motion passages, motion blocks, distinct capabilities, maximum
   live stages, and active playheads.
9. **Add advanced CodeMirror capabilities.** Whole-repository semantic
   discovery, Helm/Vertico-like completion, richer Vim customization,
   structured history curation, KaTeX tree operations, and typed `kp` blocks
   follow only after the practical editor loop is stable.
10. **Add Canvas/WebGL salience adapters and 3D optical parity.** Reuse semantic
    roles and theme intent while retaining renderer-specific paint,
    projection, antialiasing, and depth decisions.
11. **Adopt SvelteKit and build Internal Studio/Public Web.** Host migration and
    product surfaces follow proven publication, authoring, navigation, and
    performance boundaries. Animation assets remain framework-neutral.

Ranks 1–5 are the immediate tranche. Ranks 6–11 remain ordered follow-up and
must not be pulled into the first run merely because nearby code makes them
tempting.

## Gates And Dependencies

- Rank 1 has a mandatory human visual checkpoint. Its canonical reference is
  the economics `animation-station` projection; approval requires text to be
  present before pinning, calm rail entrance, readable cue timing, exact
  reverse behavior, no scroll-jacking, and a credible phone fallback.
- Rank 2 follows that checkpoint so publication work preserves an approved
  visual target. It precedes rank 3 so the current client-mounted route and
  mixed stylesheet are not duplicated.
- Rank 3 has its own projection-parity checkpoint. It may share semantic state
  and the progress-rail contract but not stacked geometry.
- Rank 4 consumes stable lesson structure and progressive publication. It does
  not persist arbitrary Svelte source or activate the full Internal Studio.
- Rank 5 consumes static headings, stable motion-passage IDs, and direct state
  restoration from ranks 2–4.
- Rank 7 requires a structurally different rank-6 caller. Economics alone
  cannot authorize a universal lesson schema.

## Performance And Product Boundaries

- Current Svelte coupling is conceptually low but operationally high: assets,
  semantic state, clocks, renderer sessions, compiler data, and custom
  elements remain framework-neutral, while the economics route currently
  mounts an empty HTML shell into one large client component.
- Keep Source Serif 4 during choreography discovery. After local anchors are
  stable, compare it against a system serif. Remove unrelated global font and
  editor closure from the public route regardless.
- Split the mixed economics stylesheet by responsibility:
  `tutorial-foundation`, `graph-surface`, `dimensional-continuity-graph`,
  `economics-equilibrium-graph`, `economics-demand-shift-lesson`, and selected
  projection/station styles.
- Keep light mode. Dark and light are both legitimate preference and
  accessibility contexts; forced-colors support is a separate requirement.
  Tune dark first, then run bounded light parity after the human checkpoint.
- The progress rail is read-only. A scrubber is interactive. Both, plus scroll,
  URL, TOC, and keyboard actions, drive one semantic playhead rather than
  independent animation clocks.
- IntersectionObserver may gate lifecycle and lazy activation, but local
  geometry owns continuous station phase and progress. Direct navigation sets
  semantic state without replaying intermediate frames.
