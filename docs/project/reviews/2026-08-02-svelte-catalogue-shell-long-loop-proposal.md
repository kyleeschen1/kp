# Reversible Svelte 5 Catalogue Shell Long-Loop Proposal

Date: 2026-08-02
Status: complete; all 26 slices closed in Theseus

## Outcome

The approved vector checkpoint passed human review, and the Svelte 5 shell is
now the canonical catalogue host. The former imperative application
composition was removed in a separate rollback unit after the Svelte route had
been pressured through equation, Graph2D, Graph3D, economics, physics,
programming, generated-reader, Review, URL, and terminal-state callers. The
asset loader, runtime clock, renderer ports, URL codec, and Review service
remain framework-neutral authorities.

Final evidence includes 3,386 passing tests; 42 release checks across Chromium,
Firefox, and WebKit; the seven-state Svelte visual contact sheet; all-family
catalogue captures; production-review and promotion-memory closure; and a
1,008-module production build with no Svelte or TypeScript diagnostics. The
frozen bundle ratchets pass at 10,459 gzip bytes for the outer shell, 178,189
for the main host, 90,158 for the measured catalogue route, and 71,795 for the
place-value increment.

Normal-profile performance is regression-clean at 280 ms LCP, approximately
0.00022 CLS, 13 ms interaction paint, and 17.6 ms animation-frame p95. The
constrained profile retains explicit optimization debt: its longest task is
106 ms and frame p95 is 33.3 ms. No ceiling was widened. SvelteKit, Internal
Studio, Public Web, the public editor, and rank-6 matrix-to-linear-map remain
separate follow-on decisions and work.

## Why This Loop Is Current

Rank 5 is certified through `animation.dot-projection.basic`. The next content
frontier is rank 6, matrix-to-linear-map, but the accepted product sequence
places one reversible Svelte 5 catalogue-shell proof before that caller. This
lets KP test whether a declarative host actually reduces application
composition complexity before Internal Studio or Public Web adopts SvelteKit.

The current catalogue already has the desired product shape: a flat searchable
rail, one visible artifact, compact transport, optional inspector and
parameters, and lower-left Review capture. The proof therefore replaces only
the imperative host composition and lifecycle. It is not a redesign and it is
not an animation-engine migration.

The user approved the exact 26-slice long-loop contract in conversation on
2026-08-02. The typed Theseus run contract owns that ordered slice ledger,
verification evidence, live status, and stop state. This document owns the
rationale, approved boundary, visual checkpoint, and promotion criteria.

## Canonical Reference And Acceptance

The canonical reference is the approved vector dot-projection catalogue route,
`animation.dot-projection.basic`, at wide and narrow viewports and at its
settled and projection checkpoints.

The Svelte exemplar must preserve:

- the current asset-first three-region tiling and compact visible controls;
- in-shell selection without a full document load;
- stable URL, Back/Forward, playhead, query, rail scroll, focus, inspector,
  parameter, and Review-draft behavior;
- one lower-left Review composer mount across asset transitions;
- loading, not-found, error, reduced-motion, and static truth;
- selected-caller loading for KaTeX, Graph SVG, Three.js, programming, and
  generated-reader capabilities; and
- current bundle, layout-stability, interaction, and animation-frame budgets.

The proof must not add a second playback clock, asset registry, renderer path,
review history, or parallel semantic state. The Svelte view may observe and
command the existing framework-neutral host services; it may not become their
authority.

## Preservation Boundary

The following remain framework-neutral and semantically unchanged:

- `KpAnimationAsset`, semantic objects, transformations, selectors, lineage,
  and authored assets;
- runtime samplers, renderer-neutral frames, playback clocks, and transport
  laws;
- equation, graph, diagram, Three.js, and programming renderer ports;
- catalogue loading and selected-capability package contracts;
- URL codecs and canonical artifact routes;
- Review service, screenshot protocol, inbox history, and production erasure;
- authoring commands and future publication bundles; and
- existing reader, dashboard, workbench, and public-route behavior.

Current CSS and the approved catalogue visual language remain canonical until
the exemplar checkpoint. Presentation may change only where Svelte requires an
equivalent lifecycle joint; aesthetic cleanup is deferred.

## Rollback And Promotion

The smallest rollback unit is the isolated Svelte catalogue entry, its typed
host adapters, and its Vite integration. The current imperative route remains
available until human approval. After approval, the default-route cutover and
the later removal of obsolete imperative composition are separate commits and
can be reverted independently.

Promotion requires all of the following:

- visual parity for the vector exemplar at wide, narrow, reduced-motion, and
  static checkpoints;
- unchanged engine, clock, renderer, URL, Review, and lazy-capability
  ownership;
- browser proof for selection, cancellation, history, focus, scroll, draft,
  and playhead restoration;
- no eager KaTeX, Three.js, programming, or generated-reader leakage;
- no widened performance or bundle ceiling; and
- explicit human approval of the live exemplar.

The run must stop at that visual checkpoint before making Svelte the default
catalogue route or generalizing through other callers.

## Execution And Verification Cadence

The approved run has 26 independently verifiable slices. The first tranche
freezes the existing baseline, integrates Svelte without route cutover,
extracts typed host joints, reconstructs the catalogue shell over the existing
player, and reaches the vector checkpoint. The second tranche, which remains
behind that checkpoint, promotes the route, pressures every capability family,
removes only proven-obsolete imperative composition, and runs the release
matrix.

Each completed slice receives one focused commit. Inner loops use changed-path
tests and the stable catalogue browser or visual commands. Shared routing,
package loading, lifecycle, and integration changes receive broad verification.
Promotion and release boundaries run typecheck, the full test/build gates,
production-review closure, promotion-memory validation, performance and bundle
attribution, relevant cross-browser suites, and Theseus workspace validation.

## Stop Conditions

Stop immediately when:

- the vector exemplar reaches its mandatory human checkpoint;
- work would move animation, semantic, clock, renderer, authoring, or
  publication authority into Svelte;
- the host requires a second loader, clock, review history, or URL state;
- compatibility requires changing a canonical route or public/reader surface;
- a selected capability becomes part of the default bundle or startup path;
- an existing performance ceiling would need to be widened;
- visual parity requires an unapproved redesign; or
- verification evidence is missing, contradictory, or cannot be recorded.

## Explicit Deferrals

- SvelteKit application routing, SSR, prerendering, and deployment;
- Internal Studio and its typed authoring session;
- Public Web, the public editor, mission pages, and lesson publication;
- rank-6 matrix-to-linear-map implementation;
- animation assets, renderers, clocks, or semantic-runtime rewrites;
- a universal renderer, scene graph, parameter schema, or motif registry;
- catalogue-wide visual restyling or disposition changes;
- LLM explanation milestones M4 and M5; and
- account, classroom, authentication, or learner-state work.
