## Why this loop is current

Human review accepts the current quadratic animation as a diagnostic exemplar
but rejects it for publication and architectural promotion. Its semantic
authorities, branching, graph synchronization, drill-down, accessibility, and
review behavior are valuable; its crowded compound motion and exception-heavy
scheduling are not a scalable basis for the next animation families.

The immediate question is now falsifiable: can one lineage-constrained glyph
reconciler and one bounded geometry scheduler cover one-to-one, many-to-one,
one-to-many, and crowded nested notation while preserving KP's interactive
advantages and reducing scheduling code?

Long mode is required because the experiment crosses semantic execution,
presentation planning, DOM measurement, the JavaScript renderer, headless
sampling, accessibility, cards/Cloze, branching, responsive layout,
performance, and architecture deletion. It remains one bounded replacement
experiment, not a family rollout.

## Objective

Build and evaluate:

- one matcher that reconciles glyphs only within verified semantic lineage;
- one deterministic, cached, bounded geometry scheduler with an inspectable
  conservative fallback;
- one JavaScript backend that preserves live interaction;
- one headless test backend that proves renderer independence; and
- four adversarial cases that either pass the common path or terminate the
  custom-planner hypothesis.

The loop must finish with one of two architectural outcomes:

1. **PASS:** the common path meets semantic, visual, interaction, performance,
   and deletion budgets; or
2. **STOP_CUSTOM_PLANNER:** any case needs operation-specific scheduling, so KP
   retains conservative rendering and its semantic/interactive strengths but
   stops general custom-planner investment.

One bounded implementation-defect correction may be proposed only when a
failure is demonstrably inside the common algorithm rather than evidence for
bespoke case logic.

## Canonical references and observable acceptance

The preserved solve-x reader is the canonical reference for one-to-one
identity, native KaTeX settlement, direct seek/rewind, responsive attention,
and interaction. The numerator/fraction fixtures are the reference for
many-to-one multiplicity and Cloze. The quadratic plus-minus branch is the
reference for one-to-many identity and branch continuity. The current crowded
quadratic interval is the negative pressure fixture and comparison baseline,
not the desired scheduling policy.

Observable acceptance requires:

1. The semantic executor establishes target trees, identity, provenance, and
   multiplicity before visual matching.
2. The matcher reconciles equal glyphs only inside allowed lineage and reports
   ambiguity rather than choosing semantic identity.
3. Ambiguous or unsupported cases visibly settle, replace, or cut at a
   certified boundary without corrupting semantics.
4. Clearance is compiled from settled native notation for the active font and
   viewport; plans are deterministic, bounded, inspectable, and cached.
5. No case adds an operation-specific scheduler or durable backend/glyph IR.
6. Hover, focus, annotations, accessibility, Cloze, branching, seek, and
   rewind bind to semantic entities and survive the shared renderer path.
7. Default compound work depicts the canonical operations at increased speed;
   the same trace remains available for drill-down.
8. The JavaScript artifact executes from serialized static data without
   runtime network, LLM, Python, CAS, or Manim dependencies.
9. Wide and phone projections pass explicit collision/occlusion checks or
   visibly choose the conservative fallback.
10. The experiment removes or reduces at least one old scheduling policy site
    and does not increase the count of operation-specific scheduling modes.
11. Runtime and payload remain inside the budgets established before
    integration.
12. Human review judges the first 1:1 exemplar and the final four-case contact
    sheet at least as clear as their preserved baselines.

## Preservation boundary

- Preserve canonical operations, exact math, semantic target trees, lineage,
  multiplicity, provenance, selectors, clocks, checkpoints, and reverse laws.
- Preserve the accepted solve-x, fraction, quadratic branch/graph, cards,
  Cloze, hover, annotation, accessibility, URL, review-inbox, responsive,
  static export, and production behavior.
- Preserve native KaTeX ownership of settled states and isolate the radical
  WebGL handoff residual.
- Keep the current quadratic implementation and deterministic captures as the
  diagnostic baseline until the experiment is decided.
- Preserve unrelated user-authored roadmap, thread, decision, design, and
  portable-publication changes in the dirty worktree.

## Smallest rollback unit

Each slice is one focused commit. New artifact metadata, semantic lineage
adapters, matcher, scheduler, headless sampler, JS binding, each exemplar, and
each deletion are independently reversible. The whole experiment can be
removed without reverting canonical semantic authorities, accepted product
surfaces, or the preserved baselines.

## Allowed work

- Evolution of the existing durable animation artifact to carry
  renderer-independent presentation constraints and capability requirements.
- Deterministic adapters from canonical operation execution to semantic
  lineage suitable for visual planning.
- One lineage-constrained matcher, one geometry scheduler, one conservative
  fallback, one ephemeral plan format, one JS backend integration, and one
  headless backend.
- Focused integration of exactly four cases: simple solve-x, numerator/fraction
  merge plus Cloze, quadratic `±`, and one crowded quadratic interval at wide
  and phone widths.
- Stable visual tooling, collision/occlusion diagnostics, performance/payload
  measurements, architecture counters, tests, deletion of replaced policy,
  and Theseus evidence.

## Disallowed work

- Operation-specific schedulers, quadratic-only planner branches, or new
  exception taxonomies.
- A durable glyph IR, separate branch/card/backend artifacts, or a second
  semantic animation format.
- Full Manim export, Python runtime integration, video encoding, CAS work,
  live LLM APIs, dynamic packages, or another renderer family.
- Repair of the separate radical `1/2` renderer-handoff residual.
- Workbench publication of the quadratic, family-wide promotion, curriculum
  expansion, or new algebra/domain exemplars beyond the four cases.
- Broad visual redesign, new animation styles, or unrelated roadmap work.

## Verification cadence

- Inspect `npm run verify:impact -- --path <changed-path>` before using
  `--run`.
- Run focused deterministic checks for semantic, matching, plan, and geometry
  helpers.
- Add typecheck and `theseus workspace validate` at standard boundaries.
- Run affected equation, flashcard, accessibility, reader, Workbench, browser,
  production, and build gates at broad boundaries.
- Extend the committed scope-specific visual entrypoint for deterministic
  experiment captures; keep output under `tmp/codex/`.
- Run release-level gates at slice 24.
- Commit every completed slice with its Theseus evidence.

## Human checkpoints and promotion criteria

Slice 14 retains the exemplar-first evidence gate. The user explicitly approved
implementation of the whole experiment on 2026-07-24, so this checkpoint does
not pause execution unless its evidence triggers another named stop condition.
Continuing means only that the common path is clear enough to pressure-test; it
does not approve architecture promotion or quadratic publication.

Slice 24 decides the hypothesis. `PASS` requires all automated criteria, the
deletion budget, and explicit human judgment that the four-case result is at
least as clear as the preserved baselines. `STOP_CUSTOM_PLANNER` preserves the
semantic and interactive system while ending further generic planner
investment.

## Contract stop conditions

- **H1 FIRST-EXEMPLAR:** produce and verify the slice-14 evidence before cases
  2–4; stop only if it exposes a named semantic, visual, layering, complexity,
  performance, or preservation failure.
- **H2 FINAL-DECISION:** stop at slice 24 for explicit `PASS` or
  `STOP_CUSTOM_PLANNER` review.
- **H3 BESPOKE-SCHEDULING:** stop immediately if any case needs an
  operation-specific, quadratic-specific, fraction-specific, branch-specific,
  or viewport-specific scheduling algorithm.
- **H4 AMBIGUITY:** stop if the matcher must infer semantic lineage from glyph
  equality or silently choose among plausible lineages.
- **H5 LAYERING:** stop if measured glyphs, backend plans, DOM handles, or
  renderer resources must enter the durable artifact.
- **H6 PRESERVATION:** stop on exact math, lineage, multiplicity, branch,
  graph, card/Cloze, accessibility, review, route, seek, rewind, native
  settlement, or baseline regression.
- **H7 COMPLEXITY:** stop if scheduling-policy sites or operation-specific
  modes increase, or if no old common-path policy can be deleted or reduced.
- **H8 PERFORMANCE:** stop if budgets require case-specific optimization,
  silent feature lowering, or relaxed interaction targets.
- **H9 RADICAL-ISOLATION:** stop if the experiment modifies or relies on the
  radical WebGL handoff residual.
- **H10 SCOPE:** stop before full Manim export, another renderer/domain,
  Workbench publication, curriculum expansion, live LLM integration, CAS work,
  or broad style redesign.
- **H11 USER-OVERLAP:** stop if work cannot be separated from unrelated
  user-authored worktree changes.
- **H12 VERIFICATION:** stop if a required gate fails without one bounded
  common-algorithm correction.

## Done contract

The approved loop is complete only when all 24 slices have a terminal state,
the four cases use the same matcher and scheduler or have triggered the named
stop, the artifact remains renderer-independent, JS and headless backends have
declared capability behavior, static execution is proven, performance and
deletion budgets are measured, deterministic review evidence exists, and the
human checkpoint records either `PASS` or `STOP_CUSTOM_PLANNER`.

## Explicit deferrals

- Full Manim, video, image-sequence, SVG, WebGL, and additional backend
  exporters.
- General family migration after the four cases.
- Repair of the radical renderer-handoff residual.
- Quadratic Workbench publication or further current-scheduler polish.
- Live LLM APIs, CAS integration, dynamic packages, media encoding, curriculum,
  learner memory, and new subject domains.
- New operation categories, specialized motifs, style systems, or universal
  choreography laws not required to evaluate the hypothesis.
