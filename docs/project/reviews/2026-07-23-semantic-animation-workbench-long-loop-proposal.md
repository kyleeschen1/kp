# Semantic Animation Workbench Long-Loop Proposal

Date: 2026-07-23
Status: proposed; awaiting explicit execution approval
Decision: `../decisions/2026-07-23-kp-semantic-animation-workbench-order.md`

## Objective

Build one canonical Semantic Animation Workbench inside the Semantic Editor so
an animation can be found, previewed, understood, reviewed, and moved through
its lifecycle without treating every representation as a separate animation.
Use that workbench to introduce quadratic solution branching, then extract only
the contracts proven by a second consumer.

This successor replaces the old integral, vector, and matrix continuation. It
does not discard those domains; it moves them behind the Workbench and
quadratic checkpoints.

## Canonical cohort

The first workbench cohort contains three deliberately different lifecycle
states:

- the approved power-to-radical exemplar;
- the approved derivative secant-to-tangent exemplar; and
- the planned quadratic solution-branching exemplar.

The animation catalog remains the authority for concrete animation identity.
Representation registries, Theseus, promotion evidence, and the development
review inbox remain separate authorities joined by stable references.

## Allowed work

- Add a derived canonical animation index and explicit representation links.
- Reuse the existing picker, catalog, player, review inbox, and Theseus data.
- Add a Semantic Editor Workbench route, fuzzy search, preview, badges,
  acceptance brief, review evidence, and representation switching.
- Introduce the quadratic semantic and visual exemplar only after the Workbench
  control-plane checkpoint is approved.
- Normalize a local contract only after the quadratic becomes a second
  consumer.

## Disallowed work

- Do not create a second animation database or manually duplicate Theseus
  progress.
- Do not make cards, lessons, exports, or styles separate animation identities.
- Do not redesign Agenda, replace the review storage protocol, or merge
  unrelated branch work wholesale.
- Do not begin integral, vector, matrix, arithmetic, FTC, BFS, economics,
  programming, physics, dynamic package loading, or course-scale curriculum.
- Do not generalize subjective visual language before its named human
  checkpoint.

## Preservation boundary

Preserve existing animation IDs, semantic documents, runtime clocks, editor
deep links, learner routes, renderer ownership, KaTeX settlement, seek and
rewind behavior, reduced/static projections, accessibility, and append-only
review history. Planned items must remain visibly non-playable. Existing
Animation Library navigation remains available until the Workbench replacement
is approved.

## Checkpoints and promotion criteria

### Workbench control-plane checkpoint

The reviewer must be able to find all three seed items, see only one canonical
result per animation, play concrete results, understand the acceptance brief,
distinguish every lifecycle facet, inspect item-specific evidence, and switch
representations without changing animation identity.

The independently reversible rollback unit is the Workbench route, derived
index, adapters, and tests. Existing Animation Library behavior remains the
fallback.

### Quadratic exemplar checkpoint

The reviewer must see exact branch semantics, a readable factorable and
quadratic-formula relationship, stable KaTeX endpoints, presentation-only
branch scheduling, and exact rewind. Approval promotes only the exemplar and
the cross-consumer contracts explicitly demonstrated afterward.

The independently reversible rollback unit is the quadratic semantic fixture,
compiler bindings, choreography, Workbench publication record, and focused
tests.

## Verification and cadence

- Run impact-selected focused checks inside each slice.
- Run typecheck and Theseus validation at every standard boundary.
- Run route, review, browser, accessibility, responsive, seek/rewind, and
  architecture cohorts at broad boundaries.
- Run the full repository suite and production build at both human checkpoints
  and final release.
- Commit every completed slice with its Theseus evidence.
- Keep the development server and stable visual commands reusable across the
  loop.

## Contract stop conditions

- Human review is required after slices 21 and 24.
- Stop on authority ambiguity, identity collision, silent status conflict,
  review-history mutation, runtime duplication, route regression, accessibility
  regression, or exact seek/rewind failure.
- Stop if implementation would enter a deferred domain or require a second
  animation database.
- Stop if unrelated user-authored roadmap or design work cannot be kept out of
  a slice commit.
