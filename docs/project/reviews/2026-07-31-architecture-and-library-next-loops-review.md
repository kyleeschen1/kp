# Architecture And Library Next-Loops Review

Date: 2026-07-31
Status: recommendation
Promotion order: unchanged from `plan-revision.kp.v19`

## Decision Summary

Run one bounded baseline-recovery loop before implementing the rank-3
economics exemplar. This is not a new platform program or a change to the
promotion order. It responds to six observed release-gate failures that make
future regression attribution unreliable: four repository architecture
ratchets and two shared payload ceilings.

After the baseline is trustworthy, resume the recorded content-led sequence:
economics, physics, public API tiers, the verified linear-problem bridge with
its first deterministic explanation spine, a short proven-family harvest, and
then vector and matrix promotion.

## Recommended Loop Sequence

### Loop 0: Restore A Trustworthy Release Baseline

Bound this to the six observed failures and project-memory drift. Do not add
features or redesign the renderer.

- reconcile the stale operation-promotion evidence path after the generated
  catalog split;
- consolidate the extra generic `escapeHtml` implementation through the
  existing context-appropriate boundary rather than raising the count;
- restore the native compositor source ceiling through real deletion or
  responsibility reduction, not by moving bytes outside the audited list;
- restore the neutral linear-provider dependency direction;
- bring the main-host and shared-reader payload closures under their accepted
  ceilings through attributable splitting or pruning, without charging lazy
  place-value code for pre-existing shared growth;
- update the stale cross-domain thread current action and extend the memory
  drift check if that check can cover the active-thread projection cleanly.

Exit when `npm test`, both payload gates, production closure, project-memory
alignment, build, and Theseus validation are green. Stop and return a focused
diagnosis if any payload repair requires a product-level loading change or a
new renderer architecture. The rollback unit is this baseline repair alone.

### Loop 1: Bounded Supply-And-Demand Equilibrium Shift

Build one deterministic model with persistent supply and demand curves, one
equilibrium intersection, one approved curve shift, exact parameter values,
and synchronized equation, graph, quantity, and narrative projections. Reuse
one clock, deterministic direct seek, existing SVG/graph contracts, Review,
static/export, and the single Animation Library host.

The first checkpoint is the visible shift and equilibrium handoff. Do not
generalize until human approval. After approval, prove a structurally distinct
parameter change through the same model-view contracts. No economics solver,
new runtime category, universal scene graph, or graph-specific clock.

This loop buys the first real proof of the synchronized-model-view composition
environment and adds a visibly different domain to the promoted library.

### Loop 2: Constant-Force Work And Energy

Use one exact constant-force scenario to synchronize force, displacement,
work, kinetic-energy change, a force-displacement graph, and a restrained
object/arrow diagram. Treat units, assumptions, and conservation as verified
semantic inputs.

This is the cross-domain second caller for the deterministic model-view seams
exposed by economics. Promote only contracts that both exemplars actually
share; keep curve equilibrium and physical conservation domain-native. No
physics engine or second diagram runtime.

This loop buys genuine architectural evidence that synchronized views compose
across domains, plus a second high-value demonstration.

### Loop 3: Public API Tiers And Adjacent Pruning

Declare the stable authoring facade, internal compiler/reader/rendering APIs,
and experimental surfaces before a generated-problem caller depends on them.
Inventory callers, forbid dependency inversions, and retire compatibility
facades whose final callers have migrated. Do not redesign motifs here.

This loop buys a comprehensible canonical implementation boundary for humans
and LLM callers, and prevents the generator bridge from depending on arbitrary
internal modules.

### Loop 4: Verified Linear Problem To Animation

Compile the existing verified linear-equation generator trace into canonical
`KpAnimationAsset` output with stable selectors, semantic lineage,
instance-aware reader descriptors, fail-closed unsupported presentations, and
conformance fixtures. Include the first minimal hand-authored
`ExplanationSpineV1`, learner state, approved vocabulary, and verified claim
references. Do not add model-generated prose yet.

This loop buys the first credible one-shot generation path: a model or problem
generator supplies verified semantic intent, while KP owns presentation,
layout, motion, accessibility, and playback through the canonical pipeline.

### Loop 5: Short Proven-Family Library Harvest

Promote a small exact-fraction cohort such as equivalent-fraction conversion,
common-denominator alignment, and addition/subtraction. Include a place-value
sparse-position or decimal item only if its explicit family proof obligation
fits without delaying the cohort.

The admission rule is strict: each item must reuse the current trace,
presentation union, compositor/session, scheduler, host, and promotion gates.
Any request for a new runtime or operation-specific renderer branch stops the
batch and becomes a separately reviewed architecture finding.

This loop measures the marginal cost of library growth. Success means several
approved animations per loop rather than another foundation program.

### Loops 6 And 7: Vector Projection, Then Matrix Linear Map

Resume the stable frontier with vector/dot-product projection, followed by a
`2 x 2` matrix acting on a vector and matrix composition from row/column dot
products. These pressure persistent grids, indexed correspondence, geometric
views, and nested evaluation without reopening written-arithmetic branches.

## Operating Rule Across All Loops

Each subjective content loop follows:

```text
one canonical exemplar
-> human visual checkpoint
-> smallest failed generic invariant, if any
-> return to the exemplar
-> structurally different second caller
-> adjacent pruning and promotion evidence
```

Durable semantic, ownership, clock, accessibility, endpoint, and known-
regression laws stay test-first. Novel choreography stays exemplar-first and
receives motif-specific tests only after visual approval. A content loop may
spend on infrastructure only when the exemplar falsifies a named invariant;
otherwise it must deliver visible library coverage.

## Expected Progress Shape

- Loop 0 restores trustworthy attribution and makes future regressions obvious.
- Loops 1 and 2 add two promoted domains while proving synchronized model
  views with a real second caller.
- Loops 3 and 4 turn the existing architecture into a stable generated-content
  entry point without introducing a parallel renderer.
- Loop 5 demonstrates that mature families can add several animations quickly.
- Loops 6 and 7 resume the recorded mathematical frontier with grid and spatial
  pressure.

The key strategic test is marginal cost. After the first synchronized-view
pair and generator bridge, a normal animation that introduces no new primitive
should be a small content loop dominated by semantic authoring and visual
review, not another multi-day infrastructure reconstruction.
