# Cross-Language Code Animation Foundation Closeout

Date: 2026-08-13
Status: complete
Theseus contract: `run-contract.kp.cross-language-code-animation-foundation-v1`

## Outcome

KP now has three approved, governed code-animation exemplars:

- TypeScript free-shipping threshold, the canonical novice-readable imperative
  refactor;
- Python free-shipping threshold, a structurally different build-time frontend
  for the same pedagogical claim; and
- Scheme factorial, a specialized evaluator-grounded recursive animation now
  directly selectable in the catalogue.

The catalogue contains 40 lazy assets. All three exemplars retain native,
searchable endpoint code, one deterministic sampled clock, direct seek and
rewind, reduced-motion behavior, stable URLs, and explicit host lifecycle.
No new clock, scheduler, browser parser, evaluator, scene graph, semantic store,
or framework-owned animation authority was introduced.

## What Became Shared

The caller comparison and Scheme pressure justified four bounded seams:

1. common syntax paint roles with exact half-open source ranges;
2. immutable complete-source projection and range-rebasing mechanics for the
   imperative callers;
3. causal settlement and native accessible-owner laws; and
4. explicit, transition-scoped exceptions for cuts, deletion, pedagogical
   dissolve, and reduced-motion endpoint jumps.

The third caller corrected the shared paint vocabulary to distinguish source
native, transient overlay, and target native ownership. HTML output also now
uses the established context-specific encoders in the TypeScript renderer and
Scheme publication instead of adding more local generic escaping helpers.

## What Deliberately Remains Local

There is no universal code parser, AST, evaluator, semantic model, renderer,
score, timing table, trajectory planner, or language-normalized identity.
TypeScript and Python retain their language-owned frontends, semantic recipes,
whitespace, IDs, scores, and geometry. Scheme retains syntax-address identity,
delimiter ownership, membranes, binding arcs, branch resolution, recursive
fold/bloom choreography, evaluator evidence, and deepest-first returns.

This separation is the result of the proof, not unfinished consolidation.
Flattening those mechanisms would discard the pedagogical differences the
third caller was meant to protect.

## Operations

Deterministic build-time generation and drift checks:

```text
npm run generate:typescript-refactor-semantics
npm run check:typescript-refactor-semantics
npm run generate:python-refactor-semantics
npm run check:python-refactor-semantics
npm run generate:scheme-factorial-trace
npm run check:scheme-factorial-trace
npm run generate:scheme-factorial-full-evaluation
npm run check:scheme-factorial-full-evaluation
```

Stable browser review commands:

```text
npm run visual:typescript-refactor
npm run visual:python-refactor
npm run visual:scheme-factorial
```

The TypeScript and Python assets have direct artifact pages. Scheme has both
its tutorial route and a direct catalogue selection under
`animation.programming.scheme-factorial`. Browser bundles consume checked-in
generated semantic data; they do not ship the TypeScript compiler, Python AST
frontend, Scheme parser, evaluator, or trace compiler as learner authority.

## LLM Repair Boundary

The current governed construction entrypoint is strongest for registered
equation operations. Code animation still requires a language-local fixture,
build-time frontend, semantic recipe, score, and motion plan selected from an
approved exemplar.

Types and executable laws now catch unknown IDs, invalid source ranges,
incomplete source projections, forged trajectory authority, premature
ownership handoff, invalid exceptions, and missing surface capabilities. They
do not invent semantic correspondence, decide which execution facts matter,
write pedagogical choreography, or synthesize trajectories. Unsupported work
must remain a typed repair gap; there is no arbitrary-source code generator or
generic fade fallback.

## Performance And Marginal Cost

The release bundle gate remains inside its budgets:

- outer catalogue shell: 10,328 / 50,000 gzip bytes;
- main catalogue host: 187,252 / 490,000 gzip bytes;
- measured catalogue route: 112,861 / 190,000 gzip bytes; and
- place-value incremental closure: 70,470 / 75,000 gzip bytes.

The shared programming adapter is 5,003 raw / 1,844 gzip bytes. Its selected
surface capability is 47,513 raw / 11,506 gzip bytes of JavaScript plus 13,089
raw / 2,465 gzip bytes of CSS. Scheme's generated full-evaluation data is
75,229 raw / 5,553 gzip bytes. These assets remain behind the lazy programming
capability, so they do not enlarge unrelated initial reader routes.

Python reused the asset model, clock, host, catalogue, URL, review,
accessibility, and capability infrastructure, but deliberately carried local
duplication until its visual approval. The comparison then removed only proved
duplication. Scheme library adoption was cheaper still: its existing sampler,
renderer, and choreography remained intact while a generated-data adapter and
standard catalogue registration exposed it. The foundation therefore passed
the architecture ROI test even though adding a new language is not yet a
one-file operation.

## Verification And Known Baseline

The TypeScript, Python, and Scheme scoped browser suites pass, as do focused
cross-language conformance, catalogue, source-projection, encoding,
architecture, typecheck, generated-drift, and bundle checks. The pre-existing
reader-budget baseline remains separately disclosed: shared reader routes were
already 7,834 gzip bytes above stale thresholds before this tranche, while
production closure passed and the code callers were absent from those built
reader assets. This closeout does not waive or attribute that debt to the code
foundation.

## Next Direction

Do not add another language now. Use the symbolic, graph, and code portfolio to
select the Public Web v0 projection and prove a small learner-facing product.
After that gate, the next useful code pressure is one structurally different,
novice-readable transformation such as wrap/unwrap. Only after a second
transformation topology should KP consider a bounded LLM request-and-repair
surface for code animation. Broad SICP, Python, TypeScript, or curriculum
expansion remains deferred.
