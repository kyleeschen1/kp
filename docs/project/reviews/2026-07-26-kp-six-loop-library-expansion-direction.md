# Six-Loop Library Expansion Direction

Date: 2026-07-26
Status: next-step review

## Current State

The canonical fraction split/merge construction contract is complete. Native
KaTeX owns settled typography; one renderer session owns moving paint; lineage,
seek, rewind, responsive behavior, accessibility, export, and governed
construction have focused proof. The active Theseus plan still described that
closed contract as current, and the ready queue is intentionally empty.

The remaining near-term foundation question is whether a structurally different
radical transition can be adopted through the same path and leave behind a
small, repeatable promotion kit. This is the appropriate last foundation gate
because it tests radical rules, indices, compound glyph structure, and exact
native settlement without broad family rollout.

## Directional Six-Loop View

### 1. Radical Reader Adoption And Promotion Kit

Make one `x^(1/2) -> sqrt(x)` reader transition canonical and exclusive while
preserving native semantics, interaction, and export seams. Extract only the
promotion steps demonstrated by both fraction and radical exemplars. A
unit-exponent dry run proves the promised low adoption cost. Stop for human
visual review before any family-wide promotion.

Visible progress: a second structurally distinct canonical reader animation and
an explicit, tested way to add the next one cheaply.

### 2. Foldable Distribution And Collection

Use `3(x + 2) + 2(x - 1) -> 5x + 4` as the exemplar. Compile its distributive
fan-out, multiplication, collection, and simplification into an immutable
transformation tree. Allow the learner to expand, collapse, auto-fold, or pin
nodes while preserving exact checkpoints and one renderer clock.

Visible progress: a richer algebra animation whose detail can be composed and
controlled without crowding or a second implementation.

### 3. Exact Arithmetic Evaluation Trees

Apply the same tree and fold laws to exact fraction quantity models and
place-value exchange. Begin with one exemplar that synchronizes symbolic
arithmetic with a concrete bar, area, number-line, or base-ten view; expand to
regrouping only after its checkpoint.

Visible progress: the library grows beyond symbolic rearrangement while AST
identity and fold behavior are reused.

### 4. Vector And Matrix Operations

Animate row/column selection, dot products, intermediate scalar evaluations,
matrix-vector or matrix-matrix composition, and the associated geometric
meaning. Grid-aware group layout replaces glyph-by-glyph improvisation.

Visible progress: nested computations compose inside a stable spatial
structure, proving that the system is not algebra-only.

### 5. Equation-Graph Derivative Bridge

Synchronize the difference quotient, secant geometry, tangent convergence, and
`f'(a)` on one clock. Routine algebra in the quotient is foldable so the learner
can keep the conceptual limit visible while drilling into a chosen symbolic
step.

Visible progress: symbolic and graph representations become one navigable
explanation rather than two coordinated demos.

### 6. Integral Accumulation

Coordinate partition refinement, many region objects, symbolic sums, and the
limiting integral. Use folding and patterned compression to keep repeated
rectangle calculations available without forcing every learner through all of
them.

Visible progress: the runtime handles large synchronized collections and
pedagogically honest compression.

## Progress Signals

The program is converging when:

- each new exemplar adds content and descriptors more often than runtime code;
- promotion slice counts fall after the radical kit;
- no transition has simultaneous legacy and canonical paint ownership;
- tree folding changes presentation but never semantic results or checkpoints;
- layout failures produce deterministic staging or folding, not ad hoc
  operation-specific routes;
- LLM-authored assets select verified operations, laws, and fold intent while
  deterministic compilers retain mathematical and visual authority;
- the visible catalog grows by domain while the number of runtimes, clocks, and
  lifecycle categories remains constant.

## Recommendation

Use a long loop for the radical adoption because it crosses reader integration,
native DOM preservation, compiler ownership, responsive/accessibility/export
checks, and a visual checkpoint. Keep the loop to the minimum complete
foundation program, then return to visible library expansion. Do not activate
an implementation contract until the exact radical proposal is approved.
