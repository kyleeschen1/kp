# Theme, Planner Binding, and Fraction-Equivalence Long-Loop Proposal

Date: 2026-08-18
Status: approved for execution
Approved contract id:
`run-contract.kp.theme-planner-fraction-equivalence-v2`
Target: `workflow.kp.delivery`

The unused `v1` contract was superseded before implementation because its
creation command omitted the required typed-autonomy mode, slice limit, commit
cadence, verification level, and stop conditions. `v2` preserves the exact
approved scope and slice order while making those execution boundaries
machine-checkable.

## Objective

Establish consistent development theming, close the natural-language equation
planner's path to governed semantic sources, and produce one native-KaTeX
fraction-equivalence exemplar for human visual review.

The loop should leave KP with a dark-by-default but explicitly overridable
development shell, one canonical planner-facing name for every exposed
operation, typed unsupported results, deterministic binding to verified
semantic evidence, and a reviewable fraction-equivalence transformation. It
must not turn model output into mathematical authority or promote a visual
motif before the exemplar is approved.

## Why This Loop Is Current

The frozen six-case live benchmark selected the correct semantic families but
exposed duplicate planner-visible identifiers and a missing deterministic
binding step. That boundary is now the highest-leverage generation bottleneck.
Fraction equivalence is the next visual pressure case only after that entrance
is trustworthy. The requested theme corrections are small, orthogonal, and
best resolved first so every later checkpoint is reviewed in the intended
development shell.

## Allowed Work

- development theme authority, defaults, and shared development-dock styling;
- neutral prose/KaTeX foreground token alignment without a prose-font change;
- planner exposure metadata, canonical names, alias normalization, typed
  unsupported results, governed-source binding, repair, and live benchmarks;
- balanced-equation and change-of-base binding through existing verified
  sources without changing their accepted presentation;
- fraction-equivalence semantic authority, one typed operation, one native
  KaTeX exemplar, stable URL state, and focused visual evidence;
- focused tests, stable visual commands, architecture checks, project memory,
  and Theseus evidence.

## Disallowed Work

- using KaTeX as the prose font;
- changing accepted logarithm, exponent, or balanced-equation choreography;
- public lesson-layout, curriculum, SRS, tutor, or generalized plugin work;
- broad fraction-family rollout before visual approval;
- matrix, code, Graph2D, or Graph3D generation;
- a general CAS, a second semantic authority, or model-authored source truth;
- unrelated pruning or repository-wide palette changes;
- edits to the dirty economics lesson or its generated publication artifact.

## Visual Reference And Preservation Boundary

The theme reference is the Catalogue rendering of
`animation.algebra.log-exponent.solve-two-power-x`, including its development
dock and review capture. With no explicit preference it must open dark; an
explicit light URL must remain light. Neutral KaTeX and prose must share their
foreground token while semantic accents remain distinct. The dock must use the
active surface background without overlap or layout shift.

The fraction reference is one new native-KaTeX equivalence transformation.
Fraction structure remains stable, factor identity is preserved, direct seek
and reverse are exact, and there is no final-frame snap, blank interval, or
endpoint correction. Theme work may roll back independently from planner work;
the complete fraction exemplar and its host are one reversible visual unit.

No renderer-wide motif promotion is authorized. Slice s26 always stops for
human review. A second structurally different caller is required after approval
before fraction equivalence can become shared motif infrastructure.

## Verification Cadence

Use focused unit and boundary checks inside slices. Run the project typecheck
and architecture checks at the two named integration boundaries, not after
every small metadata change. Live model calls occur only in s19. The new visual
treatment receives compositor and lifecycle checks plus one scoped browser
command; responsive and cross-browser promotion matrices wait for approval.

## Commit Cadence And Rollback

Each slice is one independently reversible commit containing implementation,
focused verification, and completed Theseus evidence. Exact path staging must
exclude protected user files. Theme authority, dock theming, planner exposure,
aliasing, validation, source binding, orchestration, and the fraction exemplar
remain separate rollback units.

## Expected Handoff

The loop ends as `HUMAN_CHECKPOINT` at s26 with a coherent dark development
shell, a strict and reproducible planner-to-source entrance, and one fraction-
equivalence exemplar ready for review. Fraction-family promotion, cross-domain
generation, Catalogue authoring improvements, and a tutor-facing capsule remain
ordered successor work rather than implicit scope.
