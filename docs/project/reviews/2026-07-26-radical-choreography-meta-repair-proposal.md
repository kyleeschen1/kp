# Radical Choreography Meta-Repair Proposal

Date: 2026-07-26  
Status: approved  
Contract: `run-contract.kp.radical-reader-promotion-kit-v0`  
Replaces: the rejected visual interpretation of slice 16

## Objective

Restore the accepted `x^(1/2) -> sqrt(x)` representational-succession
choreography inside the canonical native-KaTeX scene session, prove the same
session in the experiment and reader, and make choreography fidelity an
independent promotion gate.

This is a bounded repair of the reopened radical checkpoint. It is not another
general compositor program and does not authorize another animation family.

## Why The Previous Checkpoint Failed

Slices 1-15 correctly established semantic construction, selector lineage,
native endpoints, reader seams, exclusive paint ownership, responsive
containment, accessibility, export, and deterministic time behavior. Slice 16
then made the experiment and reader consume the same session and eliminated a
second host paint writer.

Those results were necessary but insufficient. The glyph experiment had
incorrectly become its own visual reference. Its canonical session preserved
the `x`, but paint compatibility reduced the declared root-notation
representational lineage to three source eliminations and one target
introduction. The generic lifecycle sampler consequently produced vertical
drift plus opacity changes. Experiment/reader parity passed because both hosts
shared the same degraded result.

The independent normative reference remains the accepted editor exemplar:

```text
editor-animation.sample.animation.radical-rewrite.square-root-as-power
```

That exemplar visibly moves and transforms the complete fractional exponent
into the complete radical operator before exact native settlement.

## Meta-Repair Rules

1. An implementation under test cannot define its own visual reference.
2. Semantic correctness, choreography fidelity, renderer mechanics, host
   parity, and native settlement are separate promotion gates.
3. A continuant, derived part, or declared representational succession cannot
   be opacity-only. Opacity-only motion is reserved for true artifacts.
4. A degraded or unavailable presentation strategy must report explicit
   checkpoint settlement; it cannot silently count as promoted motion.
5. Cross-host parity is a secondary integration gate, not a visual oracle.
6. A migrated exemplar must delete or bypass its superseded paint path in the
   same bounded program.
7. Subjective motion work stops for live review as soon as the first complete
   exemplar exists.

## Canonical Observable

Full-motion playback must:

1. show the exact native fractional exponent at the source;
2. keep `x` continuously visible, opaque, correctly sized, and correctly
   aligned as the radicand;
3. move and deform the fractional exponent as one structural material owner;
4. form a recognizable radical hook and overbar before native handoff;
5. settle into the exact native KaTeX target without a geometry, color,
   baseline, or ownership snap; and
6. reproduce the same semantic frame under direct seek and rewind.

Reduced motion and unavailable structural-morph capability use explicit
checkpoint settlement. They do not substitute an unlabelled crossfade for the
full-motion contract.

## Approved Phase Sequence

### Phase 1: Correct the oracle

- Make the original editor exemplar the named normative reference.
- Expose original, canonical experiment, and reader through one browser-readable
  comparison surface with a shared semantic scrubber.
- Mark the current fade-only canonical radical as unpromoted.

### Phase 2: Add failing choreography gates

- Add a fade-dominance probe for visible semantic material.
- Require meaningful act-phase occupancy and nonzero structural
  transport/deformation for representational succession.
- Reject a declared succession that resolves solely to independent
  eliminate/introduce paint.
- Preserve persistent-`x`, exact endpoint, seek, rewind, and handoff probes.
- Prove the current implementation fails for the intended reason before
  changing production behavior.

### Phase 3: Compile structural succession

- Project the existing radical fragment lineage, material-continuity bundle,
  and motif binding into the canonical renderer session.
- Keep lifecycle truth unchanged. Structural morph is an orthogonal
  presentation strategy inside the existing `atom-transit` mode, not a new
  lifecycle, scheduler, runtime, or clock.
- Select the strategy from typed lineage and presentation intent. Do not branch
  on an operation id, route, glyph string, KaTeX class, or viewport.
- Resolve blocked capture or missing capability to explicit checkpoint
  settlement.

### Phase 4: Port the accepted solid morph

- Reuse the existing generic solid-mask renderer and the accepted
  opposite-corner profile.
- Give one canonical session exclusive structural-paint ownership through the
  act phase.
- Preserve exact native source/target ownership and native settlement.
- Keep WebGL as an internal paint strategy under the canonical session; do not
  expose a second product renderer or durable animation artifact.

### Phase 5: Live exemplar checkpoint

- Drive experiment and reader from the same session.
- Compare original, experiment, and reader at the named semantic moments under
  wide/phone and DPR 1/2 profiles.
- Keep solve-x and fraction controls green.
- Open the live comparison in the development browser and stop for human
  review.

Phases 6 and 7 remain inactive until explicit approval of phase 5.

### Phase 6: Consolidate and retire

- Move the editor radical exemplar onto the shared canonical session.
- Remove the radical-specific editor material-layer/WebGL bridge once no
  consumer remains.
- Retain the generic solid-mask implementation as a canonical renderer
  strategy.
- Prove one session, one clock, one structural owner, and one settled native
  DOM contract.

### Phase 7: Install the reusable promotion gate

- Require a normative reference, semantic-motion audit, choreography-fidelity
  probes, explicit fallback status, host parity, and duplicate-retirement
  evidence for future subjective promotions.
- Revalidate solve-x and fraction.
- Close repaired slice 16 only after all gates and final human review pass.
- Resume promotion-kit extraction and the unit-exponent cost proof without
  changing their no-new-core-category criterion.

## Preservation Boundary

Preserve:

- governed semantic authoring and canonical construction;
- existing correspondence, fragment lineage, material continuity, motifs,
  clocks, and checkpoints;
- exact native KaTeX endpoints;
- reader accessibility, focus, hover, annotations, Cloze, transcript, URL,
  static, reduced-motion, responsive, and export seams;
- approved solve-x and fraction behavior; and
- unmigrated compatibility coverage.

Do not:

- add another public renderer, runtime, clock, or durable geometry artifact;
- let generated or LLM-authored content select coordinates, CSS, glyph
  matches, WebGL parameters, or renderer internals;
- add radical-, route-, glyph-, KaTeX-class-, or viewport-specific branches to
  the canonical compositor;
- generalize solid-mask presentation to unrelated operations without a
  separately reviewed exemplar; or
- proceed to slices 17-20 before the live radical checkpoint passes.

## Rollback

Each numbered phase is independently committed. Before phase 5 approval, the
old editor exemplar remains intact as the normative reference. If the canonical
session cannot reproduce its choreography without violating the preservation
boundary, stop with `STOP_CONDITION`, keep the radical reader unpromoted, and
retain slices 1-15 as semantic and integration evidence.
