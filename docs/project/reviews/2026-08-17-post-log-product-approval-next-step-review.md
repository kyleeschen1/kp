# Post Log-Product Approval Next-Step Review

Date: 2026-08-17
Status: recommended; implementation requires approval

## Question

What should KP do after human approval of the shared two- and three-factor
log-product choreography?

## Current Evidence

- Binary and three-factor product callers share one semantic family, motif
  timing profile, Native KaTeX optical profile, deterministic clock, and
  renderer path.
- Persistent factors keep identity and move directly; target enclosures use
  canonical outside-in function wrapping; derived `ln` operators and `+`
  connectors expand from fixed centers on one syntax-resolution window.
- The narrow equation core, typed extension protocols, generated dispatch,
  verification modes, compiler compression, ownership convergence, and
  application/bundle isolation are complete. Another speculative
  infrastructure tranche has no named blocker.
- The existing log-quotient caller already has semantic, endpoint, catalogue,
  browser, and visual evidence. Its difference-to-quotient topology is the
  intended structurally different pressure case.

## Recommendation

Run one bounded log-quotient visual-pressure iteration.

The canonical caller is
`animation.algebra.log-quotient.difference-to-quotient`. Preserve its semantic
contract, native endpoints, factor identities, fraction meaning, catalogue
identity, clock, direct seek/rewind, reduced motion, and accessibility.

The visual question is narrower than “make quotient look like product.” Test
whether both operations share this semantic phase grammar:

```text
source applications release
-> persistent operands redistribute
-> target structural relation becomes legible
-> target application receives its argument
-> final operational syntax resolves
```

For the quotient direction, `x` and `y` should visibly become numerator and
denominator, the fraction bar should establish quotient structure, target
parentheses should receive that complete structure, and the fused `ln` should
resolve without implying that either source logarithm persists as the target
glyph. Product timing, fraction geometry, and fusion choreography must not be
copied merely for consistency.

Stop at a human visual checkpoint. Promotion requires the quotient caller to
reuse the canonical compiler, function-wrap invocation, Native KaTeX session,
and shared semantic phases without adding a clock, renderer, identity law,
core dispatch branch, or caller-authored geometry.

## After That Checkpoint

1. If approved, compare product and quotient and promote only the common phase
   and role contract; keep timing and optical geometry local unless both
   callers genuinely share them.
2. Remove any superseded quotient-specific production path and uniquely owned
   duplicate tests in the same rollback unit.
3. Begin one bounded migration-wave-A family through the declarative entrance,
   retiring its bypass and redundant authority beside the final caller.
4. Measure whether that migration is materially cheaper than the pre-narrow-
   core baseline before scheduling a broader wave.

## Explicit Deferrals

- no new animation family;
- no learner-facing layout iteration;
- no public-site, SRS, tutor, or curriculum expansion;
- no universal symbolic renderer or global motif timing table; and
- no new infrastructure work without a measured blocker from quotient or the
  subsequent migration slice.
