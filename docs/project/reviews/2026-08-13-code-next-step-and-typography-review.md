# Code Next Step And Typography Review

Date: 2026-08-13
Status: recommendation; consistent with the active roadmap

## Recommendation

Do not add another language or code-animation subsystem next. Use the approved
TypeScript free-shipping refactor as the code caller in the Public Web v0
projection proof alongside one symbolic and one graph explanation. This tests
whether the existing code artifact can become a legible, searchable,
responsive learner experience without changing its semantic or motion model.

After the product projection gate, build one structurally different code
transformation: a novice-readable wrap/unwrap sequence with obvious motivation,
such as surrounding unsafe parsing work with a guarded error boundary. Its
purpose is to pressure indentation, enclosure, block movement, and persistent
identity rather than repeat helper extraction.

Only after that second topology should KP add a bounded LLM code-animation
request/repair surface. More languages, broad SICP work, and arbitrary-source
generation remain deferred.

## Proof Scope

The projection proof should preserve the approved asset and demonstrate:

- complete searchable source and explanatory text before enhancement;
- one compact interactive scrubber over the deterministic timeline;
- direct links to the artifact, playhead, and relevant semantic object;
- readable wide and phone compositions without resizing code typography;
- native accessible endpoint ownership and reduced-motion behavior; and
- no new clock, parser, renderer, score, or code-specific page lifecycle.

The question is whether KP can present the artifact as a compelling lesson,
not whether the refactor animation engine can acquire more capabilities.

## Current Code Typography

The approved TypeScript, Python, and Scheme code surfaces use this system
monospace stack:

```css
ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, monospace
```

On a current macOS browser this will ordinarily resolve to the platform's SF
Mono-style face, with Menlo as a nearby fallback. The exact appearance is also
substantially shaped by the dark `#0d0e1c` surface, warm `#ede8d0` foreground,
syntax palette, regular weight, and generous line height.

This is distinct from the proportional system sans stack now used by Internal
Studio and Animation Catalogue chrome. The formerly bundled `Kinetic Press New
Computer Modern Mono` root face is retained only as unreferenced rollback
material. Economics prose continues to use Source Serif 4, while code retains
the system monospace stack; these are intentionally separate typography roles
rather than one universal face.

## Explanation-Font Recommendation

Do not immediately make the system code stack the universal explanation face.
It is a strong candidate for code, short stage captions, step cues, semantic
labels, and compact annotations. Keep long-form explanatory paragraphs in a
proportional reading face until a three-shape Public Web typography comparison
shows that monospaced prose remains comfortable.

Advantages of a mono-forward explanation treatment:

- strong visual continuity between prose, code, and moving tokens;
- predictable character metrics for animated material and annotations;
- an austere, distinctive technical voice;
- excellent alignment for short parallel claims and symbolic references; and
- a system stack can avoid font download, swap, and layout-shift costs.

Costs and risks:

- long paragraphs become wider, less shape-distinct, and often slower to scan;
- code and explanation lose a useful categorical distinction;
- SF Mono, Menlo, and Consolas produce meaningfully different cross-platform
  typography;
- the system stack does not visually harmonize with KaTeX as closely as a
  Computer Modern-derived reading face; and
- headings and reflective prose can acquire an unintended editor or terminal
  tone.

The smallest useful typography proof should compare one long paragraph, one
short focus cue, inline KaTeX, and one code stage on desktop and phone. Test
three policies: proportional prose, universal system mono, and the recommended
hybrid of proportional paragraphs with system-mono instructional material.

## Roadmap Effect

No roadmap change is required. The recommendation instantiates the already
current Public Web v0 projection gate and retains wrap/unwrap as the next code
topology after that gate.
