## Recommendation

Choose one useful explanation the user actually wants to author, within a
currently supported capability. For the most direct test of this migration,
prefer the composed factoring/evaluation source path: three states, two
operations, explicit left/right compound order and supported integer arithmetic.
Do not quietly widen its grammar to make a preferred example succeed.

## Trial packet and boundaries

Give the author only the supported authoring packet, schema/example, exact
validation/Apply/publication commands and repair vocabulary. Start with
`../authoring/composed-algebra-authoring-packet.md` for the recommended path,
through `../authoring/llm-generation-entrypoint.md`. Record any later specialist
source inspection as an intervention; do not disguise it as ordinary authoring.
Use a fresh human/model context unfamiliar with the compositor implementation.
External services or paid calls require their own approval; a deterministic
fixture exercise is not independent author evidence.

After the user selects the explanation, predeclare five variants. Prefer
meaningful variation in numbers, compound structure and explicit orientation,
not five cosmetic title changes. Keep every valid case within documented
presentation support. Include separate wrong arithmetic and valid-but-unsupported
cases. These must yield located, actionable repairs without silently substituting
a generic animation or changing the last valid displayed revision.

## Work and success criteria

1. Freeze the task, five variant descriptions, support boundary and baseline
   packet. Record author familiarity and assistance conditions.
2. Author and check each source. Log first-pass success, every repair attempt,
   elapsed author time, extra documents retrieved, files changed and specialist
   interventions. Do not omit unsuccessful attempts.
3. Apply each valid revision to the canonical Focus Card; inspect exact stops,
   reason flow and preserved motifs. Check full/compact readings, prompts,
   exact-position return, displayed-source export and immutable publication
   against that same revision.
4. Batch the representative visual/pedagogical results into one review packet
   with the working shared URL. Interrupt earlier only for a real scope/safety
   issue or a new treatment requiring approval. No routine nonvisual check-ins.
5. Publish the measured result and select one next improvement from the largest
   observed authoring bottleneck. Do not automatically turn every difficulty
   into renderer work or start another capability tranche.

The central target is **five completed unfamiliar variants with zero renderer,
clock or semantic-engine edits**, plus transparent invalid/unsupported recovery.
Report source/schema/template edits separately from library interventions.
If an engine repair is necessary, record that variant as requiring intervention;
preserve the failure and propose a bounded repair rather than redefining success.
Instruction-only repairs count as packet friction, not zero-effort success.

Compare first-pass and one-repair completion, total author effort, retrieval
overhead, intervention count and revision coherence across projections. Show
per-case results as well as totals; five cases cannot establish a general success
rate. Learner comprehension remains a separate study: a compiling card is not
evidence of understanding. Human review should assess whether motion explains
the deduction, not merely whether controls work.

## Visual gate, preservation and done contract

Slice 17 is the single planned user check-in after initial approval. It batches
one canonical explanation and its five same-family variants; approving this
plan explicitly permits preparing that bounded variation set before review.
It does not permit another family or new aesthetic treatment. The packet must
give a functioning URL and exact source/Apply instructions, not assume that the
URL itself selects a custom variant. The primary question is whether the
unchanged group remains perceptually understandable as its count is combined.
Controls, text/fraction alignment and revision coherence are necessary checks,
not substitutes for that judgment.

Promotion requires accepted explanation/prose, canonical motifs, correct
endpoints, readable retained information and revision-consistent projections.
If review needs source/prose-only refinement, make it within the same bounded
exemplar and resubmit the batched packet. New motion/layout decisions are out
of scope. After acceptance, continue slices 18–20 without another routine resume
request. Smallest rollback unit: one case's source and its associated fixtures;
packet corrections and test instrumentation are separately reversible commits.
Previously accepted primary/product sources and publication bytes stay intact.

Global stops: missing execution/agent authority; user pause; unsafe action;
unrecoverable evidence loss; a required subjective decision; or a dependency
that prevents all remaining independent in-scope work. Local unsupported cases
are expected observations, not automatic blockers for the whole trial. All
failed checks remain visible; budget-only issues follow standing measured repair
policy. No external model services, new math families, CAS, shared animation
framework, editor rewrite, accounts, deployment, merge or automatic follow-on.

The run is complete when it delivers an honest per-case report, checked retained
artifacts, the human review result and one evidence-ranked next recommendation.
Five successful source-only variants is the target, not a fact to manufacture.
Report authoring success separately from run completion. Do not infer learner
comprehension, general LLM success rates or isolation guarantees from this trial.
