# Phase-Ordered Choreography And Gestalt Style Long-Loop Proposal

Date: 2026-07-16
Status: proposed; awaiting explicit loop approval

## Conclusion

The next KP loop should compile every semantic motif through a universal
orient/reflow/act/settle/release choreography plan, then make the concrete
realization configurable through pinned gestalt styles. The loop should promote
the existing dashboard function-wrap, radical-rewrite, and linear-rearrangement
behaviors into conformance fixtures and add a three-term dot product as the
semantic-traversal proof.

This is the right next loop because the previous grammar loop solved identity,
lineage, layout, paths, and deterministic motion, while user review exposed the
remaining gap: smooth numeric interpolation does not guarantee perceptually
correct ordering or the preferred organic symbolic aesthetic.

## Proposed 30-Slice Contract

Each slice ends with focused verification and one commit. Standard verification
adds `npm run typecheck` and `npm run theseus -- validate`. Broad verification
adds the affected Chromium or integration suite.

### Baseline And Core Model

1. **Capture dashboard choreography baselines**
   Target: `next-action.kp.choreography.dashboard-exemplar-baseline-v0`
   Risk: medium. Verification: broad plus manual/runtime.
   Change: record orient, reflow, act, settle, release, geometry, stagger, and
   rewind evidence for function wrap, radical rewrite, and linear rearrangement.
   Commit: fixtures and failure assertions only.
   Stop if: exemplar behavior cannot be observed without changing it.

2. **Define choreography vocabulary and identity classifications**
   Target: `next-action.kp.choreography.vocabulary-v0`

   Change: encode semantic continuant, representational lineage, semantic object
   constancy, perceptual material continuity, and motion classification types.
   Commit: renderer-neutral types and validation tests.
   Stop if: identity depends on glyph or DOM matching.

3. **Define the universal choreography plan**
   Target: `next-action.kp.choreography.plan-schema-v0`

   Change: add mandatory orient/reflow/act/settle/release phases, explicit
   no-ops, dependencies, prerequisites, and checkpoints.
   Commit: schema, builders, and validation.
   Stop if: the plan needs concrete coordinates or a second clock.

4. **Enforce envelope dependency laws**
   Target: `next-action.kp.choreography.envelope-laws-v0`
   Risk: medium. Verification: standard.
   Change: focus-before-motion, reservation-before-reflow,

   Commit: law checks and path-specific diagnostics.

## Deferred

- Live model-provider and upload ingestion: deferred until generated output is
  gated by the choreography and style compiler.
- A public style marketplace: deferred until package validation and version
  migration are proven locally.
- New executable style plugins: deferred; this loop uses trusted existing
  primitives and declarative styles.
- Full existing-catalog migration: warning-first audit only, then later
  family-specific promotion.
- General diagram routing or 3D diagram language: outside this equation-focused
  proof.
- Stateful spring or particle simulation: disallowed because seek, rewind, and
  export must remain deterministic.
- Curriculum expansion, media encoders, and unrelated dashboard work: deferred
  to protect the choreography vertical slice.

## Expected End State

- New generated animations default to `kp.organic-subtle@1.0.0` with flat focus.
- Function wrap, radical rewrite, linear rearrangement, and dot product pass
  strict semantic, perceptual, style, accessibility, and rewind conformance.
- Organic motion uses arcs, diagonals, stagger, deterministic jostle,
  hierarchical token/fragment motion, cohesion, and calm exact settlement.
- `kp.restrained-editorial@1.0.0` proves configurable realization of the same
  semantic plans.
- Authors and viewers can switch compatible styles at the same progress.
- Elevated focus can be compared experimentally without changing x/y paths.
- LLMs author semantic choreography inputs only; KP owns concrete realization.
- Existing assets receive honest warnings until migrated family by family.

## Why This Loop Now

- It directly addresses the user-observed mismatch between dashboard exemplars
  and generated editor motion.
- It converts a preferred aesthetic into versioned, configurable, testable
  architecture.
- It strengthens the safe LLM authoring target rather than adding bespoke
  effects.
- It has independent verification and commit boundaries.
- It keeps 3D and shadows inside the existing semantic clock and renderer
  boundary.
