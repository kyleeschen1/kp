## Recommended Sequence

### Loop 1 — Punctuated-substitution visual checkpoint

Start from the existing provisional `2 × 3 → 6` comparison, whose recipe holds
the source, displays a measured punctuation cue, and then makes a discrete
replacement. Inspect it before changing code. If the isolated expression does
not genuinely establish the stable-anchor reading, revise it once with stable
outer context while holding semantic endpoints and the canonical compositor
fixed. Stop at a human checkpoint; do not register a shared family yet.

The visual question is narrow: can KP briefly punctuate the evaluated region
and replace it at the same native anchor without implying contributor fusion,
carrier identity, or readable simultaneous source/result ink?

### Loop 2 — Structural pressure and narrow promotion

If the exemplar is approved, apply the same declared family to one
structurally different operator shape. Promote only the laws that survive both
callers. Register friendly discovery metadata, required semantic evidence,
compatible handoffs, and release evidence without exposing geometry or timing
to authors or models.

### Loop 3 — Governed authoring round trip

Prove the product-facing compiler path rather than adding another motif:
natural-language intent or ordered LaTeX states should narrow among carrier
preservation, contributor fusion, and punctuated substitution; obtain a typed
clarification when intent is ambiguous; bind code-owned evidence; compile one
deterministic sequence; and return an exact playable URL. No generic fade or
caller-authored choreography may fill a gap.

### Loop 4 — Fraction pressure recovery

Return to the deferred `1/3 + 1/6` caller with the now-explicit evaluation
family choice and completed paint-ownership machinery. Decide whether the
caller proves fraction-equivalence promotion or exposes a genuinely new
evaluation topology. Do not complete fraction arithmetic merely for category
coverage.

### Loop 5 — Power/root inversion

Add the next mathematically distinct symbolic family only after the previous
round trip is reliable. Make inverse branches, sign choices, and domain
conditions semantic authority rather than presentation annotations.

### Loop 6 — First cross-domain frontend proof

After the equation entrance can generate several reviewed families end to
end, select one matrix or code transformation as a domain-owned frontend over
the shared request, sequencing, host, URL, and review envelope. This should
prove the boundary without importing the equation parser or Native KaTeX
presentation model into another domain.

## Loop Shape Guidance

- Loop 1 should be short and human-gated.
- Loop 2 can become a medium promotion loop after approval.
- Loop 3 is the best autonomous infrastructure loop because its acceptance
  criteria are typed and deterministic.
- Loops 4–6 should not be activated together; each changes a different source
  of uncertainty.
