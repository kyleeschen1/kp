## Objective

Create the first honest control surface and compiler foundation for turning
natural-language intent or ordered LaTeX states into verified semantic
animation sequences that resolve registered canonical motifs. Preserve typed
gaps for unsupported work and expose matrix, code, Graph2D, and Graph3D as
future domain frontends without flattening their semantics into the equation
compiler.

## Why This Loop Is Current

The project has strong semantic, runtime, native-KaTeX, hosting, review, and
URL machinery, but its asset inventory does not tell an author what KP can
generate. The narrow tool-neutral equation entrance supports only three fixed
operation surfaces, while many working assets remain registered, exemplar
specific, adapter-backed, or static. The approved log-product and log-quotient
callers provide the next warranted compiler promotion. A capability-derived
Coverage view and one equation-series compiler make that progress visible and
usable without reopening public layout work.

## Allowed Work

- a typed cross-domain capability plan and generated coverage projection;
- evidence joins over existing assets, operations, motifs, authoring surfaces,
  promotion records, and review state;
- the bounded product/quotient homomorphic crossover promotion with no visual
  change;
- one equation-transform-series request, validator, compiler, sampler, CLI,
  deterministic corpus, and typed repair taxonomy;
- a model-neutral natural-language planning port and recorded proposal format,
  without vendor integration or reliability claims;
- matrix, code, Graph2D, and Graph3D capability declarations and future
  frontend contracts at the shared envelope only;
- a minimal internal Coverage view;
- URL-backed view/theme/settings state, exact-link copying, global development
  dock navigation, and Review collision/state repairs;
- focused tests, one persistent visual check, architecture checks, bundle
  checks, and durable closeout evidence.

## Disallowed Work

- a complete CAS, theorem prover, arbitrary-code executor, or live-model
  provider integration;
- a universal parser, semantic operation set, renderer, motif registry, or
  geometry system across equations, matrices, code, Graph2D, and Graph3D;
- new public lessons, curriculum, SRS, broad tutoring, or public layout work;
- new subjective equation choreography beyond the already approved product
  and quotient behavior;
- implementation of the full fraction, root, matrix, code, Graph2D, or Graph3D
  backlog;
- hand-maintained readiness claims that are not tied to evidence;
- planned-only rows in the concrete Animation Catalogue;
- a second manually maintained phase-plan tree.

## Preservation Boundary

- approved log-product and log-quotient timing, geometry, cardinality,
  fraction construction, optical profiles, native settlement, and URLs;
- existing asset-first Catalogue behavior and fuzzy selection;
- one deterministic clock and framework-neutral animation authority;
- current public routes, Article grammar, code frontends, graph semantics,
  Graph3D lease limits, accessibility, review history, and user-authored
  content;
- unrelated dirty-worktree files.

## Visual Reference And Promotion Gate

The canonical UI reference is the current compact Svelte Catalogue shell: one
quiet surface, `h3`-scale heading, flat rows, no cards or ontology tree, and the
existing global development dock language. The new Coverage view must show the
entire ordered capability table without nested navigation. The dock must keep
playback unobscured and give visible pressed/focus feedback.

Automated checks may establish routing, URL restoration, collision bounds,
keyboard access, theme persistence, and exact review payloads. Human review
selects spacing, density, legibility, and whether the view is genuinely
simple. No broader UI treatment is promoted before that checkpoint.

## Verification Cadence

- Focused slices use the smallest named unit/schema/generation tests and
  `npm run verify:impact -- --path <changed-path>` before broadening.
- Standard boundaries add the relevant focused typecheck, architecture check,
  and `theseus workspace validate`.
- Shared routing, package loading, runtime composition, and UI slices use
  impact-selected broad checks plus the scoped browser command.
- The visual checkpoint extends the stable repository-owned catalogue capture;
  no changing scratch browser script is introduced.
- The inserted s19a checkpoint uses the existing log-exponent capture and
  browser entrypoints. Its canonical reference is the approved semantic
  `2^x = 7` sequence plus the canonical lateral function-wrap motif. Promotion
  requires readable intermediate beats, no clipped operators, no protected
  intersections, and exact seek/rewind. The independently reversible rollback
  unit is the one repair commit; the series compiler and approved log-product
  and log-quotient presentations are outside its rollback boundary.
- The release slice runs only after human approval and uses the impact-selected
  release gate, Internal Studio build, bundle boundary, and Theseus validation.

## Commit Cadence And Rollback

Each slice is one independently reversible commit containing implementation,
focused tests, and completed-slice evidence. Generated projections travel with
their source change. No broad `git add .` is permitted; unrelated worktree
changes remain untouched. The homomorphic promotion, series compiler, domain
seams, Coverage UI, URL codec, dock, and Review repair are separate rollback
units.

## Contract Stop Conditions

- any approved product or quotient visual behavior changes;
- the series path requires a second clock, renderer authority, or silent
  generic fallback;
- mathematical truth or identity is inferred only from glyph/text equality;
- cross-domain declarations require shared domain semantics;
- Coverage readiness cannot be tied to exact evidence;
- existing URLs, Review history, accessibility, or bundle boundaries regress;
- a subjective UI decision is required at s28;
- work would expand into a live-model provider, full CAS, public layout,
  curriculum, or the deferred transformation-family backlog.

## Expected End State

Before the human checkpoint, KP will have an evidence-derived transformation
coverage page, URL-reproducible settings, an unobstructed exact-state Review
flow, one promoted homomorphic crossover, one governed equation-series compiler
with typed repair, and honest frontend-required declarations for matrix, code,
Graph2D, and Graph3D. It will not yet turn arbitrary prose or arbitrary LaTeX
into animations. It will provide the stable, measurable boundary through which
a live model and additional motif families can be added without inventing
motion or silently lying.
