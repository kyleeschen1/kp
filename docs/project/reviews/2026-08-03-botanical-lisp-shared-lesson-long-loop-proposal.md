## Why this loop is current

The economics lesson has completed its discovery loop and later human-requested
navigation and rhythm refinements. KP now needs a structurally different caller
to learn which lesson mechanics are actually general. Botanical Lisp is a
better test than another equation lesson because it introduces recursive
identity, binding provenance, code-as-data, native code settlement, and a
subject-native stage while retaining the same continuous-prose, motion-block,
deep-link, progressive-enhancement, and salience requirements.

The loop deliberately builds Lisp locally first. Only after economics and Lisp
can be compared field by field does it extract shared lesson code. The result
should let later changes to article geometry, typography, navigation, controls,
scroll ownership, and semantic restoration apply to all adopted lessons,
without putting domain semantics or animation assets under Svelte or a generic
scene graph.

## Canonical reference and boundaries

- **Semantic exemplar:** `((lambda (x) (+ x 1)) 4) -> (+ 4 1) -> 5`.
- **Tutorial question:** How can applying a function transform code into a
  value without losing where each part came from?
- **Economics reference:** the current approved
  `/tutorials/economics/demand-shift/` route and its stable visual/performance
  evidence.
- **Observable acceptance:** exact S-expression and binding identity, direct
  seek/rewind, material conservation, native settled code, two cumulative Lisp
  motion blocks, calm scroll/manual coordination, reconstructible semantic
  URLs, progressive TOC/scrubber light DOM, responsive and reduced/static
  projections, bounded performance, and shared lesson code used by both callers
  without economics drift.
- **Preservation boundary:** existing economics semantics and visuals,
  `KpLessonDocument`, the current programming execution trace, catalogue
  contracts, shared runtime clock, custom-element event contracts, Review
  capture, and the tabled matrix frontier.
- **Rollback unit:** every slice is one focused verified commit. Lisp-local
  visual work remains removable until the final checkpoint; shared extraction
  starts only after the comparison gate.
- **Promotion boundary:** approval authorizes shared lesson mechanics, not a
  generic Lisp language pack, universal botanical motifs, a universal scene
  graph, or catalogue-wide lesson migration.

## Verification and cadence

Focused slices run the smallest semantic, projection, or single-browser proof.
Shared seams, routes, persistent state, custom elements, and renderer ownership
use broad checks. The final boundary is expected to include:

- `npm run test:botanical-lisp-tutorial`;
- `npm run visual:botanical-lisp-asset`;
- `npm run visual:botanical-lisp-tutorial`;
- the shared two-caller lesson visual/contract commands created by the loop;
- `npm run performance:botanical-lisp-tutorial`;
- `npm run test:economics-demand-shift-tutorial`;
- `npm run visual:economics-demand-shift-tutorial`;
- `npm run performance:economics-demand-shift-tutorial`;
- `npm run typecheck`;
- `npm run build`;
- `npm run check:architecture`;
- `npm run check:promotion-memory`;
- `npm test`;
- `git diff --check`; and
- `theseus workspace validate`.

Every verified slice is one focused commit. Progress heartbeats come from
`npm run --silent loop:status` at slice start, completion, commit boundaries,
and before any stop or handoff.

  caller after this checkpoint;

  macros, arbitrary Lisp parsing/execution, and other languages;

- a universal scene graph, stage grammar, motif registry, or animation schema;
- SvelteKit, Internal Studio, Public Web, mission site, Public Editor, or a
  catalogue-wide lesson projection;
- client-side KaTeX, client syntax-highlighter bundles, live LLM prose, and
  runtime editorial calls;
- resuming/reranking matrix-to-linear-map or another animation promotion; and
- broad cleanup outside files made obsolete by the two-caller migration.

## Contract stop conditions

Stop on source-of-truth conflict, identity inferred from glyph equality,
botanical motion that invents evaluator semantics, loss of native settled code,
nondeterministic seek/rewind, material without an explicit provenance reason,
scroll/manual discontinuity, more than one active sampler, economics visual or
URL regression, a shared layer requiring domain-specific branches, framework
ownership of semantic/runtime authority, eager heavy capability, widened
performance ceilings, overlap with unrelated user-owned files, missing durable
verification, or the final required human checkpoint.
