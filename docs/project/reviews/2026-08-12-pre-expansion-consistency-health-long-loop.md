# Pre-Expansion Consistency And Health Long Loop

Date: 2026-08-12
Status: approved for execution

## Objective

Make KP healthy for further development by reducing its effective decision
surface. Establish one obvious extension path, align standards and executable
APIs, reject obsolete conventions early, close the known catalogue layout-shift
defect, and prove with fresh LLM benchmarks whether established animation
vocabulary is materially easier to compose.

This is not deletion for its own sake. A file, API, compatibility path, or test
is removed only when reachability and replacement evidence prove that the
removal reduces real ambiguity or regression risk.

## Approved Order

### Causal health baseline

1. Capture source/test size, public entrypoints, compatibility, bundle,
   browser, verification, and dirty-worktree baselines.
2. Classify recent regression families from durable evidence.
3. Audit the canonical semantic-to-host extension path and competing paths.
4. Reconcile current instructions and canonical construction guidance.
5. Inventory public API modules and cross-boundary deep imports.
6. Inventory clocks, schedulers, registries, capability loaders, editor
   sessions, and stage lifecycle authorities.
7. Require complete caller, replacement, sunset, and retirement evidence for
   every compatibility entry.

### Known release defect

8. Attribute the exact equation and graph catalogue layout shifts.
9. Repair equation-stage reservation with unchanged hydrated appearance.
10. Apply the same contract to graph only if the underlying cause is shared.
11. Re-run capability loading, route closure, lazy-boundary, performance, and
    stage checks.

### One demonstrated convention conflict

12. Migrate accepted linear solve from legacy presentation metadata to its
    existing typed presentation profile.
13. Require every concrete catalogue asset to use a typed profile or deliberate
    defaults and forbid new legacy recipe authoring.
14. Prove whether any serialized, public, or production caller still needs the
    legacy recipe decoder; fail stale inputs explicitly if none does.
15. Retire legacy recipe compatibility entries and helpers only after last-caller
    proof.
16. Move equation presentation-profile policy from renderer ownership to the
    declared neutral animation owner.
17. Resolve the recorded sampled equation payload ownership debt only if the
    dependency graph becomes simpler; otherwise record a justified retention.

### Make the healthy path difficult to bypass

18. Align touched production callers with existing public seams and ratchet
    migrated directories against cross-boundary bypasses.
19. Standardize structurally equivalent lazy capability packs on serializable
    assets plus immutable runtime capabilities.
20. Standardize typed failure, last-valid-state, and no-silent-fallback behavior
    at touched authoring, asset, and capability boundaries.
21. Teach `verify:impact` about profiles, capability packs, ownership seams,
    stage reservation, and publication changes.
22. Consolidate only provably redundant touched-area tests while preserving
    distinct semantic, browser, responsive, accessibility, and regression
    evidence.
23. Add negative fixtures rejecting a second clock, import-time registry,
    legacy recipe author, unclassified compatibility entry, and renderer
    authority crossing a layer.
24. Add one stable `health:pre-expansion` command composed from existing gates
    and one explicit broader release variant.

### Readiness proof

25. Run the complete health and release matrix without weakening thresholds.
26. Measure final complexity and run fresh bounded-context LLM benchmarks for:
    an existing-operation variation, a two-operation composition, and an
    unsupported request that must return a typed repair gap. Close as
    expansion-ready or name the exact remaining blockers.

## LLM Benchmark Measures

- first-pass validity and validity after one typed repair;
- context and source files required;
- obsolete API selections;
- caller-specific code introduced;
- semantic endpoint and rewind correctness;
- time to a catalogue-previewable artifact; and
- silent fallback count, which must remain zero.

The benchmark must use a fresh bounded context and committed fixtures rather
than relying on the implementation conversation. It may generate disposable
scratch output under `tmp/codex/`, but durable claims must cite committed tests,
commands, and artifacts.

## Verification Policy

- Focused checks for inventories, pure selectors, fixtures, and typed tables.
- Standard checks add affected subsystem tests, typecheck, architecture, and
  Theseus validation.
- Broad checks cover browser hydration, persistence, routing, lazy package
  closure, rendering, performance, production builds, and the full suite.
- Run `npm run verify:impact -- --path <changed-path>` before executing its
  selected checks for implementation slices.
- Existing failed thresholds remain failed until repaired; no closeout may
  rename or relax them.

## Visual Exemplar Contract

The solve-x equation catalogue stage is the canonical reservation exemplar.
Acceptance requires the hydrated stage to preserve exact visible geometry,
styling, settled endpoints, semantics, accessibility, direct seek, rewind, and
lazy capability behavior while meeting the existing `0.001` CLS ceiling.

The graph stage may generalize the fix only when attribution proves the same
cause. A perceptible visual change, different cause, or necessary choreography
choice is a human checkpoint. The rollback unit is the individual equation or
graph reservation commit.

## Success Criteria

- all active release gates, including catalogue CLS, are green;
- code, instructions, and LLM guidance expose one canonical extension path;
- no unclassified clock, scheduler, mutable registration path, or compatibility
  entry remains;
- new legacy presentation metadata cannot be authored;
- legacy recipe paths are retired only when last-caller evidence permits;
- public APIs and production representations do not increase;
- impact verification detects touched risks early;
- production code holds flat or decreases unless small enforcement code
  demonstrably replaces a larger ambiguity; and
- the benchmark either proves established motifs materially easier to generate
  or identifies bounded remaining friction.

## Preservation Boundary

- user-modified economics Article source and generated publication;
- unrelated untracked documents;
- canonical semantic truth, lineage, direct seek, rewind, and one sampled clock;
- current visible choreography, settled native KaTeX, SVG semantics, static
  publication, accessibility, and stable URLs;
- retained historical evidence and independently useful projections; and
- existing performance, CLS, bundle, architecture, and type thresholds.

## Explicit Deferrals

No layout pruning quota, TypeScript or Python exemplar, matrix or curriculum
expansion, broad Graph3D promotion, SvelteKit migration, public-layout choice,
visual redesign, universal scene graph, general diagnostics framework, package
reorganization, repository-wide deep-import rewrite, or full timeline
unification belongs to this run.

## Commit Cadence And Stop Conditions

Commit each independently verified slice with its Theseus evidence. Stop on an
unexplained semantic or visual regression, loss of static/accessibility truth,
invalid provenance, unsafe persistence, threshold relaxation, a second runtime
authority, a subjective visual choice, a compatibility requirement without a
safe migration, unbounded bundle growth, user-owned file overlap, or work beyond
the approved boundary.
