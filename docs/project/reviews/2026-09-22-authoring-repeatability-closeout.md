# Authoring repeatability: outcome and next direction

The approved trial establishes two changed fraction chains through the existing
checked source, publication compiler and interactive host. It also exposes the
limits clearly: five of ten inputs check, only two have demonstrated application,
three successful checks are reference-only, and both algebra intentions were
blocked by malformed source IDs. The one permitted implementation repair restores
accessible native mathematics in fraction publication without changing visual
markup, semantic checks, animation or runtime payload.

## Evidence and interpretation

Ten raw proposals remain byte-pinned in `content/authoring/repeatability/`.
The [baseline findings](authoring-repeatability/baseline-findings.md), original
JSON outcomes and separate `rerun/` records retain every failure. All ten owner
reports are identical after repair. The broad expected-status match is 9/10,
but only eight intended test purposes were exercised: the algebra negative also
failed too early. Neither number estimates model precision or curriculum coverage.

The fraction proposals are `2/5+1/10 → 4/10+1/10 → 5/10 → 1/2` and
`3/4−1/6 → 9/12−2/12 → 7/12`, without hints or per-case engine edits. Their
adjacent Articles required content authoring. The browser harness applies exact
source bytes to an isolated response using the canonical compiler and runtime;
it is not a new public Apply feature or an immutable publication edition.
Source application failed static accessibility initially. Requesting the existing
KaTeX adapter's native MathML at the shared fraction publication helper repairs
both cases and all four established fraction hosts. Original failed preview
records remain alongside passing `preview-rerun/` records.

Structural safeguards separate source reports from application claims, pin input
hashes and revisions, and reject reference-only/rejected sources claiming applied
success. Regression tests preserve the first outcomes and exact before/after
owner reports. Publication tests require source-matching native MathML and
unchanged visual markup across all four callers; browser tests check actual
accessible output without JavaScript. These guards do not certify arbitrary new
choreography, editorial quality or learning.

The [cost comparison](authoring-repeatability/cost-comparison.md) includes all
affected production consumers. Main-host HTML gains 190 gzip bytes; initial and
activated JS/CSS remain 415,444 and 458,026 bytes. Zero per-case engine edits does
not erase the shared harness, two Articles, repair and verification work.
Engineering minutes are unmeasured. Cold/warm checker timings are incomparable;
no authoring speedup or learner benefit is claimed.

## What the loop changed, and what remains

The loop was useful: it converted a vague repeatability question into bounded
source/application evidence and found one shared accessibility defect. Its most
important result is honest separation of reuse, missing host integration and
author mistakes. It did not demonstrate that broad content generation is cheap.
The 24-slice plan was more granular than the product outcome needed; future
delivery should group result-only cases where compatible with the requested loop
workflow, while keeping frozen inputs and explicit authority distinctions.

Recommended next product experiment: one connected short argument using the
demonstrated fraction path, with two or three passages, prerequisites and exact
return. Measure source/Article work separately from engine repair. A small,
separately identified algebra follow-up can retry the intended cases from generated
examples; never replace this trial's failures. These are recommendations, not
new execution authority.
