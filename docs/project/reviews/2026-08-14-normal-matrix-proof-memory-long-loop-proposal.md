# Normal-Matrix Proof Memory Exemplar Long-Loop Proposal

Date: 2026-08-14
Status: proposed; awaiting explicit approval
Source specification:
`2026-08-14-normal-matrix-proof-memory-exemplar-spec.md`
Proposed contract id: `run-contract.kp.normal-matrix-proof-memory-exemplar-v1`

## Objective

Implement the bounded normal-matrix Proof Memory Loop exemplar through one
static searchable Article, one local native-KaTeX vignette, six deterministic
checkpoints, two attention cycles, eleven prompt projections, exact proof
re-entry, an internal static comparison, and a human visual/product checkpoint.

The loop tests whether KP can improve symbol recovery and proof reconstruction
without adding a scheduler, generic matrix system, new lesson layout, or shared
runtime authority.

## Why This Loop Is Current

The product experiment and exemplar specification are accepted project
direction. The existing Theseus queue still exposes the older economics public
projection action and is too thin for a long run. On approval, create a new
typed run contract from this proposal. Do not select a refill candidate or
silently repurpose the economics action. Economics remains the next product
caller after this bounded checkpoint.

## Estimate

- **Mode:** forced long
- **Slices:** 27
- **Expected active work:** approximately 10-18 hours before and after the
  mandatory human checkpoint; visual revision can extend this estimate.
- **Commit cadence:** one independently reversible verified commit per slice,
  including its Theseus evidence.
- **Context:** brief Theseus context per slice; working context only when the
  brief packet cannot support the implementation.

## Canonical Exemplar Boundary

- **Reference:** the mathematical proof and interaction contract in the source
  specification, informed by Michael Nielsen's spaced-repetition essay.
- **Acceptance:** the learner sees the row/column-to-product correspondence,
  predicts `r = 0` for the right reason, understands why `B` is normal, and can
  re-enter exact proof context from a prompt.
- **Preserve:** Article v1, build-time KaTeX, semantic addresses, native settled
  paint, one deterministic clock, current salience and flashcard contracts,
  approved public exemplars, and user-owned economics edits.
- **Rollback:** the Article, route, local semantic fixture, vignette, prompt
  projection, and route-specific checks remain independently removable.
- **Promotion:** none in this loop. One exemplar cannot create a shared matrix
  type family, palette, renderer, proof-memory grammar, or catalogue rollout.

## Allowed Work

- one original normal-matrix proof Article and prerequisite ledger;
- one local semantic asset, transformations, relations, checkpoints, and
  versioned vignette;
- one static/no-JavaScript publication and internal static comparison;
- one route-local progressive stage over existing native-KaTeX authority;
- two orient/act/settle/inspect attention cycles;
- one compact semantic checkpoint scrubber without autoplay or scroll control;
- eleven validated flashcard projections and direct proof re-entry;
- focused accessibility, responsive, theme, bundle, idle-cost, CLS, and
  deterministic-state checks;
- one stable repo-owned visual capture command; and
- project-memory and Theseus evidence required to close the exemplar.

## Explicit Deferrals

- SVD or any second linear-algebra theorem;
- generic matrix animation or proof-memory APIs;
- shared renderer or Article syntax changes without a demonstrated hard gap;
- scheduler, accounts, learner profiles, analytics, classrooms, or assessment;
- sticky, split, deck, scrollytelling, or universal layout work;
- Graph3D, Canvas, WebGL, particles, or decorative motion;
- public or advanced CodeMirror authoring;
- broad LLM prose/card generation;
- economics implementation; and
- post-checkpoint promotion before explicit human approval.

## Global Stop Conditions

Stop and report when:

- the proof or a prerequisite cannot be stated and reviewed rigorously;
- implementation requires Article v2, a second clock, another paint owner, a
  generic matrix engine, or model-authored geometry/timing;
- semantic identity must be inferred from glyph equality or KaTeX internals;
- static and motion evidence disagree mathematically;
- a direct link requires replay to become correct;
- the route cannot preserve no-JavaScript truth, accessibility, or 390-pixel
  fit;
- a required budget exceeds its ceiling without an independently removable
  cause and approved revision;
- user-owned economics or unrelated untracked work would need modification;
- visual judgment is required at slice 25; or
- any requested continuation would exceed the approved contract.

## Verification Cadence

- Run `npm run verify:impact -- --path <changed-path>` before selecting checks
  for a new production boundary.
- Add stable scoped commands for the exemplar rather than changing disposable
  scripts: `test:normal-matrix-proof`, `typecheck:public-normal-matrices`,
  `build:public-normal-matrices`, `check:public-normal-matrices-budgets`,
  `test:browser:public-normal-matrices`, and
  `visual:normal-matrix-proof-checkpoint` as their slices arrive.
- Use unit and single-exemplar browser checks during discovery. Do not run a
  broad browser matrix before visual approval.
- Run full typecheck and the all-route production build only at defined
  boundaries or when shared files require them.
- Keep Playwright at one worker and reuse the scoped visual command.
- Derive every progress heartbeat with `npm run --silent loop:status`.
- Run `theseus workspace validate` after every durable Theseus mutation.
