## Recommendation

Prioritize boundaries that let us change an explanation, choreography, or host
independently. Keep the first finite outcome from the
[October 29 repair roadmap](2026-10-29-next-step-review.md): composed algebra
and distribute/collect share an independently owned, validated mount, and the
superseded import paths are removed. Do not expand that milestone into a new
renderer or the entire architecture campaign.

After that first conversion, use anchored commentary as the next product-facing
test of the architecture. Repair the style and preparation boundaries needed by
that test, explore one spatial treatment, and promote only what a second caller
demonstrates. Personal practice remains the product destination.

The user's [October 30 capture](../capture.md#2026-10-30-fraction-tutorial-criticism-and-anchored-commentary)
rejects the fractional tutorial's content and its use of choreography while
strongly valuing anchored text. Keep the accepted reader behavior as a regression
reference; do not treat its tutorial prose as the editorial exemplar or spend
this architecture work polishing it.

## Evidence and limits

This is a targeted source assessment, not a new runtime benchmark or full audit.

- `src/experiments/common-factor/native.ts` owns validated mounts used by
  `src/experiments/composed-algebra/card.ts`, including distribute/collect.
  It constructs endpoints, the canonical session, layout, preparation, clock,
  resize and disposal. Useful guarantees already exist; ownership is misplaced.
- `src/experiments/composed-algebra-intuition/entry.ts` and
  `src/experiments/distribute-collect/entry.ts` import styles from four other
  example directories. This proves cross-example coupling, not duplicated
  shipping bytes.
- `src/reader/renderers/equation-material-layer.ts` removes inactive owners and
  recreates fragments on return, including computed-style cloning for applicable
  visuals. `src/reader/app/exemplar-entry.ts` coordinates this path with the
  canonical compositor. Canonical pool reuse alone cannot describe every
  preparation cost. Fresh measurements are required for any improvement claim.
- `src/reader/app/reader-canonical-equation-session.ts` already bounds prepared
  sessions and owns revision keys. Extend responsible ownership where appropriate;
  do not introduce an independent cache or animation clock.
- `src/semantic/semantic-scene-protocol.ts` already represents entities,
  relationships, groups, regions and correspondence. These contracts are not
  proof of a general nested 3D presentation hierarchy.
- `src/tutorial/focus-deck-annotation.ts` already separates entity-linked text
  and shared typography from renderer-owned anchoring. It is a useful starting
  point, not proof that relation-, occurrence- and beat-aware commentary already
  works end to end.

One question/attempt can retain its exact source context and return after reload. |

Style conversion and preparation repair are distinct work slices. Their scope is
the selected family, not a repository-wide cleanup or a demand to remove every
geometry read. Preparation should be distinguishable from frame sampling;
direct seeking must not replay intermediate motion. Exact structural transitions
may retain measured geometry where it explains the mathematics.

For anchored commentary, distinguish the mathematical referent from the specific
representation occurrence: two visible copies can share a referent but have
different roles. Wording and timing belong to the explanation; local attachment,
readable placement and transform propagation belong to presentation. Parent
motion should not require querying every descendant's browser bounds per frame.
Relation targets need an explicit visual realization rather than an invented
fallback coordinate. Reuse existing scene, attention, timeline and typography
owners instead of creating a parallel global model.

For the depth experiment, a useful question is which structure survives when an
operation acts on a combination. Choose an already supported mathematical
instance before adding domain semantics. The discussed derivative choreography
does not establish derivative authoring or renderer support. Human review selects
the spatial language; a planning document cannot certify it.

## Disposition of the previous proposal

- Shared mounting remains the first recommendation with the same finish line.
  The source-linked vision view's next outcome therefore remains accurate.
- Explicit document projection and removal of the HTML rewrite remain valid
  bounded repairs. They need not precede an isolated anchored-commentary
  experiment that does not use that document host. Repair them when that host's
  integration requires it; retain the earlier proposal and its finish conditions.
- Style ownership, completed retirement and concise authoring remain priorities.
  Every conversion includes removal or justified versioning of its old path.
- Broad performance sweeps, universal scene/ontology frameworks, catalogue-wide
  API renaming, new diagram families and a full workbench remain horizons, not
  prerequisites for the selected experiment or personal practice.
- Existing WebGL and diagram work is preserved. This recommendation does not
  impose a single renderer or pause those domains as a global policy.

## First action if implementation is selected

Trace the complete consumer set of the current validated mount, choose its
existing responsible shared owner, and implement the two-consumer conversion
with focused lifecycle and preservation checks. Keep it separately reversible.
Do not add anchored text, new choreography, or new visual defaults to that repair.
Subsequent visual work needs its own canonical artifact, host, renderer,
semantic authority, acceptance criteria and review checkpoint.

No implementation, new Theseus run or changed acceptance of existing visuals
is authorized by this review. It refines the proposed sequence without marking
the earlier campaign complete or turning all horizons into active work.
