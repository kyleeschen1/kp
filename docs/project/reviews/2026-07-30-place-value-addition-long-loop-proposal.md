## Objective

Promote one canonical multi-digit addition animation for:

```text
    278
  + 156
  ─────
    434
```

The primary animation is the conventional written algorithm: two right-aligned
three-digit addends stacked vertically, a plus sign immediately to the left of
the second addend, an underline beneath the second addend, and a result row
beneath the line. Addition proceeds from right to left. When a column
overflows, the result digit settles in that column while the carried digit
moves visibly to a carry slot above the next column and participates in its
evaluation.

A synchronized base-ten-block projection is secondary evidence for the same
semantic exchange. It may sit beside the written algorithm on wide screens or
be selected separately on phones. It must never replace, crowd, or become the
mathematical authority for the canonical stacked calculation.

The canonical path remains:

```text
verified place-value addition trace
-> immutable evaluation and fold projection
-> one shared runtime frame and clock
-> native KaTeX paint in a semantic column grid plus deterministic base-ten SVG
-> exact settled, accessible, and exportable state
```

## Why This Loop Is Current

The stable promotion ledger names place-value addition as rank 2, and approved
Theseus plan revision 16 marks multi-digit addition active after the promoted
exact-fraction exemplar. The exact-fraction work provides certified
operation-evaluation, identity-fission, identity-fusion, shared-session,
responsive-focus, native-settlement, Review, and evidence-derived promotion
seams. This loop tests whether those foundations now produce visible library
growth rather than another platform-only repair.

The new reusable architectural pressure is value-preserving place exchange:
ten lower-place quantities become one adjacent higher-place quantity while
preserving contributor provenance. The written carry and concrete exchange are
two projections of that same semantic event. This is content-led work; pressure
for a new compositor, renderer, clock, lifecycle, or scheduler is a stop
condition rather than permission for infrastructure expansion.

## Canonical Reference And Observable Acceptance

The exact written sequence is:

1. establish the right-aligned `278` and `156`, the plus sign, underline, blank
   result row, and empty carry row;
2. evaluate `8 + 6 -> 14` through the canonical operation-evaluation motif;
3. settle `4` in the ones result slot while the `1` moves upward and left into
   the tens carry slot;
4. evaluate `1 + 7 + 5 -> 13`, with the carried `1` visibly participating;
5. settle `3` in the tens result slot while the new `1` moves into the hundreds
   carry slot;
6. evaluate `1 + 2 + 1 -> 4`; and
7. settle the exact native result `434`.

The base-ten projection shows the same events:

- fourteen ones exchange into one ten and four remaining ones;
- thirteen tens exchange into one hundred and three remaining tens; and
- four hundreds settle as the final quantity.

Promotion requires:

1. exact integer state and typed place identity throughout;
2. compiler-minted adjacent-place exchange and complete contributor lineage;
3. one immutable trace, one fold tree, one sampled frame, and one clock for
   both projections;
4. native KaTeX paint roots arranged by a stable semantic column layout;
5. a fixed plus sign, underline, addend alignment, result columns, and carry
   slots with no baseline sag, font substitution, crowding, or endpoint jerk;
6. operation glyphs participate in evaluation, while carry and exchange use no
   generic fade, teleportation, or whole-expression replacement;
7. direct seek and outline navigation land only on animation starts or settled
   checkpoints, never transient overlapping states;
8. exact rewind, replay, rapid scrubbing, resizing, and representation
   switching are history-independent;
9. wide presentation may show both views, while phone presentation preserves
   the complete written algorithm and exposes the secondary view separately;
10. reduced motion, static/no-JavaScript, screen-reader, transcript, and export
    projections preserve the same causal explanation;
11. the existing lazy Animation Library and Review capture box remain the only
    display and review surfaces;
12. catalog status is derived from passed evidence and human approval; and
13. the implementation adds no new runtime, renderer, compositor, clock,
    lifecycle category, scheduler category, display page, or WebGL lease.

## Stop Conditions

Stop immediately if:

- exact quantity, place identity, contributor lineage, exchange conservation,
  fold truth, accessibility, export truth, or native endpoint authority changes;
- the base-ten projection becomes a mathematical source or crowds out the
  canonical stacked algorithm;
- evaluation, carry, exchange, or persistence falls back to generic opacity,
  teleportation, whole-expression replacement, or example-specific geometry;
- implementation requires a new runtime, clock, scheduler, lifecycle,
  compositor, renderer, display page, or WebGL lease;
- a missing presentation can typecheck, a certificate can be copied, or a
  status flag can falsely claim promotion;
- outline navigation exposes transient overlap, fast scrolling freezes, hidden
  views retain work, or a browser diverges;
- another promoted reader, Review, accessibility, export, or production
  boundary regresses;
- unrelated user-owned files must be overwritten;
- the visual checkpoint is rejected or not explicitly approved.
