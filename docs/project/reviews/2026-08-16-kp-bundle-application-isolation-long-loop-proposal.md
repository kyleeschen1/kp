# KP Bundle And Application Isolation Long-Loop Proposal

Status: approved
Approved: 2026-08-16
Execution owner: Theseus run contract

## Objective

Make each KP experience load only the capabilities it needs, repair the
place-value bundle boundary structurally, and isolate Internal Studio and
Public Web production graphs without weakening the framework-neutral kernel.

This is Tranche B of the architecture sequence. Tranche A closed the full
TypeScript dependency graph with zero exact exceptions; this tranche uses that
enforced ownership to make production closure attributable and application
boundaries real.

## Baseline

- outer catalogue shell: 10,819 / 50,000 gzip bytes;
- main host: 196,852 / 490,000 gzip bytes;
- measured catalogue experience: 118,535 / 190,000 gzip bytes;
- place-value increment: 74,980 / 75,000 gzip bytes;
- production build: 1,444 transformed modules; and
- dependency-direction exceptions: zero.

The place-value boundary has only 20 bytes of headroom. Vite also retains its
known large-chunk advisory. Neither may be hidden through a budget increase.

## Preservation Boundary

- Preserve semantic IDs, transformations, lineage, clocks, direct seek,
  rewind, sampled endpoints, native settled KaTeX, and accessibility output.
- Preserve current URLs, static publications, catalogue behavior, and public
  lesson output.
- Preserve framework-neutral animation assets and the zero-exception
  dependency-direction gate.
- Do not modify the user's uncommitted economics source or generated
  publication.
- Do not change choreography, visual tuning, layout, curriculum, or theme.
- Keep the binary log-product checkpoint as the next human visual action.

## Allowed Work

- bundle-scenario declarations, Vite-manifest closure analysis, attribution,
  budgets, and stable measurement commands;
- typed immutable native-KaTeX feature-pack ownership and caller migration;
- behavior-preserving place-value loading and closure repair;
- Internal Studio, Public Web, development-review, and dashboard entry-graph
  isolation;
- evidence-driven algebra and CSS splitting;
- Vite helper extraction that preserves entry ownership;
- narrow framework-neutral public entrypoints and dependency enforcement; and
- adjacent tests, compatibility retirement, documentation, and Theseus
  evidence.

## Disallowed Work

- SvelteKit adoption or physical `@kp/*` package extraction;
- new animations, curriculum, layout experiments, or visual redesign;
- Public Editor, accounts, SRS, learner modeling, or arbitrary plugin APIs;
- broad CSS consolidation unrelated to route ownership;
- budget increases used in place of structural repair; and
- mutation of protected economics authoring files or unrelated user work.

the full suite, and Theseus validation.

## Stop Conditions

Stop when:

- visible behavior, choreography, semantic identity, URLs, or static output
  would change;
- an entry graph cannot be isolated without SvelteKit or physical packages;
- place-value cannot reach ten percent headroom without product or visual
  changes;
- KaTeX migration changes native endpoints, accessibility, or paint ownership;
- splitting duplicates a heavy runtime or increases the selected closure;
- Vite helper extraction makes ownership less attributable;
- unrelated user work overlaps a required file;
- release evidence becomes non-deterministic; or
- work must broaden into any deferred product or visual tranche.

## Done Contract

The run is complete when selected experiences have deterministic closure
reports, place value has at least ten percent structural headroom, Internal
Studio and Public Web have isolated production graphs, development tooling is
absent from production, dashboard startup is data-only, algebra and CSS splits
are evidence-driven, narrow entrypoints are enforced, all release gates pass,
and no visible or semantic regression was introduced.
