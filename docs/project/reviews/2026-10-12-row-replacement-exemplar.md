# One reversible row replacement

Authorized October 12 by “go” after the bounded collection closeout recommended
one elementary row operation with explicit solution-set preservation.

## Outcome and boundary

Starting from the accepted two-equation system, show R1 ← R1 + R2, including
the right-hand side: [2, −1, 3 | 7] + [0, 1, −2 | −1] = [2, 0, 1 | 6].
Keep R2. The inverse R1 ← R1 − R2 explains both directions of solution-set
preservation. This is not a solver or a claim that the numerical matrices are
equal. Ordered unknowns remain unchanged.

Canonical source: `linear-system-source.ts` on the existing rectangular-product
host. Candidate URL: `?view=row-operation`. Existing `polynomial-view.ts` supplies
the completed collection state; a bounded row-operation adapter composes its
tokens with the existing contributor-fusion sampler and pouring-player clock.
Typed scalar/matrix objects own values and provenance; an exact integer
row-addition checker owns this new operation and inverse witness. Catalogue
row-operation declarations are provenance, not executable certification.

The target row rises into a compact working area. A copy of the retained source
row joins it, including RHS. Addition signs resolve, corresponding contributors
evaluate using the existing fusion treatment, and the new row settles into the
vacated destination. Equality withdraws while the matrix notation is incomplete.
Static before/after systems and a two-direction explanation remain readable.
All stages sample one playhead and reverse deterministically.

This first candidate uses a unit multiple only. The exact semantic checker can
validate other safe integer multiples, but no general visual authoring API or
scale-then-add choreography is claimed. Row 1 is the receiver; row 2 stays put.
The input vector and brackets retain their accepted layout. Equality is absent
while the receiver row is in the working area. Grouped signed coefficients stay
whole through the existing contributor-fusion mechanism. The final inverse
identity explains recovery; replaying the film backward is not itself the proof.

The checker requires distinct row indices and mandatory independent RHS values.
BigInt intermediate arithmetic guards exact integer storage before constructing
derived scalar values. Every result cites source, target and multiplier IDs;
unchanged source entries retain their original objects. It rejects self-addition,
non-integers, missing RHS, symbolic inputs, overflow and new/existing ID collision.
The residual identity e'_t = e_t + k e_s, e'_s = e_s and its inverse establish
solution-set equivalence for every assignment. Property samples and inverse
reconstruction tests pressure the implementation; they are not the proof.
