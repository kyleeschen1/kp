# Canonical equation renderer convergence long-loop proposal

Date: 2026-07-25
Status: approved for execution on 2026-07-25
Mode: forced long
Target: `workflow.kp.delivery`
Candidate plan option:
`refill.experiment.plan-revision.kp.v8.native-math-settlement`

## Objective

Resolve KP's equation-renderer fork by proving or rejecting one canonical
native-KaTeX scene renderer, then—only after a human-approved fraction
exemplar—make it the default for one gold reader card and remove that card's
duplicate equation-motion path.

The canonical upper pipeline remains:

```text
semantic animation
-> canonical operation trace and lineage
-> renderer-neutral frame
-> one native-KaTeX scene renderer
-> exact native KaTeX checkpoint
```

The renderer may use native continuity, atom transit, or conservative
checkpoint settlement as internal modes. They must share one observation,
reconciliation, sampling, ownership, and endpoint contract rather than appear
as separately routed animation implementations.

## Exact benefit

If the promotion gates pass, this loop leaves KP with:

- one understandable equation rendering path for the migrated gold exemplar;
- no query flag or peer compositor/material-layer implementations for that
  exemplar;
- a generic fix for the fraction typography handoff or a contract stop proving
  the compositor must not become canonical;
- one total-scene overlap and paint-ownership model across glyphs, rules, paths,
  merge, split, introduction, elimination, and settlement;
- preserved semantic animation assets, branches, direct seek/rewind, Cloze,
  focus, annotations, accessibility, static output, and export seams;
- a renderer contract that consumes canonical traces produced by deterministic
  compilers or governed LLM drafts without accepting DOM, geometry, styles, or
  keyframes from the model;
- durable visual baselines showing what “better” means rather than relying on
  test counts alone; and
- an explicit deletion/retirement ledger for superseded equation-renderer code.

If the generic typography gate fails, the loop stops before migration. That is
still valuable: it triggers the previously agreed custom-planner stop instead
of allowing a permanent second renderer or a growing exception catalog.

## Visible definition of progress

Progress is not “more animation modules.” It is observable movement down this
ladder:

1. **One stable baseline:** source and target share a deliberate equation
   anchor; the experiment no longer adds irrelevant vertical travel.
2. **One clean handoff:** the `(x+y)/2` material frame and native target are
   visually continuous at wide and phone sizes.
3. **One renderer contract:** native continuity, atom transit, and settlement
   are internal modes of one session.
4. **One default reader exemplar:** the gold card uses the renderer without a
   query flag.
5. **One fewer implementation:** its old operation-specific paint path is
   deleted in the same migration.
6. **One composable proof cohort:** merge, split, and radical succession use
   the same renderer vocabulary.
7. **One LLM-safe path:** a governed semantic draft compiles to the same
   canonical animation and renderer without model-authored pixels.

Every subjective promotion has a named contact sheet and human checkpoint.
Every mechanical promotion has exact direct-seek, rewind, accessibility,
responsive, static/export, payload, and production-closure evidence.

## Allowed work

- Experiment and production native-KaTeX scene observation, reconciliation,
  track sampling, style adaptation, ownership, and settlement.
- Stable fraction and reader visual entrypoints and their deterministic tests.
- One reader adapter/default-route migration after human promotion.
- Deletion or retirement of renderer code superseded by the migrated exemplar.
- Existing governed semantic/LLM fixture compilation into the canonical
  renderer contract.
- Project-memory and Theseus records required to close the architecture fork.

## Disallowed work

- Fraction-, plus-, radical-, viewport-, card-, or KaTeX-class-specific
  correction logic.
- A new paint kind, atom lifecycle, semantic operation taxonomy, durable glyph
  IR, or operation-specific geometry scheduler.
- Model-authored DOM, CSS, coordinates, keyframes, timing tables, or target
  mathematics.
- Global equation-family rollout before the two human checkpoints.
- Changes to graph, diagram, code, table, curriculum, media encoding, package
  loading, portable publication, or unrelated UI work.
- A permanent query-selected second reader implementation.
- Broad roadmap, thread, or user-draft rewrites before the renderer decision is
  accepted.

## Rollback units

- Slices 1–14: same-baseline fraction harness plus the generic style-adaptation
  model; revert without changing the prior compositor or semantic assets.
- Slices 15–20: canonical renderer-session boundary and internal mode
  selection; revert without changing reader defaults.
- Slices 21–24: one gold reader migration; revert to its preserved baseline.
- Slices 25–28: cross-family/LLM proof and cleanup; each is an independent
  commit.

## Human checkpoint criteria

### Slice 14: fraction exemplar

Promotion requires explicit human agreement that:

- source and target occupy one motivated stable equation anchor;
- the plus, fraction rule, numerator, and denominator show no endpoint snap;
- merge and inverse split remain legible at wide and phone sizes;
- the motion explains structural continuity rather than merely looking busy;
- no overlap, double ink, opacity trick, or clipped mark is visible; and
- the correction looks generic enough to test in a real reader.

### Slice 24: reader exemplar

Promotion requires explicit human agreement that:

- the canonical default is at least as clear as the preserved gold reference;
- causal focus and pedagogical timing remain legible;
- native interaction and accessibility remain intact;
- phone projection is composed rather than merely scaled down; and
- removing the old path is acceptable.

## Contract stop conditions

Stop immediately if:

1. the typography fix requires a plus, fraction, radical, viewport, KaTeX
   class, card, or operation exception;
2. the fraction endpoint jerk remains at the slice-14 checkpoint;
3. a new paint kind, atom lifecycle, semantic taxonomy, or operation-specific
   scheduler is required;
4. moving paint gains accessibility, focus, annotation, Cloze, or export
   authority;
5. native endpoint typography or mathematics is mutated;
6. DOM, geometry, computed style, tracks, or keyframes enter the durable
   animation artifact or LLM schema;
7. a migrated exemplar cannot delete or disable its superseded renderer path;
8. ordinary reader routes acquire unintended compositor code or exceed the
   five-percent regression policy;
9. direct seek, rewind, reduced motion, static output, headless output, or
   production closure fails;
10. either mandatory human checkpoint is rejected or materially ambiguous; or
11. work requires changes to deferred domains or unrelated dirty files.

## Verification cadence

- Focused checks after every slice.
- Typecheck and Theseus validation at standard boundaries.
- Browser, visual, architecture, build, performance, and production closure at
  slices 3, 11–14, 20–24, and 28 as appropriate.
- One independently reversible commit per completed slice.
- Broad `npm test` only at promotion/release boundaries unless impact analysis
  requires it earlier.

## Explicit deferrals

This loop does not build:

- the derivative bridge;
- a new animation authoring UI;
- broad LLM generation or prompt UX;
- global algebra-family renderer rollout;
- new graph, DiagramScene, code, economics, physics, or BFS exemplars;
- media encoding, curriculum, learner modeling, or dynamic package loading;
- broad portable-publication work; or
- a new Gestalt style package.

Those become valuable only after the renderer fork is resolved.

## Expected subsequent loops

### Loop 2: canonical animation construction and governed LLM round trip

Goal: let an author or LLM select canonical objects, operations, lineage,
motifs, emphasis, narration intent, and composition while deterministic KP
compilers own mathematics, timing, layout, typography, renderer selection, and
repair.

Visible result: several genuinely different algebra animations generated from
structured drafts, inspected in the dashboard, rendered by the one canonical
equation renderer, and exported from the same artifact.

### Loop 3: derivative bridge gold pedagogical exemplar

Goal: compose a finite-difference quotient, secant geometry, tangent
convergence, `f'(a)`, narration, focus, checkpoints, drill-down, and exact
rewind on one shared semantic clock.

Visible result: one beautiful learner-facing module that proves equation,
graph, interaction, and explanation compose without a new runtime.

### Loop 4: governed variation and promotion cohort

Goal: generate a bounded family of variants from the accepted animation
grammar, measure semantic/rendering closure automatically, and attach human
review only to genuinely new visual or pedagogical combinations.

Visible result: KP scales from one gold animation to a reusable family without
copying renderer code or reviewing every parameter substitution.

### Loop 5: cross-domain composition

Goal: apply the same animation artifact, shared clock, claim/evidence,
interaction, and renderer-capability model to one BFS/code or physics exemplar.

Visible result: proof that KP is a semantic-to-interactive compiler rather than
an algebra animation system.
