# Botanical Lisp tutorial next-step review

Date: 2026-08-03
Status: accepted direction; botanical Lisp replaces solve-x as the next
tutorial caller without changing the animation-promotion ledger

## Question

Is KP ready to generalize the economics publication work through another
tutorial, and should the previously designed botanical Lisp animation be that
caller?

## Recommendation

Yes, KP is ready for a structurally different tutorial caller. Do not first
extract a generic reader, motion-block schema, publication compiler, or stage
grammar from economics. Use one asset-first botanical Lisp exemplar to establish
the new domain truth and visual language, stop for human review, and then wrap
that approved asset in a Lisp tutorial using only the already portable
URL/TOC/scrubber contracts.

This is a better domain-crossing test than another equation lesson because it
pressures recursive identity, code-as-data, binding provenance, native code
paint, fold/reveal composition, and a subject-specific stage. It is a worse
choice if the only goal is the fastest possible proof of publication reuse;
generated solve-x remains the cheaper fallback because its semantic asset and
explanation spine already exist.

The earlier tutorial decision named generated solve-x as the second caller.
The user has now explicitly chosen the stronger cross-domain evidence supplied
by Lisp. The accepted replacement and shared-lesson boundary are recorded in
`../decisions/2026-08-03-kp-botanical-lisp-second-caller-and-shared-lesson-seams.md`.
Generated solve-x remains the recommended third caller.

## Recovered design provenance

The prior programming-language-theater design names Lisp as the first semantic
theater because source, data, recursive structure, evaluator input, and runtime
values can share structural lineage. Its exploratory `kp.botanical-recursive`
profile treats atoms as leaves, lists as branches, parentheses as flexible
enclosures, typed holes as destinations, and recursive return as material
gathering toward an ancestor.

The required law is material conservation: every visible semantic fragment
persists, gathers into or emerges from an ancestor, or enters/exits for an
explicit semantic reason. Native selectable code remains authoritative at
rest. Botanical material is a presentation projection, never the semantic
model.

The recorded first checkpoint is one recursive substitution through a nested
S-expression. Meta-circular evaluator dispatch, a language-family pack, and
other programming languages follow only after that recursive opening,
substitution, gathering, reconstruction, and rewind are accepted.

The tracked convergence proposal supplies a compact candidate:

```lisp
((lambda (x) (+ x 1)) 4)
-> (+ 4 1)
-> 5
```

Its intended diagnostic pressure is syntax-tree and subexpression identity,
binding/environment provenance, substitution without text-diff identity fraud,
application opening and collapsing, code flowing through code, selector
locality, direct seek, exact rewind, and reuse of KP's existing lineage, clock,
focus, and sampled-frame laws.

## Current implementation evidence

KP already has a deterministic programming execution-trace asset, SourceFile
selectors, stack/locals/output frames, a programming render target, canonical
animation wrapping, shared-clock sampling, export support, and selected-caller
catalogue hosting. That is useful transport and host evidence.

It is not yet the Lisp semantic substrate. The current trace is an ordered list
of call/evaluate/return/output steps over source ranges, stack frames, string
locals, and output. There is no implemented `SExpression`, pair/list identity,
quote boundary, lexical environment, binding occurrence, typed substitution
hole, closure, recursive return, or botanical renderer. The Lisp work therefore
adds a real semantic and presentation exemplar; it is not a reskin of the
addition trace.

The economics tutorial leaves only the semantic URL codec, TOC model/static
renderer/custom element, and scrubber renderer/custom element as explicit
portable candidates. Its corridor registry, cumulative projection, stage
composition, verification reveal, deep-link reconstruction, publication
compiler, scroll coordinator, and Svelte host remain economics-local discovery.
The Lisp caller should import the portable candidates directly and implement
its own local semantic timeline and stage until comparison proves more.

## Recommended sequence

### 1. Freeze the economics evidence

Treat the current economics route, review captures, performance budgets, and
framework-neutral interface ledger as the reference caller. Do not move its
local modules into shared packages.

### 2. Build one Lisp semantic animation asset

Create the smallest typed S-expression and evaluation fixture needed for the
canonical lambda application. Preserve object-language form, binding,
occurrence, argument, substituted form, runtime value, and environment
provenance as distinct identities. Validate the fixture against a bounded
deterministic evaluator or equivalent exact provider rather than making motion
the source of truth.

The first animation should stop at a human checkpoint after proving:

- whole-form recognition and reversible opening;
- binding `x` to argument `4` through an explicit semantic destination;
- structural substitution into `(+ x 1)` without token-diff identity fraud;
- reconstruction as `(+ 4 1)` and optional exact settlement as `5`;
- material conservation and explicit entry/exit reasons;
- native selectable code at settled endpoints;
- direct seek, exact rewind, reduced/static projection, and narrow layout; and
- no new clock, universal scene graph, or generic programming ontology.

### 3. Human-select the botanical language

Review enclosure shape, branch/leaf material, gathering, timing, pauses,
recursive depth cues, and the relationship between code text and botanical
structure before defining reusable motifs or a language pack.

### 4. Author the Lisp tutorial as the second caller

Use continuous prose around one persistent code/S-expression stage. A likely
learner question is: “How can applying a function transform code into a value
without losing where each part came from?” Use two local motion blocks:

1. open the application, bind the argument, and reconstruct the body;
2. evaluate the reconstructed form and gather it into the result.

Reuse semantic URLs, the static/enhanced TOC, and the static/enhanced scrubber.
Keep Lisp checkpoint projection, scroll corridors, stage composition,
publication compilation, and salience profiles local on the first pass.

### 5. Compare callers before promotion

Only after the tutorial passes human review should economics and Lisp be
compared field by field. Promote contracts that are identical in semantics and
lifecycle, not merely similar in TypeScript shape. Generated solve-x can then
serve as a lower-risk third caller for equation-specific pressure and guard
against overfitting the shared boundary to two unusually visual domains.

## Stop conditions

Stop before tutorial work if the Lisp asset cannot preserve binding and
subexpression identity independently of rendered text; if the botanical
metaphor invents evaluation semantics; if settled code loses native selection
or accessibility; if a general language pack becomes prerequisite; or if the
implementation requires moving economics-local modules into shared ownership
before the second caller exists.

## Decision taken

Proceed with botanical Lisp as the next tutorial caller and use the completed
economics and Lisp routes to extract only caller-proven shared lesson seams.
The approved 28-slice execution proposal is in
`2026-08-03-botanical-lisp-shared-lesson-long-loop-proposal.md`, with live
execution owned by `run-contract.kp.botanical-lisp-shared-lesson-v0`.

This choice updates the roadmap tutorial order but does not rerank the
animation-promotion ledger, resume matrix work, or promote botanical motifs.
