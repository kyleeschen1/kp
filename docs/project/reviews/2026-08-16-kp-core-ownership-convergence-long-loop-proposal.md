# KP Core Ownership Convergence Long-Loop Proposal

Status: approved
Approved: 2026-08-16
Execution owner: Theseus run contract

## Objective

Make the framework-neutral KP dependency graph mechanically enforceable,
eliminate the known upward dependencies, and resolve the legacy equation SDK
without changing visible behavior.

This is the ownership tranche of the broader architecture plan. Bundle and
application isolation remain a separately ordered follow-on tranche so bundle
optimization cannot conceal ownership mistakes.

## Preservation Boundary

- Preserve semantic IDs, transformations, correspondence, lineage, clocks,
  sampled endpoints, public URLs, static publication, and catalogue behavior.
- Preserve current bundle ceilings and the pending binary log-product visual
  checkpoint.
- Do not modify the user's uncommitted economics source or generated
  publication.
- Do not change animation choreography, visual tuning, layout, or curriculum.
- Do not adopt SvelteKit or perform a repository-wide package move.

## Allowed Work

- architecture declarations, import analysis, and boundary gates;
- program-trace ownership migration;
- removal of the linear-solve semantic/tutorial cycle;
- context-safe HTML-output ownership;
- renderer theme inversion;
- legacy public SDK reachability, retirement, or isolation; and
- adjacent tests, compatibility retirement, dashboard metadata, project
  memory, and Theseus evidence.

## Disallowed Work

- place-value compositor refactoring;
- catalogue pack splitting;
- CSS reorganization;
- Internal Studio or Public Web application restructuring;
- Vite configuration consolidation;
- new animations, public layout work, or physical package extraction; and
- any mutation to current economics authoring files.

## Ordered Slices

1. Record the proposal, preservation boundary, worktree exclusions, and
   follow-on tranche.
2. Capture import, bundle, typecheck, test-duration, and production-closure
   baselines.
3. Define typed module ownership zones.
4. Build a TypeScript-AST import extractor.
5. Implement source-coupling and runtime dependency-direction policies.
6. Freeze only exact known violations with owners and retirement conditions.
7. Add the ratcheted global gate to `check:architecture`.
8. Move program-trace contracts into neutral domain ownership.
9. Extract the addition source, selectors, and clock into a semantic fixture.
10. Rebuild the deterministic addition trace fixture under neutral ownership.
11. Migrate semantic and animation consumers to the neutral trace.
12. Make tutorial trace modules projections and retire obsolete shims.
13. Audit linear-solve tutorial-behavior reachability.
14. Retire or relocate that behavior and remove the semantic/tutorial cycle.
15. Retire resolved core-to-tutorial exceptions and prove neutrality.
16. Complete the HTML-output sink and trust-context audit.
17. Add the neutral context-specific encoder with adversarial tests.
18. Migrate code renderers away from the editor encoder.
19. Introduce an injected renderer theme reference or role binding.
20. Migrate the distribution application caller and retire the renderer leak.
21. Prove caller-complete reachability for the legacy public equation SDK.
22. Retire the legacy SDK if zero-production-caller evidence holds; otherwise
    stop for human disposition.
23. Update dashboard metadata, authority inventories, and tests to canonical
    APIs.
24. Run release verification, record before/after evidence, close the run, and
    make the follow-on tranche the durable next action.

Each slice is independently verified and committed. Focused checks run inside
the loop; typecheck, architecture, build, bundle, full tests, and Theseus
validation run at the boundaries appropriate to their risk.

## Stop Conditions

Stop when:

- work would affect visible choreography or require aesthetic judgment;
- an external consumer prevents safe SDK retirement;
- semantic IDs, frames, endpoints, URLs, or bundle ceilings change;
- HTML trust contexts cannot be proven equivalent;
- unrelated user work overlaps a required file;
- bundle/application work becomes necessary to close ownership; or
- a broad failure cannot be repaired inside the approved boundary.

## Follow-On Long Loop: Bundle And Application Isolation

The next long loop, in order, is:

1. generalized selected-experience bundle scenarios;
2. a typed immutable native-KaTeX feature-pack seam;
3. place-value closure repair and meaningful budget headroom;
4. Internal Studio production-entry isolation;
5. Public Web production-entry isolation;
6. development-only review-tool closure;
7. dashboard data-only startup projection;
8. algebra-pack attribution and conditional subdivision;
9. Vite helpers that do not eagerly import route implementations;
10. route-owned CSS splitting;
11. narrow semantic, runtime, renderer, authoring, and publication entrypoints;
    and
12. physical-package readiness assessment.

Physical `@kp/*` packages and SvelteKit remain deferred until plain HTML and a
second host prove the public boundaries.

## Done Contract

The run is complete when the global direction gate passes without the retired
exceptions, neutral core modules no longer import tutorial/editor/application
owners, the legacy SDK has a caller-complete disposition, focused and release
checks pass, current bundle ceilings hold, project memory names the follow-on
tranche, and the binary log-product visual checkpoint is restored as the
catalogue's active visual action.
