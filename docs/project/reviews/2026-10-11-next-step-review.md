## Concrete sequence and stopping rule

1. State the exemplar's learning objective: see expanded expressions as the
   same coefficients acting on an explicit ordered input family. Review the
   current visual candidate; preserve the coefficient grid and occurrence identity.
2. Make supported coefficients, input expressions, selections and annotations
   authorable without renderer, CSS or geometry edits. Parameterize only what
   the accepted exemplar and second caller require.
3. Author a linear system through the same collection/distribution mechanism.
   Preserve equations and right-hand sides; unknowns are not polynomial basis
   functions. Share presentation mechanisms without merging domain validators.
4. Publish one bounded authoring packet: two examples, supported cases, typed
   repair cases, static output, deterministic seek/reverse checks, and measured
   incremental authoring/browser costs. Record every renderer change required
   by the second caller; within the stated envelope, the target is zero.

Stop this milestone when both callers satisfy that contract. If the second
caller needs a second choreography implementation, diagnose the failed boundary
before expanding coverage. Preserve historical experiments but keep one adopted
implementation for the demonstrated mechanism.

Prepare prediction/reconstruction prompts during authoring. Actual reader
testing is still deferred by user direction; recommend a small formative test
when that deferral is explicitly revisited, not an implied new gate now.
Visual polish alone establishes no learning advantage.
