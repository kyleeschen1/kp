# Certified Equation Stage Layout Long-Loop Proposal

Date: 2026-07-27
Status: proposed; execution requires explicit user approval

## Objective

Repair the foldable distribution exemplar so its declared semantic rows are
actually measured, placed, fitted, and enforced before canonical glyph paint is
sampled. Wide and phone projections must remain centered, readable, unclipped,
and free of unrelated visible-paint overlap. After that geometry is stable,
complete the already queued factoring requirement: both distributed `x`
contributors must collapse simultaneously and opaquely into the extracted
factored `x`.

This loop closes one demonstrated generic invariant rather than adding another
renderer:

```text
semantic row intent
-> native group-envelope measurement
-> certified and applied stage layout
-> responsive fit and protected occupancy
-> canonical native-KaTeX renderer session
-> native settled DOM
```

## Why This Loop Is Current

The previous `x` baseline repair closed a paint-coordinate defect through
required measured-paint track and frame types. Human review now confirms that
the remaining crowding is different: `semantic-two-row-stage` is a typed
description and DOM attribute, but no runtime consumer applies its rows.
Responsive fitting unions settled single-coordinate-space endpoints and may
shrink below the nominal readability floor. Existing tests prove the policy
label, selected material-pair clearance, containment, and centering; they do
not prove that rows were applied or that all native and material paint remains
separate.

The ready Theseus action
`next-action.kp.bound-native-fan-in-motion-v0` remains valid but is downstream
of this layout repair. Its simultaneous opaque `x` fusion belongs after the
stage coordinate system is final.

## Canonical Exemplar And Acceptance

The sole visual exemplar is the existing foldable distribution reader, opened
through the Animation Library:

```text
3(x + 2) + 2(x - 1)
-> 3x + 6 + 2x - 2
-> (3x + 2x) + (6 - 2)
-> (3 + 2)x + (6 - 2)
-> 5x + 4
```

Review viewports are 1100x800 and 390x844 in expanded mode, with automatic,
collapsed, and pinned projections retained as conformance cases.

Promotion requires:

1. every declared row and semantic envelope resolves to measured native paint;
2. the applied layout carries the same measurement and coordinate-space
   revision consumed by the renderer session;
3. unrelated visible native/native, native/material, and material/material
   paint never intersects beyond an explicit semantic-contact tolerance;
4. row membership and the minimum measured gutter remain stable throughout a
   phase;
5. the fitted row stack and its material transit corridor remain centered and
   unclipped;
6. scale never falls below the declared readability floor; an unsatisfied
   layout selects deterministic stage, fold, or condense fallback;
7. direct seek, rewind, resize, and font readiness reproduce the same layout;
8. the fixed measured-paint `x` boundary and endpoint handoff do not regress;
9. both factoring `x` contributors form one simultaneous opaque fusion cohort;
10. no operation-specific coordinates, second renderer, lifecycle category,
    scheduler category, clock, or paint authority is introduced.

## Preservation Boundary

Preserve the immutable expression/evaluation tree, verified mathematics,
semantic lineage, existing motifs, fold truth, URLs, checkpoints, one runtime
clock, one canonical renderer-session path, native KaTeX accessibility and
settlement, the Animation Library host, Review capture, static/export truth,
and all approved solve-x, fraction, radical, and linear-equation behavior.

The layout planner may use existing semantic envelope membership and measured
native paint. It may not infer mathematical identity from glyph equality or
introduce distribution-specific pixel coordinates.

## Rollback Units

- `s01-s06`: diagnostic and proof-carrying layout contracts;
- `s07-s12`: pure layout, corridor, fit, and fallback planning;
- `s13-s18`: reader and compositor integration on the one exemplar;
- `s19-s23`: determinism, type closure, and simultaneous factoring fusion;
- `s24-s26`: human checkpoint, release verification, and closeout.

Each completed slice is an independently reversible commit with its exact
Theseus evidence. Existing user-owned roadmap, thread, exploration, and
portable-publication changes remain untouched.

## Verification Cadence

- **Focused inner loop:** changed-path unit/type checks and the smallest stable
  browser probe.
- **Boundary gates:** `npm run test:foldable-distribution`,
  `npm run visual:foldable-distribution`,
  `npm run test:canonical-equation-renderer`, and `npm run typecheck`.
- **Release gates:** `npm test`, `npm run build`,
  `npm run test:canonical-animation-construction`,
  `npm run test:animation-library-display`,
  `npm run visual:linear-equation`,
  `npm run check:reader-production`,
  `npm run check:reader-budgets`,
  `npm run check:dev-review-production`, and
  `theseus workspace validate`.
- `npm run check:canonical-animation-budgets` remains visible. Its existing
  optional Review-plus-glyph ceiling failure is not attributed to this loop
  unless the loop increases the isolated baseline; its repair is deferred.

## Stop Conditions

Stop immediately if:

- exact mathematics, semantic lineage, fold truth, accessibility, or native
  settlement changes;
- layout requires operation-specific coordinates, browser wrapping, glyph
  text inference, or persisted DOM geometry;
- compositor-core work exceeds generic occupancy consumption or introduces a
  new lifecycle, scheduler, route catalog, renderer, clock, or paint authority;
- any migrated exemplar regresses in typography, handoff, seek, rewind,
  responsive behavior, resources, or production closure;
- a type certificate can be produced without its runtime proof or can be
  consumed across measurement revisions;
- user-owned dirty files must be modified;
- the slice-24 visual checkpoint is not approved.

## Explicit Deferrals

The following do not fit this exemplar-bounded loop and should remain deferred
Theseus actions:

1. repository-wide canonical ownership/lifecycle type migration;
2. proof-carrying exact-checkpoint navigation across every reader;
3. nominal canonical-format promotion certificates replacing authorable
   evidence booleans;
4. context-safe branded HTML text, attribute, URL, and script-data boundaries
   plus consolidation of remaining local escape helpers;
5. the pre-existing optional Review-plus-glyph bundle ceiling repair.

These are recorded for later loops, but this proposal does not authorize their
implementation or move them ahead of visible animation-library expansion.
