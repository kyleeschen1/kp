# Equation Narrow-Core Overnight Reorder Proposal

Date: 2026-08-16
Status: proposed; requires explicit approval before execution

## Purpose

Reorder the approved equation-convergence program so deterministic architecture,
porting, extensibility, and test-economics work can run without waiting on the
binary log-product visual checkpoint. Preserve that candidate and its review
evidence, but do not promote its aesthetics or tune another caller overnight.

This proposal refines the execution order in
`2026-08-16-equation-iteration-architecture-next-step-review.md`; it does not
replace its extensibility law, migration scope, or cross-domain boundaries.

## Failure Being Corrected

The phrase “reuse function wrapping” was descriptive guidance, not executable
authority. The log-product transit session could therefore reproduce timing
and geometry manually without invoking the canonical function-wrap machinery.
That is why like parts did not automatically receive like motion.

The corrected boundary is:

```text
semantic operation
-> typed presentation recipe
-> typed motif invocation with semantic role bindings
-> registered motif compiler and shared profile
-> renderer-specific motif adapter over measured native geometry
-> sampled tracks on the shared clock
```

A caller binds semantic objects to roles such as `argument`,
`leading-enclosure`, `trailing-enclosure`, `operator`, and `connector`. It does
not import timing constants, calculate paths, or reproduce the motif. A
homomorphic-decomposition recipe composes shell release, material
redistribution, canonical function wrap, and relation resolution rather than
implementing wrapping internally.

## API Direction

The authoring surface should be equivalent to:

```ts
invokeMotif("motif.function-wrap.v1", {
  branches: [{
    argument: ref("target.left.argument.x"),
    leadingEnclosure: ref("target.left.log.open"),
    trailingEnclosure: ref("target.left.log.close"),
    operator: ref("target.left.log.operator")
  }]
})
```

The runtime resolves that typed invocation through immutable, explicitly
composed registries. The motif owns its phase grammar and default profile. The
Native KaTeX adapter owns measured outside-in enclosure geometry. Generated
literal-import dispatch keeps runtime execution exhaustive and tree-shakable.

Changing a defect or approved policy in `motif.function-wrap.v1` should update
all v1 callers. Subjective redesign must not silently rewrite every lesson: it
is introduced as a candidate profile or version, pressure-tested, and promoted
deliberately. Central authority therefore supplies leverage without making one
aesthetic experiment an uncontrolled global mutation.

## Preservation Rules

- No overnight slice may approve, tune, or promote the pending log-product
  visual candidate.
- Existing approved callers must retain semantic IDs, native endpoints,
  settled typography, sampled frames, direct seek, rewind, interruption,
  reduced motion, accessibility truth, and lazy-loading boundaries.
- Migration means changing authority and dispatch without changing visible
  choreography. If equivalence cannot be proved, leave that caller on its old
  path, record the exact gap, and continue with independent slices.
- Stop the run on semantic loss, deterministic-runtime drift, bundle-boundary
  regression, an unexplained global visual delta, or an edit to unrelated
  user-owned work.
- Equation recipes do not absorb graph, code, diagram, Canvas, WebGL, or 3D
  domain semantics.

## Deferred Human Work

Resume these only after the overnight refactor is reviewed:

1. judge the binary log-product outside-in wrapping aesthetics and timing;
2. if approved, pressure three-factor product and quotient before promoting a
   homomorphic-decomposition visual recipe;
3. tune any caller explicitly deferred for non-equivalent presentation;
4. run cross-browser visual certification for newly promoted motifs; and
5. resume product/layout work only under its separate evidence gate.

## Expected End State

- `function-wrap` is an executable typed motif invocation, not prose guidance;
- one motif definition and one adapter per renderer update every opted-in v1
  caller;
- recipes compose motifs instead of reimplementing them;
- adding an equation caller contributes data and bindings rather than editing
  core switches;
- runtime dispatch stays closed, auditable, and tree-shakable through generated
  literal imports;
- migrated families have no parallel authority or duplicate test owner; and
- visual questions remain explicitly pending rather than being silently
  approved by an overnight refactor.
