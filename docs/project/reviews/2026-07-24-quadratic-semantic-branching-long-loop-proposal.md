Date: 2026-07-24

## Why this loop is current

The semantic-animation convergence and semantic-presentation continuity
contracts are resolved, the Semantic Animation Workbench already carries one
planned-only quadratic identity, and the active product roadmap places
quadratic semantic branching next. The active plan revision still labels
semantic-animation convergence active, so the first slice must reconcile that
durable authority before implementation.

This proposal replaces the four coarse quadratic slices skipped from the
Workbench loop with one exemplar-first, lesson-owned implementation contract.
It does not revive integral, vector, matrix, arithmetic, or cross-domain work.

## Objective

Build one canonical, lesson-owned animation for
`x^2 - 5x + 6 = 0` that:

- exposes completing-the-square and quadratic-formula solution methods as
  explicit semantic paths;
- branches lawfully at `±` into stable roots `2` and `3`;
- reunites both methods into one exact solution set;
- synchronizes those root identities with the parabola's graph intersections;
- preserves exact native KaTeX endpoints, direct seek, rewind, responsive
  attention, accessibility, and the shared runtime clock; and
- promotes the existing Workbench item from planned-only to playable only
  after human approval of the exemplar.

## Canonical reference and acceptance criteria

The canonical reference is the accepted solve-x reader for measured equation
motion, responsive attention, native KaTeX settlement, direct seek, and rewind.
The derivative secant-to-tangent exemplar is the reference for synchronizing
equation and graph evidence on one clock. The quadratic animation must remain a
new lesson-owned presentation rather than copying either exemplar's domain
choreography.

The exemplar passes human review only when:

1. both methods visibly begin from the same equation and end in the same exact
   solution set;
2. the `+` and `-` branches remain distinguishable, inspectable, and stable
   through rewind;
3. symbolic roots and graph intersections share explicit semantic identities;
4. no renderer invents algebra, correspondence, timing, or solution evidence;
5. wide and narrow layouts remain readable without horizontal overflow or
   attention competition;
6. reduced, static, high-contrast, keyboard, and spoken projections preserve
   the same causal explanation; and
7. native KaTeX owns every settled equation state with no cross-renderer
   typography workaround.

## Preservation boundary

- Preserve every accepted solve-x, distribution, fraction, radical,
  derivative, reader, Workbench, and review behavior.
- Preserve existing animation IDs, routes, URL state, semantic documents,
  clocks, native KaTeX authority, accessibility, and append-only review
  history.
- Preserve `animation.algebra.quadratic.solution-branching` as the one canonical
  identity; it remains planned-only until the publication slice.
- Preserve the radical handoff as an animation-specific known residual and
  promotion blocker. Do not reuse or generalize its WebGL material layer.
- Keep unrelated user-authored roadmap, thread, and design changes outside
  every commit.

## Allowed work

- Quadratic semantic fixtures, exact rational/discriminant laws, structured
  rewrite authorities, solution-method paths, `±` branching, root-set reunion,
  correspondence, provenance, and verification.
- One lesson-owned equation/graph animation, responsive reader projection,
  Workbench publication, stable visual tooling, focused tests, and Theseus
  evidence.
- Extraction of a shared contract only after the human-approved quadratic
  exemplar proves it as a second consumer alongside an accepted reference.

## Disallowed work

- Integral, vector, matrix, arithmetic, rational-expression, trigonometry,
  geometry, probability, data, programming, economics, or physics
  implementation.
- General quadratic curriculum, arbitrary polynomial solving, a CAS, numerical
  root approximation, or unverified provider output.
- LLM-authored math text, DOM, CSS, pixels, geometry, timing, keyframes, or
  presentation policy.
- Broad WebGL, radical, KaTeX, renderer, route, review-storage, or dynamic
  package-loading redesign.
- Family-wide visual promotion before the quadratic human checkpoint.

## Human checkpoint and post-approval promotion

Slice 20 is mandatory. Review covers the complete exemplar, not isolated
screenshots: method selection, algebraic causality, `±` branching, root
reunion, graph correspondence, wide/narrow attention, direct seek, and rewind.

Approval promotes only:

- the one quadratic animation;
- its lesson-owned Workbench representation; and
- contracts demonstrated by at least one accepted prior consumer and the
  quadratic exemplar.

Rejection or revision rolls back only the quadratic presentation profile,
lesson surface, graph binding, choreography, visual tooling, and their tests.
The exact quadratic semantic fixture and independently verified math laws may
remain if the reviewer rejects presentation but accepts semantic correctness.

## Verification cadence

- Inspect `npm run verify:impact -- --path <changed-path>` before using
  `--run`.
- Run the smallest deterministic focused checks within semantic slices.
- Add typecheck and Theseus validation at standard boundaries.
- Run shared architecture, renderer, reader, Workbench, browser, and build
  checks at broad boundaries.
- Reuse committed `npm run visual:quadratic-branching` throughout the loop.
- Run full release gates at slice 20 and slice 24.
- Commit every completed slice with its Theseus evidence.
- Use brief tracked context per slice and working context only when the brief
  packet is insufficient.

## Contract stop conditions

- **H1 HUMAN-EXEMPLAR:** stop after slice 20 until the user reviews the
  quadratic exemplar.
- **H2 MATH:** stop on any unverified rewrite, inexact canonical result,
  fabricated provenance, or need for unchecked CAS behavior.
- **H3 IDENTITY:** stop on ambiguous method, branch, root, solution-set, or
  equation/graph identity.
- **H4 PRESERVATION:** stop on accepted semantic, motion, route, URL, review,
  accessibility, native-settlement, seek, rewind, or visual-baseline drift.
- **H5 OWNERSHIP:** stop if semantic code must own renderer resources or a
  renderer must invent semantic truth, timing authority, or correspondence.
- **H6 RADICAL-ISOLATION:** stop if quadratic work must reuse or broaden the
  animation-specific radical WebGL material path.
- **H7 SCOPE:** stop before entering another roadmap domain, general
  polynomial solving, course-scale curriculum, dynamic loading, or broad
  renderer redesign.
- **H8 USER-OVERLAP:** stop if a required change cannot be separated from
  unrelated user-authored worktree changes.
- **H9 VERIFICATION:** stop if a required focused, boundary, release, visual,
  or workspace gate fails without a bounded in-scope repair.
- **H10 AUTHORITY:** stop if destructive work, external mutation, or new
  authority exceeds the approved contract.

## Done contract

The loop is complete only when the canonical quadratic animation is
mathematically exact, lesson-owned, direct-seekable, exactly reversible,
responsive, accessible, synchronized with graph roots, human-approved,
playable in the Workbench under its existing identity, covered by stable
visual and browser gates, and closed with an honest promotion audit and release
record. No deferred roadmap phase is authorized by this closeout.

## Explicit deferrals

- Integral accumulation, vector projection, matrix linear maps, and all exact
  arithmetic loops.
- General quadratic or polynomial family generation.
- Fractional-power/radical generalization and repair of the known `1/2`
  handoff residual.
- Live LLM prompt APIs, course generation, assessment, media encoding, and
  dynamic package loading.
