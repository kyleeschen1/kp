# Proposed path after engineering discipline

Discussion recommendation, not implementation authority. The completed native
preparation run and earlier engineering portfolio remain closed. The roadmap's
remaining clone/alignment investigation is a bounded engineering option, not an
indefinite prerequisite for authoring work.

Evidence: [architecture agenda](../2026-10-21-authoring-architecture-delivery.md),
[authoring boundaries](2026-10-21-authoring-boundaries.md),
[engineering discipline](2026-10-21-engineering-discipline.md),
[native preparation](2026-10-21-native-preparation.md).

The next strategic uncertainty is whether a new useful explanation is cheap to
author through existing public boundaries. Correctness, smaller dependency
closures and preserved motion are demonstrated; broad authoring ease and learner
benefit are not. Another round of maintenance alone cannot resolve those questions.

| Candidate | Authoring benefit | Reliability | Reuse evidence | Risk | Recommendation |
| --- | --- | --- | --- | --- | --- |
| Further native clone/alignment repair | Indirect | High if measured | Existing native owner | Medium geometry risk | Time-box; stop if no bounded repair |
| Source-only authoring transfer audit | Direct | Tests existing contracts | Meaningfully different caller | Low with existing presentation | Lead next delivery |
| Universal composition API | Unproven | Unknown | Insufficient | High | Defer |
| More Gaussian/content variants | Limited strategic learning | Established machinery | Mostly repetition | Low technical, high opportunity cost | Defer |
| New flagship publication | Potentially high | Needs editorial review | Must first prove authoring transfer | Medium/high | Follow authoring proof |

Proposed sequence:

1. Pressure the concise authoring boundary with one short explanation selected
   for a specific learner question. First inspect supported operations; do not
   assume a proposed mathematical example is already expressible. Prefer a
   familiar calculus/algebra question the user can judge, with a genuinely
   different structure from a numeric substitution. Use an accepted host and
   existing motif vocabulary. Record source size, engine edits, unsupported
   operations, diagnostics, reader payload and first/warm interaction cost.
2. Repair only friction exposed by that caller. Require a meaningful source
   variation to work without engine changes. Preserve checked operations,
   correspondence, deterministic seek/reverse and native endpoints. An honest
   typed gap is preferable to an invented generic animation. Do not require
   mathematics, narration and presentation to be one object or one language.
3. Demonstrate practical composition: reuse mathematical referents in a second
   explanation or presentation, vary emphasis and granularity, and confirm
   that changes propagate without copied renderer implementations. Reuse
   equation rails and top-text focus cards where already supported; any new
   visual treatment retains its exemplar review gate.
4. Establish a bounded author workflow: examples, check, preview, readable
   errors, inspectable semantic provenance and predictable publication output.
   Evaluate fresh author/LLM tasks by valid source, repairs and engine edits,
   not merely generated code or test count. Start from the existing CLI/editor.
5. Make one exceptional reference publication once that workflow supports it.
   It demonstrates the medium and tests the tools; it does not commit KP to a
   competitive content library. Later learner feedback must separately test
   whether the explanations improve understanding.

During limited user availability, source-boundary audits, deterministic failure
cases, measured repairs and author-task evaluation can proceed under approved
scope. Learner-context selection and visual/pedagogical quality remain human
judgments. Keep performance a maintained constraint, not the sole success metric.

No roadmap priority or old visual gate is changed by this proposal. Gaussian
elimination remains frozen; the unaccepted calculus card is not promoted. No
new run is created. Approval would be needed for a concrete new delivery scope.
