# Compositor extension participation — proposed long loop

Date: 2026-09-10. Status: PROPOSED, awaiting explicit scope approval.
Pending target: `next-action.kp.compositor-extension-occupancy`.
No successor execution contract is activated by this document.

## Recommendation and product value

Before another specialized mathematics motif, close the extension-participation
gap exposed by M1b. An author should be able to reuse a canonical operation without
wondering whether its extra painted material bypasses shared scene inspection.
This is a bounded integration migration, not a replacement animation engine or
another attempt to eliminate every overlap. It implements the accepted planning
obligation in `../threads/compositor-extension-occupancy-follow-up.md`.

| Candidate | Authoring value | Reliability / reuse | Risk | Decision |
| --- | --- | --- | --- | --- |
| Require complete extension participation at the existing compositor seam | Indirect but necessary for dependable motif reuse | Repairs one demonstrated shared gap | Tight source budget; runtime coverage must be earned | Next, bounded as below |
| Add another specialized mathematics family immediately | More visible mathematical coverage | Could repeat incomplete scene participation | Multiplies migration and validation debt | After this boundary |
| Build universal motion planning or a CAS | Speculative breadth | No bounded second-caller proof | High complexity and scope | Do not pursue |

The visible M1b result already works. The purpose here is to make that path harder
to bypass as mathematical coverage grows, not to redesign its accepted appearance.
Learning efficacy and broad LaTeX-to-animation coverage remain separate questions.

## Canonical boundary and evidence

Reference artifact: the accepted composed factoring/evaluation source in
`src/authoring/examples/composed-algebra-primary.json`, with the retained
`composed-algebra-product.json` as opposite-orientation compound pressure.
Host: the existing port-8000 application at
`/experiments/reusable-reasoning/?example=composed-algebra`.
Semantic authority: verified source and operation-owned authenticated bindings.
Renderer: the canonical native KaTeX scene compositor; timing: the shared semantic
clock. No host-owned geometry, alternative renderer or independent timing path.

The source-backed gap is specific: `native-katex-scene-compositor.ts` accepts a
`supplementalMaterialOwners` callback at renderer construction, while the
protected-plan compilation separately invokes factoring's `inspectTransit`.
Successor synthesis is assembled through another owner. Factoring's local audit
is useful but is not a required, final assembled-scene audit for every extension.
Inspect these seams, `native-katex-factoring-binding-types.ts`,
`native-katex-factoring-choreography.ts`, `native-katex-successor-synthesis.ts`
and `equation-material-layer-types.ts` before selecting an implementation shape.
Inventory actual realized paint and ownership, not just registry entries.

## Intended contract, not a preselected framework

Each extension contribution couples its actual material sampler and participant
identity to measured occupancy in the scene's coordinate frame. Assembly must
make missing participation unrepresentable through supported TypeScript APIs.
Operation owners remain open registrations; no central operation-name ladder.
The design should remove the independent unchecked callback path, not add an
optional inspection flag beside it. Use only abstractions demonstrated by the
factoring exemplar and one materially different existing mechanism.

The final assembled scene, after partitioning, routing and contributions, owns
inspection. Issued evidence binds the actual sampler, participant set, measured
geometry/font revision and coordinate frame. Runtime authentication, invalidation
and cache-reuse checks reject copied, stale or incomplete evidence. Types ensure
participation and authority boundaries; executed paint tests establish geometric
and lifecycle facts. Neither establishes aesthetic quality.

Preserve `../principles/motif-composition-contracts.md`: required fusion contact
is explicit; transit contact is diagnostic under a motif-owned policy. Endpoint
readability, exclusive ownership and compatible handoffs remain hard invariants.
Never enlarge arcs, insert detours, fade continuants, invent notation offsets or
exempt whole mechanisms merely to remove rectangle intersections. Inspection
coverage must not be called collision freedom. Finite samples are not a
continuous-time proof; evaluate swept bounds or bounded subdivision separately,
and record an honest unsupported assurance boundary if they are not justified.

## Cost and execution agreement

The current accounted 28-module renderer closure is **514,955 / 515,000 bytes**.
Only 45 bytes remain. The first implementation decision is therefore costed
consolidation, not permission to add a new framework. Measure the complete closure
and every real inference consumer. Moving code outside the measured file list is
not a repair. If the bounded migration cannot fit after useful consolidation,
stop with a measured non-TypeScript policy proposal before exceeding the gate.
Approval of this plan would not itself approve that amendment. TypeScript cost
repairs retain the standing measured, complete-consumer policy. Runtime, reader,
source and production-isolation gates otherwise remain fixed.

On approval, materialize one Theseus contract from this proposal with the exact
24 slices below; Theseus then owns order, status and evidence. One scoped commit
and context receipt per slice. F = focused law/type tests and diff checks;
S adds full affected types, architecture and Theseus validation; V adds a real
canonical Chromium compositor canary. Broad browser/release checks happen at
promotion, not during speculative visual discovery. Planning allowance: 6–12
active hours, not a completion-time promise. No subagents or external model calls.

Routine nonvisual checks continue automatically. The accepted M1b appearance is
the exemplar checkpoint: unchanged preservation evidence does not require a
second human approval. If the implementation requires a materially different
treatment, stop on the reversible exemplar and present it before promotion.
Stop also for missing authority, unsafe action, required unavailable proof,
budget violation, material scope expansion or user pause. No merge, deployment,
new subject family, universal compositor, host redesign or automatic successor.

## Preservation, rollback and completion

Preserve semantic models, authoring sources and repair gaps, native typography,
existing motif timing and character, shared controls/clocks, readings and revision
contracts. Do not touch unrelated graph, diagram, code or WebGL ownership.
The smallest reversible visual unit is the factoring contribution adapter plus
its assembly wiring; an optional parallel authority path is not an acceptable
rollback strategy. Retire the old path when migrating each owner, and preserve
the semantic safeguards if a visual adapter must be reverted for review.

Done means every inventoried in-scope extension participates through the required
final-scene seam; forgery/omission/staleness regressions fail closed; two materially
different mechanisms traverse the real compositor; accepted visuals and fixed
gates pass; assurance limits are stated. No catalogue-wide geometric certification
is implied merely by mandatory participation. If the inventory exposes another
materially distinct risk, execute a bounded representative or retain it as an
explicit gap rather than claiming certification.

After this migration, return to the accepted mathematical authoring horizon:
choose a bounded assumptions/branches or symbolic–geometric example using the
same source-to-canonical-presentation pipeline, measured by new author capability
and marginal glue. Do not turn ongoing compositor work into an indefinite
prerequisite for all product progress. The earlier horizon remains ordered
context; this proposal does not supersede it or restart completed R1–R4B/M1a/M1b.
