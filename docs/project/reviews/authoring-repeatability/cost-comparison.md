# Fixed-case cost comparison

The one repair changes the fraction publication helper (three added lines and
one replaced line), not a domain checker or runtime renderer. It restores native
accessible mathematics for both frozen fraction proposals and all four existing
hosts. All ten owner reports are byte-for-byte equivalent as parsed data before
and after. Checked outcomes remain five; passing applied fixture previews rise
from zero to two. The three checked mechanics/code proposals remain reference-only.

## Authoring and engineering work

Every frozen case has zero input corrections and zero per-case adapter or engine
edits. That does **not** mean zero engineering cost. Shared work includes the
manifest, truthful outcome records, runner, source-application browser harness,
two adjacent Article documents, the publication repair and its regression tests.
Two test-driver waits were needed so resize/width-restoration checks aim after
observer layout; they do not change product geometry or loosen tolerances.
Editorial code variants were inspected but do not prove clearer teaching.

Engineering minutes were not measured reliably and remain `null`, not zero.
The current agent already knew the implementation; this is not a blind LLM trial.
No repeated authoring-time sample or cost-saving estimate is justified. The two
algebra inputs fail on missing namespaced state IDs; their intended positive and
presentation-boundary checks remain unexercised. Those inputs are retained.

Checker timings in retained JSON range from 13.8–547.7 ms in baseline and
0.15–581.1 ms in rerun. Baseline used several separate processes; rerun used one
process and warmed owners. These are incomparable cold/warm observations, not a
speedup, interaction latency or authoring time. No runtime implementation changed,
so no new latency optimization is claimed.

Each closure contains 114 initial and 137 activated files; additional activation
is 42,582 compressed bytes. Fonts, images, HTTP overhead and parse/paint costs are
excluded. The two trial fixtures use this same publication compiler and runtime
in a test response; they are not additional production entrypoints.

The main host's recorded [pre-trial measurement](../2026-09-22-consolidation-closeout.md)
was 415,444 / 458,026 JS/CSS gzip and 4,368 HTML gzip. Its reader closure is
unchanged; HTML grows by 190 gzip bytes (4.35%) for native accessible mathematics.
Individual pre-repair HTML measurements for the other three hosts were not
retained, so no per-host deltas are asserted for them. All current consumers are
included above. No ceiling, baseline or cost policy needed amendment in this
trial. The substantial existing fraction runtime remains a separate attributed
optimization candidate, not an excuse to omit semantic output.

The useful result is bounded reuse of two changed numeric chains through the
same host and one shared preservation repair. It supports trying a small coherent
argument within that demonstrated path; it does not establish cheap generation
across subjects, arbitrary algebra inference or learner effectiveness.
