# What recent loops bought, and the next product threshold

Date: 2026-09-10. Status: independent assessment and recommendation, not execution
approval or a roadmap pivot. This is not a Theseus-generated report card.
The current roadmap and deferred extension-participation action remain unchanged.

## Executive judgment

- The recent loops bought a more trustworthy authoring-to-presentation path, not
  merely more animations. Ordinary authored mathematics can reach the complete
  canonical operation presentation without the host inventing motion.
- Coherent revision handling and multiple projections are meaningful reusable
  infrastructure: failed edits do not replace the displayed lesson, and readings,
  prompts and exports can remain attached to the same verified source.
- Source-only second callers are the strongest reuse evidence. They demonstrate
  parameter/shape reuse inside a bounded supported task, not cheap expansion to
  arbitrary new mathematical operations.
- The project has stronger engineering foundations than author-facing product
  completeness. It is a promising semantic medium with functioning integrated
  slices, not yet a general lower-undergraduate mathematical authoring tool.
- Keep the required bounded compositor repair, then insist on an unfamiliar real
  author task and measured authoring leverage. Do not let scene certification
  become an indefinite prerequisite for content or product progress.

## What the last few loops bought

**R4A: discoverability and honest handoffs.** One checking command delegates to
domain-owned validators, examples and located diagnostics. It distinguishes
checking from preview Apply, extraction and publication. The current registry
requires both lazy handlers for each supported task. A common workflow does not
erase equation, probability, code or graph semantics.

**R4B: authorable explanations, not just parameterized demonstrations.** Bounded
Bayes sources can supply passages, readings and prompts around verified facts.
The spam and urn explanations reuse shared domain-local assembly without a new
renderer. Free prose is still editorial; parameter changes do not automatically
prove a rewritten interpretation correct.

**M1a: trustworthy access to the old factoring investment.** Ordinary bounded
LaTeX and exact ordered factoring evidence now lead to the canonical factoring
presentation. A requested operation name is not mathematical proof, and a
compiled candidate is not a verified renderable artifact. The result is stronger
than recognizing that the catalogue contains a factoring animation.

**M1b: actual mixed-operation composition.** A whole compound factor survives
factoring, coefficient evaluation uses the canonical ink mechanism, and two
operations share exact intermediate identity and a deterministic three-stop
timeline. The product-shaped opposite-orientation source reuses those owners.
One revision reaches the card, full/compact readings, practice, exact return and
static edition. Parser, collapsed-viewport, display-math and introduced-glyph
repairs address shared defect classes, not only a single screenshot.

The important distinction is between **new content within a supported task**
(now demonstrated source-only) and **a new semantic/presentation task** (still
potentially expensive). The current composed presentation explicitly contains
the tuple factoring/evaluation and three checkpoints. A more general asset
composition helper exists, but that does not make arbitrary authored chains
supported. This is a useful integration proof, not generality by declaration.

## Main architectural judgment

Keep the separation between semantic truth, pedagogical selection, motion and
rendering. Keep domain owners distinct; “one pipeline” should mean mandatory
correct ownership and canonical presentation within each domain, not forcing
probability, code, graphs and equations through one mathematical schema.

The capability boundary is substantially better: source is not proof, proof is
not prepared presentation, and a prepared presentation is not automatically a
published revision. These distinctions make future human/LLM collaboration safer.
However, branded types cannot establish visual smoothness, geometric clearance,
editorial accuracy or comprehension. Those require different evidence.

The proposed extension repair addresses a demonstrated hole: an independently
supplied `supplementalMaterialOwners` callback can coexist with separately
invoked factoring transit inspection. Require final-scene participation, bind
evidence to actual sampler/participants/measurement and reject stale authority.
Do not convert this into optimal routing, universal collision freedom or a new
motion engine. Intersections can be permitted; ownership and endpoints cannot
be silently wrong. Two differently structured examples of one factoring task
are useful pressure, but a different paint/ownership mechanism is needed for
the broader extension contract.

## Recommended ordering

### Immediate: finish one reliability seam, with a firm endpoint

Retain the pending 24-slice compositor-extension proposal's scope: participation,
current evidence, a different existing mechanism and preserved visuals. Treat
its slice count as execution bookkeeping, not product value. Do not add aesthetic
optimization or broad subject expansion to make the run feel substantial.

The source closure is 514,955 / 515,000 bytes. That is a policy constraint, not
evidence that 46 additional bytes make the design bad. First seek useful
consolidation; do not compress readable code, hide dependencies or contort module
boundaries to game the metric. If a small clear design genuinely needs more
budget, present a measured explicit amendment. Do not silently raise it. Keep
source-size, TypeScript inference, shipped bytes and interaction latency separate.

### Next tranche: prove useful authoring with the current machinery

Use a fresh-context author/LLM task based on a real explanation the user wants,
with only the documented source packet and checker. External model calls remain
separately permission-bound. Start inside supported mathematical scope so the
experiment measures authoring rather than simultaneously inventing a new motif.

Measure first valid draft, repair attempts, elapsed author effort, files touched,
runtime/renderer edits, specialist intervention and whether the intended revision
reaches every promised output. Use unfamiliar in-scope variants and at least one
out-of-scope request; the latter must return an honest repair, not fake success.
Proposed acceptance target: five held-out supported content variants need no
renderer changes, invalid mathematics never becomes verified output, and every
published projection agrees on revision. A small trial is diagnostic, not a
statistically reliable success-rate estimate.

Improve the friction that appears. The likely useful author-facing unit is a
step editor exposing mathematics, the reason for a step, explanation and
checkpoint grouping over the existing source/session authority. Raw JSON remains
inspectable/exportable; the editor must not become a second semantic store.
Unsupported capability and last-valid preview state should be explicit. Separate
semantic deductions from chosen pedagogical beats: “every derivation state is a
card” is not the desired universal authoring rule.

This recommendation does not make external educator discovery a prerequisite for
architecture work. It uses authoring itself as the next engineering acceptance
test, consistent with the user's priority.

### Then: earn general composition before broad subject coverage

Select one longer, useful deduction using already-supported operation owners.
Measure which source/proof/binding boundary prevents it from composing. Generalize
only that boundary: ordered verified steps, exact adjacency and an independently
chosen pedagogical grouping, with typed unsupported gaps. No universal CAS or
reconstruction of motion from endpoint glyph similarity.

After that, take one assumptions-sensitive case and one symbolic–geometric
case. A candidate assumptions lesson is cancellation in
`(x^2-9)/(x-3) = x+3` with `x != 3`; this is proposed future scope, not a claim
that the current authoring task supports powers, fractions or cancellation.
Its value is preserving the restriction in the whole argument and every
extracted prompt. Choose a geometric caller using an existing domain owner, not
a newly invented universal renderer or a silently reactivated tabled asset.

### Later: expand by reusable mechanisms and validate learning

Treat the algebra-through-lower-undergraduate horizon as an integration matrix:
notation, semantic law, assumptions, canonical motion, authoring, extraction and
publication are separate readiness dimensions. Existing catalogue animations
may cover a dimension without completing the authoring workflow. Do not infer
a coverage percentage from eight task IDs or thousands of tests.

Use small learner observations on an authored lesson: can someone predict the
next step, explain the invariant and transfer it to a changed problem without
the animation? This can inform authoring choices without turning into a broad
research programme or claiming efficacy from a tiny sample. Scheduling/accounts,
curriculum scale, full public editor and a framework rewrite remain deferred.

For subsequent plans, state author-visible outcome and which old plumbing goes
away before listing infrastructure slices. Prefer one combined visual checkpoint
when treatment changes, not repeated approval of unchanged behavior. Keep cheap
semantic/type/lifecycle checks early and full release matrices at promotion.
Judge leverage by specialist-free new content and maintained invariants, not
commits, tests or completed loop count alone.
