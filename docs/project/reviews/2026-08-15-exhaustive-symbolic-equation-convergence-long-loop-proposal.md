# Exhaustive Symbolic-Equation Convergence Long-Loop Proposal

Date: 2026-08-15
Status: proposed; awaiting explicit human approval
Mode: Theseus long
Proposed target: `next-action.kp.exhaustive-symbolic-equation-convergence-v0`

Maximum slices: 30

## Objective

Establish one canonical semantic-motion compiler for supported symbolic
equations, validate it with the three approved pressure callers and one new
log-product animation, then migrate every current equation-surface asset to a
canonical, adapter-backed, static-only, unsupported, or retired disposition.

The loop should eliminate competing equation-animation authority paths while
preserving reviewed choreography and keeping graphs, code, diagrams, Canvas,
WebGL, Svelte, and layout outside equation-compiler authority.

## Why This Loop Is Current

The quotient, distribution, and cancellation checkpoints promoted seven
operation-independent compiler requirements. Leaving the remaining equation
assets on historical paths would preserve the exact ambiguity that caused
missing trajectories, false identity, premature retirement, endpoint jumps,
and repeated composition bugs. The current equation domain is finite—24
catalogue surfaces—and mature enough for a bounded exhaustive cutover.

This is migration and compatibility work across semantic, animation, reader,
renderer, catalogue, generated-authoring, testing, bundle, and architecture
boundaries. Long mode is required because the work spans 30 independently
verifiable rollback units, includes a new visual exemplar, and has a mandatory
human checkpoint before generalization.

Expected elapsed agent work is roughly 25–45 hours across one or more sessions,
plus human review time at the clean-path and final catalogue checkpoints.

## Preservation Boundary

Preserve exact semantic endpoints, IDs, URLs, lazy loading, accessibility,
direct seek and rewind, reduced motion, reviewed paths and pacing, native KaTeX
settlement, exclusive paint ownership, catalogue selection, bundle isolation,
and all non-equation runtime/renderer behavior.

The clean-path log-product caller is the only intentionally new choreography.
Every migrated existing asset must be behavior-preserving unless a separate
human checkpoint explicitly approves a change.

## Verification Cadence

- **Focused:** pure types, validators, inventory, semantic composition,
  diagnostics, or one caller's exact tests.
- **Standard:** focused checks plus relevant architecture gates, cached/full
  typecheck as appropriate, and `theseus workspace validate`.
- **Broad:** touched subsystem suites, one-worker Chromium, deterministic
  contact sheets, bundle boundary, production build, and full typecheck.
- Inner loops use impact-selected tests. Broad browser/build checks run only at
  architecture boundaries, visual promotion, migration-wave boundaries, and
  release to avoid the previously observed workstation load problem.
- Commit after every verified slice. Stage exact paths and preserve unrelated
  user changes.

## Human Checkpoints

### Clean-path checkpoint after s25

Review `ln(xy) -> ln(x) + ln(y)` before any migration wave. Promotion requires:

- persistent semantic identity for `x` and `y`;
- explicit derived operator applications rather than duplicated identity;
- causal enclosure release and connector introduction;
- no final-frame snap, premature fade, local clock, or renderer fallback;
- exact native endpoints, direct seek, reverse history, and reduced motion;
- a diff dominated by semantic states, bindings, and recipe selection rather
  than new renderer/runtime machinery.

Rollback unit: s24–s25 only. The canonical compiler and three approved adapters
remain independently reviewable if the new choreography is rejected.

### Final catalogue checkpoint after s30

Review a deterministic contact sheet and migration report covering every
equation disposition. No existing asset may have an unexplained visual change.

## Contract Stop Conditions

Stop immediately when:

- the inventory cannot account for every equation surface and authority path;
- a migration would overwrite the user's economics or unrelated dirty files;
- semantic identity or provenance must be inferred from glyph equality, DOM,
  layout, or renderer measurements;
- a supported caller requires a new clock, scheduler, host lifecycle, or
  equation-specific renderer branch rather than a capability recipe;
- direct seek, interruption, rewind, reduced motion, native settlement,
  accessibility, or exclusive paint ownership cannot be proven;
- an approved animation changes visually without a separately authorized
  checkpoint;
- the log-product checkpoint is awaiting or fails human review;
- a proposed shared abstraction is evidenced by only one caller;
- migration would force graph, code, diagram, Canvas, WebGL, or 3D semantics
  through equation-specific types;
- deletion lacks exact production and conformance reachability evidence;
- bundle or active-frame regression cannot be attributed and bounded; or
- the approved 30-slice envelope would need to broaden.

## Done Contract

The run is complete only when:

1. all current equation surfaces have one generated, honest disposition;
2. every supported moving equation enters through one compiler front door;
3. the seven promoted invariants are enforced before recipe resolution;
4. composition preserves semantic identity across operation boundaries;
5. no supported equation caller owns a raw motif, private clock, local timing
   table, renderer inference, or silent fallback;
6. all equation compatibility paths are retired or adapter-backed with a named
   remaining caller and retirement condition;
7. the governed LLM path reaches only the canonical compiler and fails closed;
8. the log-product caller demonstrates lower marginal renderer/runtime cost;
9. approved assets retain their semantic and visual behavior; and
10. focused, browser, architecture, type, bundle, build, accessibility,
    deterministic, visual, and Theseus release evidence passes.
