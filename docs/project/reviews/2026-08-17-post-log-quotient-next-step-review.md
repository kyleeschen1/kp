## Near-Term Sequence

### 1. Promote only the proven crossover

Run one bounded implementation loop that:

- names the shared renderer-neutral phases: source-shell release, continuant
  transport, target-structure reception, and derived-syntax resolution;
- registers product and quotient against one nominal capability or recipe;
- preserves product and quotient timing, geometry, cardinality, and optical
  profiles as local policy;
- exposes the same capability through the governed authoring and LLM-visible
  catalogue;
- proves that neither caller adds a clock, renderer, core switch branch, or
  caller-authored geometry; and
- removes duplicated production wiring only where exact reachability proves a
  replacement.

This should be an architecture-preserving change with no intended visual
delta. Stop if a shared abstraction requires either approved animation to
change its choreography.

### 2. Measure the authoring payoff

After the crossover lands, run a small fixed generation benchmark: one product
decomposition and one quotient fusion request should select the correct motif,
bind semantic roles, and reach focused conformance without editing a core
dispatcher or supplying geometry. Record files touched, repair count, focused
test duration, and time to reviewable capture.

### 3. Add one new cross-representation exemplar

Select function translation/reflection/stretch/compression as the next
catalogue artifact. Preserve one function and its salient points across
symbolic and Graph2D representations. Perfect one transformation and stop at a
human checkpoint before extracting a family or adding lesson layout.

## Medium-Term Direction

1. Use two or three new exemplars to prove that the catalogue is becoming
   cheaper to extend, not merely more abstract.
2. Improve the Internal Studio only where real authoring friction appears:
   semantic-ID completion, motif selection diagnostics, typed repair gaps, and
   exact-state review are higher value than more layout controls.
3. Keep a compact, curated portfolio across equation, graph, code, and Scheme;
   retire only exact redundancy and diagnostic rows whose evidence has a
   replacement.
4. Put the best artifact in front of tutors or educators and collect evidence
   about conceptual value, confusion, reuse, and willingness to send it to a
   learner.

## Long-Term Direction

The long-term product sequence remains:

1. **Reusable semantic artifacts:** one object, identity, transformation, and
   deterministic state can appear in prose, notation, diagrams, code, prompts,
   and review cues.
2. **A small public proof:** mission page, two or three excellent explanations,
   stable links, and one portable embed—not a comprehensive curriculum.
3. **Proof-memory behavior:** prediction, reconstruction, delayed callback,
   variation, and compression into reusable cues.
4. **Narrow semantic tutoring:** an LLM operates on selected objects and typed
   actions; KP retains the durable semantic world.
5. **Application boundary:** Internal Studio and Public Web may adopt
   SvelteKit while animation assets, clocks, frames, renderers, and publication
   contracts remain framework-neutral.
6. **Curriculum and SRS scale:** only after repeated artifacts and real users
   demonstrate that the medium produces durable understanding worth returning
   to.

## Strategic Guardrail

The largest remaining uncertainty is product value and attention choreography,
not whether KP can animate symbols correctly. Finish the narrow crossover,
then bias work toward observable learning value and external feedback. Do not
make another architecture tranche the default response to design uncertainty.
