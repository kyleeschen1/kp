# TypeScript And Python Generation Frontends Closeout

Status: complete
Completed: 2026-08-21
Run contract: `run-contract.kp.typescript-python-generation-frontends-v2`

## Outcome

KP can now accept a bounded before/after extract-helper request in TypeScript
or Python, prove the language-specific transformation, bind persistent semantic
roles, and return a governed semantic plan. The Transformation Coverage ledger
derives both capabilities as `Direct` from exact evidence rather than from the
existence of their approved animations.

The implementation preserves language ownership. TypeScript uses its compiler
frontend; Python uses its standard-library AST frontend. Each language owns
syntax, role recognition, legality, binding, diagnostics, and its adversarial
corpus. They share only the immutable refactor request envelope, extract-helper
causal relations, discovery vocabulary, orchestration result, and evidence
projection.

## Safety Boundary

- No source is executed.
- Compiler and AST work remains build-time-only and outside browser bundles.
- Only the bounded extract-helper operation is accepted.
- Exact approved source revisions reuse the existing artifact and canonical
  timeline, clock, and paint authority.
- A valid noncanonical revision returns a semantic plan only. If an animation
  artifact is requested, KP returns `code-generation.artifact-unavailable`
  instead of inventing presentation.
- Unsupported syntax, unsafe captures, ambiguous duplicates, changed behavior,
  and route mismatches fail with typed repair diagnostics.
- No approved choreography, CSS, layout, renderer, semantic ID, route, or
  sampled endpoint changed.

## Shared Proof Obligations

Both frontends have exact evidence for parsing source, recognizing
extract-helper roles, proving refactor legality, binding semantic identity,
compiling the operation, binding the causal recipe, passing a generation
corpus, and proving runtime isolation. Missing or duplicate evidence fails
Coverage compilation rather than silently lowering the bar.

Human and LLM authors discover the same two operations through one generated,
freshness-checked catalogue. Friendly aliases and examples improve discovery;
code-owned authorities and evidence remain unavailable for authors to invent.

## Remaining Limits And Next Action

This tranche does not provide arbitrary refactoring, runtime execution,
browser compilers, a universal AST, cross-language syntax semantics, or
automatic animation synthesis for source variants. Scheme remains a
specialized exemplar.

The next accepted capability is one reversible finite sum/product binder
exemplar followed by a human visual checkpoint. Only after approval should a
structurally different binder caller and narrow promotion be proposed. Bounded
Graph3D, differentiation, and integration follow in that order.
