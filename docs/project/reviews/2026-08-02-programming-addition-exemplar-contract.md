# Programming addition exemplar contract

Date: 2026-08-02  
Status: implementation-ready hostability exemplar; visual approval withheld

## Boundary

This tranche hosts the existing deterministic `add(2, 2)` execution trace. It
does not execute TypeScript, introduce a language runtime, or promote a
programming curriculum family. `kp.promotion.vector-dot-projection` remains
the sole rank-5 `next` item. `kp.promotion.programming-algorithms` remains the
rank-23, later BFS exemplar across code, queue, and graph.

The addition trace has a narrower job: prove that the native catalogue can
paint a verified programming state and close the two observed programming
surface gaps—the addition row and the exact linear-solve/programming composite
caller—through one lazy adapter.

## Canonical truth

`kp.programming-addition-exemplar.v1` freezes:

- `source-file.programming.add`, TypeScript revision `rev-1`, at `src/add.ts`;
- the exact signature and return source ranges with their current provenance
  hashes;
- `trace.programming.add` on `clock.programming.add-demo`;
- four ordered states at progress `0`, `1/3`, `2/3`, and `1`;
- the exact active selectors, stack frame, locals `a=2`, `b=2`, computed
  `return=4`, and final output `4`; and
- the six required projection channels: source focus, call stack, locals,
  output, control state, and an accessible description.

The authored SourceFile and precomputed trace are semantic authority. The
shared editor player owns playback. One native programming adapter will own
paint. No renderer may run the source text or infer stack, local, return, or
output state absent from the verified trace.

## Host acceptance

- The exact source remains visible while the active source range follows the
  sampled trace step.
- Stack and locals show only trace-supplied values; the output appears as `4`
  only at the verified output state.
- Play, pause, direct seek, rewind, reduced motion, and static output preserve
  exact semantic endpoints through the existing player clock and lifecycle.
- Accessible state names the current step, selected source range, stack,
  locals, and output.
- The adapter loads only for a selected programming slot. Unrelated catalogue
  routes request neither it nor a code-highlighting dependency.
- The implementation uses no iframe, second clock, arbitrary executor,
  language runtime, inferred runtime state, BFS structures, or universal code
  presentation framework.
