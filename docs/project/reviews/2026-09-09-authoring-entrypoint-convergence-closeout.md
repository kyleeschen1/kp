## What is now integrated

One read-only `npm run author:check` entrypoint discovers six supported tasks,
returns raw starter sources, and checks selected JSON through the existing
domain owners. A discriminated report preserves the complete domain result,
including located repairs, and distinguishes checking from actual browser Apply,
extraction and publication. Its handoff explicitly says execution was not performed.

The six owners are binary Bayes, numeric logarithm change of base, reusable
equation reasoning, bounded code reasoning, pinned Graph3D saddle, and the
supply-tax market branch. They do not share a mathematical truth model or a
universal rendering path. Unsupported capabilities remain explicit. The complete
executable author packet is
`../authoring/supported-authoring-entrypoint-packet.md`; the canonical generation
guide routes supported work there.

The numeric CLI and editor now use one text compiler with a complete-success
type: a successful candidate necessarily includes verified semantics. Invalid
or superseded drafts retain the last valid displayed revision. Bayes and reusable
reasoning commands delegate their existing check owners rather than duplicating
semantic decisions. Legacy invocation meanings remain compatible.

Untrusted checking has bounded bytes and structural nesting, fatal UTF-8 handling,
exact task selection, lazy domain loading, and cross-domain/forged-authority
regressions. Transport guards do not replace the domain validator. No user code
is evaluated and checking cannot write source, Apply a preview, or publish.

## Demonstrated author value

Both retained author tasks traverse checking, explicit browser application,
source export, their existing edition builder and a real no-JavaScript reading:

- Urn prior 1/3, likelihoods 1/4 and 3/4: exact posterior 1/7, all seven stops,
  one 460-byte source file, immutable content-addressed Bayes edition.
- Log base 3 of 9: verified native endpoints and narration, one 946-byte source
  file, exported within a market branch and built as its bounded static reading.

Neither content variant needed task-specific renderer or motif code. Each retained
valid input required zero repairs in the replay. Deliberately invalid sources
return repairs; untouched valid starters fail the changed-task intent rubric.
This is deterministic task fulfillment, not free-prose grading or first-try model
success. The detailed effort audit, including specialist infrastructure work, is
`2026-09-09-authoring-entrypoint-workflow-comparison.md`.

## Was this loop worth doing?

Yes, as bounded integration: it removed command/result hunting, repaired numeric
CLI/editor drift, made unsupported handoffs explicit, and supplied repeatable
author-task checks across independently owned domains. It protects prior semantic
and visual investments instead of creating a competing framework.

The cost was significant infrastructure and verification work relative to two
small content artifacts. Six-owner closure should have been measured before the
first budget proposal. Future runs should register all intended real consumers
up front and distinguish common workflow value from mathematical coverage. The
result is a more coherent foundation, not evidence that authoring is already easy
for new users or that most undergraduate deductions can be animated.

## Remaining R4 obligations and mathematical handoff

R4A is complete; the broader R4 horizon is not. Next planning should be driven by
one real supported author task using the packet, rather than another generic
abstraction pass. Record first output, diagnostics, repairs, source changes,
manual glue, and preview/publication fidelity. An actual external model trial
still needs explicit payload/destination authority; the deferred R3 trial remains
an evidence gap, not an incomplete R4A slice.

Promote only an API tier demonstrated by real consumers, measured import costs,
preserved owner authority and adjacent retirement. R4A earned a narrow internal
reporting/dispatch seam, not blanket public API or catalogue migration. Code still
lacks the selected-source JSON editor and equation-like publication/practice
parity; Graph3D remains the pinned 4-to-8 fixed-camera case. Market static readings
are not animated graph publication, and a bare numeric equation is not its own
edition API. Existing immutable editions inherit form changes on rebuild, not
by silently changing distributed bytes.

precalculus task and its first unsupported semantic or presentation mechanism.
