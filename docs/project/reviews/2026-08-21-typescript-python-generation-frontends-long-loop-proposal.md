# TypeScript/Python Generation Frontends Long-Loop Proposal

Status: proposed; awaiting explicit execution approval
Date: 2026-08-21
Mode: Theseus long loop
Estimated envelope: 24 independently reversible slices; approximately 8–14
hours depending on compiler pressure findings

## Why This Loop Is Current

TypeScript and Python already have approved semantic refactor exemplars,
build-time parsers, semantic artifacts, operation sets, native code renderers,
deterministic motion, catalogue routes, and focused tests. Transformation
Coverage nevertheless classifies both capabilities as `Exemplar` because the
domain-owned generation frontends, operation/recipe evidence, and adversarial
corpora are not connected to the cross-domain request boundary.

Closing this gap before adding another equation family tests whether KP's
governed-generation architecture is genuinely cross-domain. The loop must add
semantic input and evidence, not redesign the existing animations.

## Objective And Done Contract

Given a governed TypeScript or Python extract-helper request over bounded
source revisions, KP can:

1. parse source with the language-owned build-time frontend;
2. prove the supported duplicated-rule-to-helper refactor or reject it with a
   typed diagnostic;
3. derive stable semantic entities, correspondence, and lineage without glyph
   equality or caller-authored source offsets;
4. bind the verified operation to the existing shared causal recipe and
   language-owned presentation;
5. return a deterministic semantic plan and the existing animation artifact;
6. expose human/LLM discovery metadata and exact capability evidence; and
7. derive `Direct` readiness for the narrowly supported TypeScript and Python
   capability without shipping TypeScript or Python compilers to the browser.

The existing free-shipping TypeScript and Python animations, their semantic
IDs, motion plans, timing, CSS, renderers, catalogue URLs, direct seek/rewind,
and accessibility behavior must remain unchanged.

## Allowed Work

- framework-neutral code-generation request/result protocols;
- TypeScript- and Python-owned build-time frontend adapters;
- bounded extract-helper semantic recognition and legality checks;
- typed operations, correspondence, lineage, recipe bindings, and corpora;
- generated semantic artifacts, discovery descriptors, evidence, readiness,
  and Transformation Coverage projection;
- focused CLI or script entrypoints for deterministic authoring and tests;
- exact URL, Catalogue, Review, architecture, and bundle verification;
- source and project documentation needed to preserve the resulting boundary.

## Explicit Deferrals

- no animation choreography, timing, CSS, renderer, or layout changes;
- no arbitrary refactoring engine or execution of untrusted user code;
- no universal code AST, cross-language parser, or shared language semantics;
- no Scheme changes;
- no live-model network benchmark;
- no CodeMirror/editor work;
- no binder, Graph3D, differentiation, or integration implementation in this
  contract;
- no legacy Direct case-ledger migration;
- no economics files or generated economics publication changes.

independently.

## Verification Cadence

- **Inner loop:** the new focused frontend/corpus test command plus the
  language-specific existing suite.
- **Standard boundary:** focused checks, `npm run typecheck`, and
  `theseus workspace validate`.
- **Broad boundary:** architecture, generated-artifact freshness, request and
  frontend evidence, selected Catalogue/browser checks, and scoped bundle
  closure.
- **Release:** both language suites, both canonical browser checks,
  Transformation Coverage unit/browser checks, architecture, typecheck,
  generated semantic/coverage freshness, bundle boundaries, and Theseus
  validation.

This loop deliberately has no subjective visual checkpoint because it may not
change presentation. If any slice requires a visible change, that is a stop
condition and a new exemplar-first proposal is required.

## Expected End State

At completion, an author or model can discover and request the bounded
extract-helper operation in TypeScript or Python. The respective build-time
frontend, not the model, owns parsing, source identity, legality, and evidence.
KP returns the existing deterministic animation when supported and a typed
repair otherwise. Both capability rows become honestly Direct, while the next
approved loop begins the finite binder exemplar and human checkpoint.
