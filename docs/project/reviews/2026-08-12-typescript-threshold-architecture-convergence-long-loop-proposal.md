# TypeScript Threshold Architecture-Convergence Long-Loop Proposal

Date: 2026-08-12

Status: approved

Theseus target: `next-action.kp.typescript-threshold-exemplar-v0`

Run contract: `run-contract.kp.typescript-threshold-architecture-convergence-v0`

## Objective

Deliver a searchable TypeScript free-shipping-threshold refactor animation
that proves KP's current semantic animation architecture can support a new
language domain without introducing another clock, scene graph, renderer
authority, or runtime framework dependency.

The exemplar will show two pieces of duplicated shipping logic, identify them
as the same concept, introduce one named helper, move the shared logic into
that helper with stable token identity, replace each duplicate with a call,
and verify unchanged behavior below, at, and above the threshold. The result
must support deterministic play, seek, and rewind as well as native static HTML
and reduced motion.

The tentative artifact id is
`animation.programming.typescript.free-shipping-threshold-refactor`.

## Why This Loop Is Current

The pre-expansion health tranche established one governed authoring route,
typed failures, explicit capability loading, classified runtime owners, route
budgets, and fresh bounded-context LLM evidence. The remaining question is no
longer whether KP has another animation subsystem. It is whether a new domain
caller can reuse the existing semantic spine at low marginal cost.

Three small convergence actions should happen with that proof: reconcile stale
control-plane wording, clarify the successful LLM authoring pattern, and retire
the narrow typed-gap-to-legacy-fade bridge if exact reachability proves it has
no live product dependency. The TypeScript exemplar then pressures the public
API, program semantics, renderer boundary, catalogue, and performance gates
without reopening lesson-layout work.

## Canonical Reference And Acceptance

Canonical references:

- the existing programming-addition catalogue surface for stable hosting and
  controls;
- `src/authoring/canonical-animation-public-api.ts` for governed construction;
- the existing semantic correspondence machinery and deterministic sampled
  clock;
- the TypeScript compiler API as build-time syntax authority, never as
  pedagogical sequencing authority.

Observable acceptance requires:

1. The initial duplicated source remains fully legible and geometrically
   stable.
2. Both repeated threshold expressions can be focused as one semantic idea.
3. The helper settles before either call-site replacement begins.
4. Operators and punctuation travel with their owning expressions; no token
   teleports, overlaps, or endpoint jerk are visible.
5. Direct seek and rewind produce the same frames as forward sampling.
6. Before and after programs typecheck and agree for declared boundary cases.
7. Initial and settled states render as native accessible code without
   JavaScript.
8. No `eval`, `Function`, arbitrary source execution, or TypeScript compiler
   code enters the client bundle.
9. Scheme factorial, programming addition, the catalogue shell, and the
   user's economics work remain unchanged.
10. Human review approves the exemplar before any cross-language abstraction
    or Python caller begins.

## Preservation Boundary

- Preserve Article v1, current layout experiments, canonical equations,
  Graph2D, Scheme factorial, programming addition, review capture, and direct
  catalogue links.
- Preserve semantic identity, lineage, correspondence, strict construction,
  static endpoints, accessibility, and the existing sampled-clock authority.
- Keep TypeScript parsing and typechecking at build/test time. Runtime receives
  only serializable semantic material and rendering plans.
- Keep TypeScript-specific semantic details local until a Python second caller
  demonstrates a language-neutral seam.
- Protect the pre-existing economics Article and generated-publication edits
  and all unrelated untracked project documents.

## Rollback Unit

Each slice is one focused commit. Control-plane reconciliation, compatibility
retirement, TypeScript source compilation, semantic asset construction,
rendering, and catalogue integration remain separately revertible. The whole
candidate exemplar can be removed by reverting its production vignette,
renderer extension, and catalogue entry without altering the shared Scheme or
programming-addition implementations. No shared abstraction is promoted by
this loop.

## Allowed Work

- Current-direction and authoring-entrypoint reconciliation.
- Exact legacy-fade reachability evidence and deletion when safe.
- One narrow build-time TypeScript source frontend.
- Stable program identities, scopes, bindings, source spans,
  correspondence, and refactor lineage for the declared exemplar.
- A typed pedagogical score over the existing clock and attention vocabulary.
- One governed animation asset and one production vignette caller.
- Native accessible code rendering and the smallest programming capability
  extension needed for the exemplar.
- Catalogue metadata, direct URL, review capture, stable visual tooling,
  bundle/accessibility/browser evidence, and project-memory closeout.

## Disallowed Work

- Python or a language-neutral refactor framework.
- A new clock, scheduler, stage lifecycle, scene graph, semantic store, or
  renderer authority.
- Tutorial-layout experimentation, CodeMirror expansion, public-site work, or
  curriculum expansion.
- Broad registry consolidation, directory reshuffling, or file splitting based
  only on size.
- Arbitrary TypeScript execution, a browser TypeScript compiler, a new package,
  or live LLM calls.
- Changes to the economics lesson edits or unrelated untracked documents.

## Verification Cadence

- Use `npm run verify:impact -- --path <changed-path>` before selecting focused
  suites.
- Use targeted Node tests for pure contracts, parsing, semantic identity,
  operations, lineage, and score sampling.
- Add `npm run typecheck`, `npm run check:architecture`, and
  `theseus workspace validate` at standard boundaries.
- Introduce one committed, scope-specific
  `npm run visual:typescript-refactor` entrypoint before browser captures.
- Use route-specific closure, active-frame, CLS, accessibility, and long-task
  evidence instead of aggregate `dist/` size.
- Run `npm run health:pre-expansion:release`, the full test suite, production
  build, stable visual command, and workspace validation at the final boundary.

## Hard Stop Conditions

1. The legacy-fade bridge has a live product caller that cannot be migrated
   without changing approved visual behavior.
2. TypeScript parsing requires a new dependency or makes the compiler part of
   the browser closure.
3. The exemplar requires another clock, scheduler, scene graph, stage
   lifecycle, semantic store, renderer authority, or public API.
4. Semantic identity must be inferred from glyph equality or geometry.
5. Behavioral validation would require arbitrary source execution or would
   overclaim whole-program equivalence.
6. Native source/target code, accessibility, review capture, direct links,
   static execution, seek, rewind, or existing program exemplars regress.
7. Route bundle, CLS, active-frame, or long-task budgets fail after one bounded
   common correction.
8. Work cannot remain separate from the protected economics and untracked
   user-authored files.
9. Work enters Python, language-neutral promotion, layout, editor, public-site,
   curriculum, live-LLM, or unrelated consolidation scope.
10. Human judgment is required to choose motion, salience, or choreography.

## Done Contract

The approved run ends at the slice-26 human checkpoint. Every earlier slice
must have a terminal state and independently verified commit. At that point the
catalogue exposes one direct-linkable, native, accessible, deterministic
TypeScript refactor candidate; route and runtime budgets pass; the public API
has a production caller; compatibility retirement is either proven complete
or has fired an explicit stop condition; and a compact review package explains
the exact marginal architecture cost. The run does not promote a cross-language
abstraction.
