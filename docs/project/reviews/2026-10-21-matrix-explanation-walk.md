# Matrix explanation walk: canonical review candidate

Review outcome: the user questioned its explanatory point. Its sequencing
capability is retained, but promotion/transfer is superseded by the approved
[input-difference comparison](../2026-10-21-input-difference-comparison.md).
Technical success here is not visual or pedagogical acceptance.

Plan: [bounded authoring continuation](../2026-10-21-matrix-explanation-walk.md).
Run: `run-contract.kp.matrix-explanation-walk-v1`.

## What is new

The accepted dependent-columns source now has a separate eight-stop authored
argument. Each stop names an ID, input column, existing native checkpoint and
prose. The source can revisit or reverse existing intervals; it cannot specify
geometry, timing or invented transitions. The original product, column cells,
scalar references, presentation and continuity compositor remain authoritative.

Host: `http://localhost:8000/experiments/matrix-column-combinations/?walk=1`.
Source: `content/authoring/linear-algebra/dependent-columns-walk.ts`.
Local projection: `src/experiments/matrix-column-combinations/walk.ts`.
This is a discovery format, not a promoted general score API or an addition to
the checked matrix JSON schema. Editing the existing JSON editor does not edit
this walk. The optional host is lazy and ordinary readers do not activate it.

## What to look for

Use **Next**, rather than Play all, for the first reading:

1. Stop 3 holds the first pair of contributions before addition. Does that pause
   give enough time to predict the result without losing the original equation?
2. Stop 5 rewinds to the original equation. Is that a useful reset, or does the
   full return feel too long? This is reverse display motion, not an inverse map.
3. Stops 6–8 inspect the second input and reach the same output. Is the comparison
   legible when the first result is remembered rather than retained alongside it?
4. Scrub or use Previous across the return and column switch. The matrix frame
   should stay in place; moving glyphs should follow the same native paths.

The first result is not retained while the second column is inspected. Adding
retained comparison paint would require a separate deliberate ownership/design
decision. A phone keeps the existing horizontally scrollable stage; this work
does not redesign narrow-screen mathematics. The two full calculations remain
available in an accessible static disclosure.

## Executed evidence and limits

- `npm run test:matrix-walk`: four passing tests, including exact semantic identity,
  source-only order variation, 1,001 deterministic samples/reversal, immutable
  stop snapshots and located unsupported-transition errors.
- `npm run visual:matrix-walk`: four passing Chromium tests. The walk's native
  contribution pose matches the original reader; direct seeking/replay,
  interruption/reversal, column handoff, stop restoration, phone resize,
  reduced motion, keyboard endpoints and disposal are exercised. Cold font
  disposal cannot install a late player. Disposable captures are produced by
  this committed command; they are not reviewed golden images.
- `npm run check:architecture`: passes dependency, entrypoint, semantic reader,
  animation, evaluation, compiler/governance and cross-domain boundaries.
- `npm run typecheck`: full application, node, test, Svelte and domain checks.
- `npm run generate:equation-reachability`: retains 68 roots; source inventory
  grows from 5,096 to 5,100 files, with no reachability edge change.

During construction, the Node strip-only runner rejected a parameter property;
it was replaced by explicit fields. Type checks caught a missing Error override
and widened test literals; both were repaired. The first browser run found that
popstate followed by hashchange could erase an invalid-stop alert after the old
position rewrote the URL. Restoration now suppresses URL publication, preserving
the held pose and the error; the failing browser scenario passes in the final run.

The impact planner selected broad defaults because these paths have no focused
rule. The approved discovery cadence uses the above semantic/paint/lifecycle and
architecture/type checks before human review. A full repository test run,
production build, complete payload/type-cost accounting and supported-browser
promotion cohort are reserved for the post-approval transfer package; they have
not been run for this candidate. No cross-browser or learner-efficacy claim is
made from this Chromium exemplar.

## Cost and next boundary

One shared timeline clock drives two prepared native column views. Only the
selected view paints or receives per-frame rendering; both occupy the same
layout box and are inert/decorative. This deliberately adds a second prepared
view to this optional route. Retained DOM and preparation cost increase; no
numerical performance improvement or byte-cost claim is established yet.
The local host adds navigation/lifecycle glue while reusing the existing
checkpoint playback helper and every native motion mechanism. No runtime
dependency or general renderer seam was introduced.

The next boundary is human review, then one structurally different source/order
to decide whether this format should be promoted. Keep the existing edition and
JSON-editor formats unchanged until that decision. Do not treat review readiness
as completion of the transfer package.
