# Numeric fraction variation

Canonical source: `examples/algebra/fraction-chain-numeric.json`, with its
adjacent Article. Host: `/experiments/fraction-chain/numeric/#counting-parts`.
The original `/experiments/fraction-chain/#counting-parts` remains available.
Both use the persistent fraction passage and the existing native alignment,
fraction merge and numerator-evaluation owners. Issued fraction-chain proofs
remain semantic authority; HTML and motion consume the same published source.

The requested `1/4+1/8 → 2/8+1/8 → 3/8` works without an invented reduction.
This was **not source-only** on first attempt. The semantic compiler accepted
the source, but the native alignment plan/endpoints embedded thirds and sixths,
and the passage required four states. Repairs touched nine production modules
and two publication/build configuration files. No new motif, timing, palette,
font, clock or compositor was introduced.

The shared alignment owner now derives values and occurrence identities from
one issued plan; copied plans cannot enter native endpoint construction. Each
session retains its own plan through font/viewport replacement. The passage
supports alignment/addition with an optional reduction and derives its rail end
from that checked sequence. Source JSON is published inertly with escaped `<`
characters and revision-checked before enhancement. Unsupported sequences and
two-sided scaling still fail explicitly at their responsible boundaries.

Evidence:

- `npm run test:fraction-chain`: original and numeric source, copied-plan
  rejection, interleaved caller isolation, publication, terminal-position
  bounds, source escaping and coarse/expanded measured-rail round trips.
- `npm run visual:fraction-chain`: real native numeric endpoints, forward and
  reverse seeking, detail return and terminal keyboard navigation; original
  passage styling, font/edge/collapsed-host preservation.
- `npm run test:common-denominator-pressure-presentation` and
  `npm run visual:common-denominator-pressure`: existing editor caller,
  ownership, seam, font/viewport replacement and static checkpoints.
- Full typecheck, architecture checks and production bundle build.

This establishes reuse for the retained positive one-sided numeric caller,
not general fraction certification. Two-sided scaling, subtraction, fluent
numeric reduction and final cross-browser release evidence remain separate.
