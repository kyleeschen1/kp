## Durable sequence

Stable loop IDs are `reader.l1` through `reader.l6`. These name outcomes, not
completed or executable Theseus slices. Each approved run uses this document as
its source; Theseus alone owns live progress. Later scopes are deliberately coarse
until their prerequisites provide evidence. Keep the order visible across sessions.

1. **A dependable reading baseline.** Adopt the accepted contextual and local
   recall treatments on the default exemplar, retain explicit comparisons, and
   give phone prose normal reading width with a bounded local inspection entry.
   Do not reopen desktop aesthetics. Preserve native scroll, held motion, exact
   return, no-JS/print, keyboard and reduced motion. Review the changed mobile
   treatment once; cross-browser checks are now justified for this adopted path.
   Stop when dependable, not when every imagined layout is solved.

   Add **local access to the lens**: one active lens, many transition-local entry
   points. A reader who has scrolled past the old knob can select a nearby step
   without scrolling back. First inspection starts at that transition's source,
   paused; revisiting restores its held progress. Preserve inactive bookmarks and
   permanent records, not multiple live animation owners. Ordinary scroll never
   changes selected transition or progress. Local entry must not hijack symbols,
   text selection, or future definition/lineage clicks. Do not default to a
   viewport-floating knob that silently attaches to whichever equation is nearby.

2. **One step that opens into its reasoning.** Extend checked authority for
   positive-mass cancellation, exposing the factorization and nonzero inverse
   pair with preserved outer endpoints. Couple it to one expandable transition,
   its static substeps, justification and exact collapse. Reuse existing motifs
   only when supported by actual source-bound roles and laws. Bound the semantic
   investigation; if it needs a broad solver, stop and rescope rather than using
   the entire loop. Human review judges whether the extra depth clarifies the
   operation. No general proof-graph service is prerequisite.

   Also distinguish **recall** from **use**: locally recall the earlier momentum
   definition, display its assumptions/provenance, then show its result used in
   the existing substitution. Reuse `p=mv` and `v=p/m` before adding another law.
   No multi-screen flying expression; preserve semantic lineage, not document
   travel distance. This capability is not already delivered by a reference link.

3. **Prove authors can reuse it.** Create an independently authored short
   explanation using that same supported cancellation in a different context
   (prefer a scalar algebra reading alongside the physics reading). Keep their
   mathematical authority separate from prose and presentation. Target zero new
   renderer, clock, CSS or navigation code for the second instance; report any
   necessary shared binding repair honestly. Supply one canonical source example,
   a focused validation command and useful unsupported-input diagnostics. Change
   shared presentation once and verify both newly built outputs update, without
   rewriting previously published immutable editions. Measure author edits and
   engine interventions separately. This proves bounded operation reuse, not
   arbitrary LaTeX generation.

4. **A bounded code test.** Use an already supported code transformation through
   its canonical language-owned source and native renderer. Present persistent
   before/after code and interleaved reasons with local reversible inspection.
   Retain enough surrounding code to explain the change; participant-only tokens
   are not the default. No new interpreter or arbitrary refactoring generator.
   Test transfer of reading, inspection, depth and provenance concepts, not visual
   imitation of moving equations. Human review of this second medium precedes
   any shared interaction abstraction. This follows authoring pressure, rather
   than waiting for a large calculus repertoire.

5. **A real mechanics argument.** Extend from kinetic energy in terms of momentum
   toward `dK/dt = v dot F`, with the existing Article as the prose baseline.
   Begin with the one genuinely explanatory bridge: differentiating the squared
   norm and interpreting the dot product. Distinguish fixed-mass assumptions,
   algebra/calculus deductions and Newton's physical law. Build toward a roughly
   6–10-state path only as the steps earn their place; not every edge requires
   motion. Include recall, one optional refinement and one prediction/self-check
   without an assessment system. Newly required calculus semantics need explicit
   authorization and tests; the current three-move source does not supply them.

6. **Transfer the medium to a graph.** Reuse the existing straight-push and
   turning Graph2D fixtures to inspect why force along motion changes kinetic
   energy while perpendicular force can turn momentum without instantaneous
   power. Couple a meaningful graph change to the relevant symbolic relation,
   preserving a stable coordinate frame, permanent argument, local progress and
   return. Do not duplicate large graphs to imitate equation rows or normalize
   physical time into algebraic rewrite time. Compare shared interaction needs
   only after this second representation supplies evidence. The contour/gradient
   exemplar remains the next geometric reference, not another simultaneous UI
   redesign or a mandate to implement potential-energy physics now.

## Cadence and relation to the old plan

Each loop has one principal user-visible outcome. Test invariants early, use one
batched subjective checkpoint, and reserve broad matrices for adoption/integration.
Approved away portfolios can park candidates and proceed with genuinely independent
fixtures, diagnostics or source validation. Do not silently batch dependent visual
promotion while the reviewer is absent. User observation should test static
reconstruction and voluntary confusion → inspect → clarification, not just liking
the animation. External studies require separate consent; ordinary user feedback
can guide the ongoing exemplar.

Keep the old v2 deferred. Its r3 return work is partially covered by the accepted
away result; overview/prediction are not automatically complete. Its r4 source-only
reuse belongs in the third proposed loop. Its r5 release checks should follow the
changed adopted surfaces, rather than force a ceremonial restart of all five
packages. No old package is marked complete solely by this recommendation.

The immediate recommendation remains loop 1. The larger aim is a dependable
explanation, adjustable depth, cheaper second authoring, a substantial argument,
then transfer across representations—not another cycle of infrastructure in search
of a lesson. Review this sequence after the authoring-pressure loop before
committing to a broad mathematics repertoire.

Motif expansion is continuous but evidence-led: reuse an existing supported
motif, repair a demonstrated failure, or add the missing operation required by
the next explanation. It starts with loop 2 cancellation/refinement and continues
with loop 5 calculus. Each new mechanism should gain a second meaningful use;
there is no separate prerequisite to fill a complete motif catalogue. Loops 4
and 5 can later be independent portfolio packages after loop 3, but only under
an explicitly approved away contract with local gates.

## First delivery run proposal: reader.l1

Status: **awaiting scope/resource approval**. The request to record and invoke
the delivery loop selected this sequence; the detailed run is proposed here so
“as long as possible” has concrete boundaries. Default mode is interactive.

### Outcome and ownership

A reader can comfortably read the accepted explanation, scroll away from its
active knob, and inspect a nearby transition without losing their place. The
author retains one checked source and one renderer, not a family of page-local
animation paths.

Canonical artifact: `examples/physics/momentum-energy.article.md`.
Host: `/experiments/mechanics-relations/` on shared port 8000.
Semantic authority: `domains/physics/momentum-energy-derivation.ts` through
`src/authoring/momentum-energy-derivation-authoring.ts`.
Renderer: `src/rendering/momentum-energy-derivation-session.ts` through the
canonical native KaTeX compositor. Reader projection and local return adapter
own access and bookmarks; the existing shared clock alone owns active progress.

Preserve the accepted contextual motion, motifs, semantic IDs/assumptions,
permanent readable equations/prose, static/no-JS/print truth, reverse/hold,
native endpoints, ordinary scroll and earlier-result exact return. Keep previous
visual treatments available as explicit internal comparisons. No catalogue-wide
rollout or global salience/navigation store. Rollback units: one default-selection
commit; one local-entry/mobile presentation commit; one post-approval integration
and evidence commit. No semantic rollback for a presentation failure.
