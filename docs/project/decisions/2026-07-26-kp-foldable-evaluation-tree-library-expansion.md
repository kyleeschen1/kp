# Foldable Evaluation Trees And Library Expansion

Date: 2026-07-26
Status: accepted direction

## Decision

KP will close the current foundation tranche with one canonical radical reader
adoption and a reusable promotion kit. After that checkpoint, the default
priority changes from platform-only compositor work back to visible animation
library growth. At least three domain exemplars should ship before another
platform-only compositor loop unless a real exemplar exposes a failed generic
invariant.

The first library-expansion exemplar should be:

```text
3(x + 2) + 2(x - 1) -> 5x + 4
```

It will introduce a foldable transformation/evaluation tree without creating a
second animation runtime. The immutable canonical trace remains the source of
mathematical truth. Expanded, collapsed, automatic, and pinned views are
presentation projections over that trace.

## Why This Is Convergent

Prior motif and animation work remains valuable as semantic law, lineage, and
presentation policy. It should not be ported by copying legacy DOM choreography
or keyframes. Cancellation retains inverse-term identity, contact/collapse,
survivor compaction, native settlement, seek, and rewind laws. Distribution
retains one-to-many lineage and reversible collection. A visible term
"crossing the equals sign" is a fluent presentation proxy for a certified
balanced operation, cancellation, and evaluation chain; it is not a new
semantic primitive.

There remains one canonical implementation path:

```text
verified semantic trace
-> presentation projection and layout plan
-> canonical renderer session
-> native settled DOM
```

Unmigrated legacy animations remain reference evidence and compatibility
coverage. They do not paint alongside a canonical transition and do not become
a peer runtime.

## Compositor Boundary

Semantic layout planning owns stable rows, groups, lanes, fold state, and
disclosure. The local compositor owns short-range paint routing between measured
native source and target geometry.

The current compositor already provides native KaTeX measurement, protected
notation regions, direct or simple dogleg routes, bounded clearance sampling,
and conservative native settlement. It does not yet globally optimize
simultaneous glyph motion, understand semantic line breaks or matrix grids, or
route around moving obstacles.

Future exemplar-driven improvements should add:

- hierarchical subtree envelopes rather than isolated glyph rectangles;
- stable layout plans over the full swept envelope;
- temporal lane reservation and dependency priorities;
- group motion for semantically bound structures;
- deterministic fold, stage, or condense fallbacks when a scene cannot fit;
- compound-scene clearance checks.

These belong in generic semantic layout or compositor policy only when an
exemplar demonstrates the need. Operation-specific geometry remains rejected.

## Folding And Timing Contract

The expression AST and the transformation/evaluation tree are distinct. A
transformation node references affected AST subtrees, its law, inputs, output,
dependencies, and semantic checkpoints. Folding hides presentation detail; it
never changes the trace or result.

A collapsed node shows the exact input, a certified summary, a short summary
transition, the exact output, disclosure that detail was folded, and a way to
expand it. Timing derives from the fold projection:

- focused or pinned nodes play at full pedagogical duration;
- surrounding context may use a compressed but still legible duration;
- collapsed nodes use a disclosed summary transition;
- repeated independent structure may show the first two instances, a patterned
  middle sweep, and a final full instance;
- causal steps are never silently skipped.

Direct seek remains deterministic for each fold projection. Opening a node
pauses at an exact semantic checkpoint; closing it restores the exact parent
frame. URLs use stable node IDs and fold state rather than raw timeline
percentages. Accessibility and static exports retain the complete trace and
disclose folded content. Governed models may suggest focus and fold state but
may not hide mathematical dependencies or author timing, geometry, or DOM.

## Promotion Ratchet

After the radical promotion kit, the next unit-exponent adoption should require:

- zero canonical compositor core changes;
- zero new lifecycle or scheduler categories;
- zero notation-specific geometry;
- no second semantic or runtime artifact;
- only lesson content, descriptor wiring, and focused verification.

That proof should be a short adoption check, not another 20-30-slice foundation
loop. Failure fires a stop condition and identifies the allegedly reusable
boundary that did not hold.

## Six-Loop Horizon

1. Radical reader adoption and reusable promotion kit.
2. Foldable distribution and like-term collection.
3. Exact arithmetic evaluation trees and quantity/place-value views.
4. Vector and matrix operations with grid-aware nested computations.
5. An equation-graph derivative bridge with routine algebra foldable.
6. Integral accumulation with partitions, sums, and the limiting integral.

This is directional ordering, not implementation authorization. Each subjective
exemplar still requires a reviewed proposal, one independently reversible
checkpoint, and a typed run contract before execution.

## Non-Goals

- no global equation-family migration;
- no second compositor or tree runtime;
- no operation-specific route catalog;
- no LLM-authored mathematics, DOM, pixels, or arbitrary keyframes;
- no silent compression of causal steps;
- no platform-only detour before three domain exemplars unless a generic
  invariant demonstrably fails.
