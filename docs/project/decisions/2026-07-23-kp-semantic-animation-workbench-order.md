# Semantic Animation Workbench Execution Order

Date: 2026-07-23
Status: accepted

## Context

KP's animation catalog, learner projections, promotion evidence, Theseus
progress, and development-review notes are individually useful but do not yet
form one coherent authoring surface. The Semantic Editor consequently exposes
duplicate-looking family samples, several presentation forms of the same
animation, and inconsistent signals about what is approved, active, planned, or
awaiting review.

Continuing to add breadth before establishing canonical animation identity
would make later reconciliation more expensive and would weaken the project's
ability to tell whether a visual success has become a reusable semantic
contract.

## Decision

Complete the active derivative/secant-to-tangent exemplar checkpoint, then
insert a Semantic Animation Workbench v0 before the quadratic branch-and-roots
exemplar.

The workbench is a Semantic Editor surface, not an Agenda view. It will derive
one canonical entry per animation from existing authorities:

- the animation catalog owns concrete animation identity;
- representation registries own asset, card, lesson, concept-room, static, and
  export views;
- Theseus owns execution order, progress, blockers, and verification;
- promotion evidence owns maturity and approval;
- the development-review inbox owns feedback.

Family samples and catalog projections become searchable aliases or coverage
relationships beneath the canonical animation rather than duplicate top-level
items. Planned animations remain searchable but visibly non-playable.

Workbench v0 must provide canonical indexing, deduplication, fuzzy search, a
live preview, lifecycle and roadmap badges, an automatically derived acceptance
brief, and item-scoped review evidence. Representation switching and interaction
polish may follow after the first human checkpoint.

## Execution Boundary

The approved order is:

1. finish and human-review the active derivative bridge;
2. build and human-review Workbench v0 using an approved symbolic exemplar, the
   active derivative, and the planned quadratic as three lifecycle states;
3. implement quadratic solution branching through the accepted workbench;
4. alternate later capability-opening exemplars with bounded normalization
   slices;
5. promote a local primitive globally only after a second consumer demonstrates
   that its contract generalizes.

The current continuation contract is already at its stored slice limit. This
decision does not rewrite it or silently replace its remaining slices.
Theseus must record the priority boundary now and establish an approved
successor contract before Workbench implementation begins.

## Completion Gate For Future Animations

After Workbench v0, an animation is not complete until it has:

- one canonical animation identity with aliases grouped beneath it;
- a concrete playable representation or an explicit planned-only state;
- an acceptance brief and current roadmap/maturity state;
- item-associated review evidence;
- approval evidence tied to a concrete revision;
- applicable seek, rewind, reduced-motion, and static checks;
- named reusable motifs and dependencies.

## Preservation Boundary

Do not create a second animation database, duplicate Theseus progress manually,
turn presentation styles into separate animation identities, or merge Agenda
planning behavior into the live Semantic Editor. Preserve existing animation
semantics, runtime clocks, renderer ownership, learner routes, and append-only
review history.
