# Six-Loop Product Convergence Sequence

Date: 2026-08-01
Status: accepted and approved for one chained Theseus long loop

## Decision

Run the next product tranche in this order:

1. make the Animation Catalogue an honest, compact inventory, including a
   meaningful native 3D-host result and a review package for later human
   dispositions;
2. compile a verified generated solve-x trace into the canonical
   `KpAnimationAsset` path and attach the first deterministic
   `ExplanationSpineV1`;
3. converge the public authoring facade and retire only compatibility paths
   whose last real caller moves in the same change;
4. build one reversible Project-one-vector-onto-another exemplar as rank 5,
   preserving the accepted dimensional-continuity graph language;
5. repair selected-capability loading, reserved layout, and the measured
   catalogue-route Core Web Vitals debt without widening product targets; and
6. close the observed programming catalogue gap with one deterministic native
   addition-trace exemplar, without promoting the later BFS curriculum rank.

The six loops may execute as one 30-slice umbrella contract. Independent
objective work may continue after a visual exemplar is ready, but visual work
on that exemplar stops: no family generalization, release certificate, motif
promotion, or rank advancement occurs before human review. The contract ends
at one consolidated checkpoint unless a technical stop condition fires first.

Rank 5 remains the first unresolved animation promotion. Generated solve-x and
its explanation spine are the already-recorded M2/M3 platform gate immediately
before rank 5. Performance work is a measured product-debt repair. The addition
trace is a hostability exemplar, not an insertion ahead of the rank-23 BFS
promotion.

## Reason

KP has strong semantic and rendering ingredients but too many partially
overlapping ways to inspect them. This sequence uses concrete callers to
simplify the system:

- the catalogue reveals what actually exists and paints;
- generated solve-x tests whether verified problem output reaches the one
  canonical asset and explanation path;
- two real public-facade callers justify API retirement decisions;
- vector projection supplies the next domain exemplar in the durable order;
- route attribution turns known bundle and LCP debt into bounded work; and
- the already-rich programming trace semantics finally receive an honest
  native catalogue host.

Batching review at the end lets the engineering work proceed without treating
advance execution approval as future aesthetic approval. It also avoids
repeatedly promoting abstractions before a structurally different caller has
proved them.

## Consequences

- The human-readable proposal in
  `docs/project/reviews/2026-08-01-six-loop-product-convergence-long-loop-proposal.md`
  owns rationale, preservation boundaries, acceptance criteria, and the
  approved slice definitions.
- The Theseus run contract is the executable record for live slice status,
  verification evidence, commit boundaries, and terminal state.
- Catalogue Keep/Retire/Rewrite labels remain unassigned until reviewed by the
  user. Jacobian/Hessian semantic and conformance fixtures are not deleted by
  catalogue curation alone.
- `ExplanationSpineV1` is deterministic and hand-authored. Verified claims own
  mathematical truth; an LLM editorial service remains deferred.
- API consolidation is caller-backed and complexity-negative. It does not
  introduce a universal scene graph, renderer, motif registry, parameter
  schema, or domain engine.
- Vector and programming exemplars can become review-ready in the same run, but
  neither receives visual promotion by inference.
- The existing product targets remain targets: initial script transfer at or
  below 250,000 bytes, constrained LCP at or below 2.5 seconds, and the already
  recorded layout, interaction, and frame-health budgets.

## Alternatives

- Run six separate loops with six interruptions. Rejected because the
  objective platform and verification work can safely chain and the user
  explicitly approved an umbrella run.
- Promote vector immediately and postpone the generator bridge. Rejected
  because the accepted M2/M3 gate belongs before rank 5 and exercises the
  public facade before more callers accumulate.
- Start with a broad API or motif rewrite. Rejected because the project already
  has strong local contracts; consolidation should follow observed callers and
  last-caller migrations.
- Treat the programming exemplar as rank-23 promotion. Rejected because a
  native addition trace closes a catalogue host gap but does not prove the
  code/queue/graph BFS learner experience.
- Infer catalogue dispositions or visual approval from advance execution
  approval. Rejected because those judgments need the resulting artifacts.

## Follow-Ups

1. Execute the approved 30-slice contract through its consolidated checkpoint.
2. Review catalogue disposition candidates and the generated solve-x, vector,
   and programming captures together.
3. After approval, issue only the matching promotion certificates,
   second-caller generalizations, and exact retirement changes.
4. Keep the public KP website, curriculum, live LLM editorial service, and
   broad visual restyling outside this run.
