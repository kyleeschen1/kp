# Decision 2026-08-15: Canonical Semantic-Motion Compiler Order

Date: 2026-08-15
Status: accepted; migration sequencing superseded

The compiler boundary remains authoritative. Its opportunistic historical
migration sequence is superseded by
`2026-08-15-kp-exhaustive-symbolic-equation-convergence.md`, which requires an
exhaustive supported equation-domain cutover after the clean-path checkpoint.

## Decision

Establish one canonical semantic-motion compiler immediately after the active
quotient, distribution, and cancellation pressure run completes its
cross-caller comparison and invariant-promotion decision. Do not add another
symbolic animation family before this bounded compiler tranche.

The tranche establishes the narrow shared waist now, but does not migrate the
whole catalogue. Existing assets move incrementally only when a real caller,
known regression, or compatibility retirement justifies the work.

The accepted order is:

1. complete the active three-operation run, including the cancellation human
   checkpoint, cross-caller comparison, and invariant promotion or rejection;
2. compile the three approved callers through one semantic-motion entry point;
3. enforce the author/compiler/renderer boundary and connect governed LLM
   drafts to that entry point;
4. build one new animation entirely through the clean path and stop to measure
   its marginal implementation cost;
5. inventory remaining symbolic paths as `canonical`, `adapter-backed`,
   `legacy-bespoke`, `static-only`, or `unsupported`;
6. migrate older families opportunistically, retiring a compatibility path in
   the same rollback unit when its final caller moves;
7. resume catalogue breadth only after the new caller shows that semantic
   content and bindings, rather than new renderer machinery, dominate its
   implementation cost; and
8. keep product-layout, curriculum, SRS, broad tutoring, advanced editor,
   SvelteKit application, public-editor, and broad 3D work behind their
   existing gates.

## Canonical Boundary

All generated and promoted symbolic motion should converge on:

```text
semantic states
-> canonical operation and role bindings
-> validated lineage and mathematical authority
-> pedagogical presentation intent
-> capability-based recipe resolution
-> role-complete presentation plan
-> nominal executable choreography
-> renderer-neutral tracks
-> renderer adapter
-> one deterministic sampled clock
```

Authors and LLMs own semantic states, canonical operations, role bindings,
lineage, teaching goals, salience, and explanation depth. KP owns motif-family
selection, presentation-recipe resolution, paths, phase ordering, timing,
interpolation, and renderer realization.

The public compiler result must fail closed through a discriminated outcome:
`ready`, `repair-required`, `explicit-static`, or `human-review`. Unsupported
work must never silently borrow a generic fade or unrelated motif.

## Promotion Gate

The compiler tranche may begin only after the active run decides the invariant
boundary evidenced by quotient fusion, distribution fan-out, and additive
cancellation. Its first implementation must use those three callers and must
not invent a broader universal animation schema.

The tranche succeeds only when one subsequently selected animation reaches a
human-reviewable result primarily by adding semantic states, role bindings,
lineage, teaching intent, and salience. Merely introducing elegant types does
not satisfy the gate.

## Reason

The strongest recent animations share sound semantic, planning, native-KaTeX,
path, and deterministic-clock machinery, but older and intermediate callers
can still select motif labels, concrete recipes, local timing, or renderer
behavior through competing authority paths. This makes correct abstractions
coexist with bypasses and explains recurring classes of missing motion, wrong
motif selection, premature retirement, endpoint jumps, and renderer-specific
repairs.

Building more animation families before closing the narrow waist would
compound those inconsistencies. Migrating the entire catalogue immediately
would instead create a broad, risky rewrite without caller evidence. The
accepted sequence removes new bypasses first and makes legacy convergence
incremental.

## Consequences

- The current run remains authoritative until its final comparison and
  promotion slices complete.
- No competing compiler run contract is created in advance of that decision.
- The next proposed implementation tranche must name the three approved
  callers, one public entry point, enforcement boundaries, LLM adapter, and one
  clean-path pressure caller.
- Asset-authored concrete recipes, raw motif selection, local timing tables,
  renderer inference from token text, and silent visual fallbacks become
  explicit migration targets rather than accepted authoring patterns.
- Catalogue-wide symbolic migration is not a prerequisite for resuming visible
  animation development.
- Existing layout, public-product, code-language, graph, and 3D priorities are
  not reordered by this decision.

## Alternatives Considered

- **Continue adding motifs before convergence:** rejected because every new
  caller could reproduce the same authority ambiguity and regression classes.
- **Migrate the complete catalogue immediately:** rejected as a destabilizing
  rewrite without proof that one compiler boundary fits every historical
  family.
- **Connect the LLM directly to renderer recipes:** rejected because it would
  give generated output geometry, timing, and presentation authority that KP
  must own.
- **Leave current family-local glue indefinitely:** rejected because the three
  contrasting callers now provide enough evidence to test a narrower common
  compilation boundary.

## Follow-Ups

1. Record human approval of the repaired cancellation checkpoint.
2. Complete the active cross-caller comparison and promote or reject candidate
   invariants.
3. Propose a separately reviewable canonical semantic-motion compiler run
   contract derived from the resulting boundary and this decision.
4. Stop that future run after one clean-path animation demonstrates reduced
   marginal implementation cost.
5. Materialize the legacy migration queue only from the resulting inventory;
   do not infer a catalogue-wide rewrite from this decision.
