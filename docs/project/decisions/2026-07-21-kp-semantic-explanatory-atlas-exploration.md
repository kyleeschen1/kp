# Semantic explanatory atlas exploration

Date: 2026-07-21  
Status: accepted exploratory direction; no implementation priority change

## Decision

Record a semantic explanatory atlas as a durable KP design lane. The atlas will
explore how KP can reveal the native semantic machinery of programming
languages and other subjects without forcing every domain through equation,
token, graph, or generic scene metaphors.

The accepted exploratory designs are:

- `docs/superpowers/specs/2026-07-21-semantic-programming-language-theater-design.md`;
- `docs/superpowers/specs/2026-07-21-semantic-topology-explanations-design.md`.

For programming, use `ProgramSnapshot` above individual source files, preserve
revision, execution, projection, and narrative time as distinct axes, and let
language semantics packs provide native objects, operations, relations,
providers, motifs, laws, caveats, and exemplars.

For topology, distinguish changes to a space from changes to its embedding,
learner projection, or narrative frame. Treat exact constructions,
illustrations, provider-backed computations, theorem claims, and proofs as
different epistemic states.

In both domains, authors state semantic change, preservation, and pedagogical
intent. KP derives routine occurrences, correspondence, frames, and governed
motion; renderers own geometry only.

## Priority Boundary

This decision records design provenance and authorizes documentation and
bounded future experiments. It does not displace the active solve-x human
checkpoint, responsive-attention design, or approved symbolic exemplar order.
No broad programming-language pack, topology runtime, or family-wide visual
grammar is authorized.

Each subject must begin with one independently reversible exemplar and stop for
human review before generalization.

## First Candidate Exemplars

Programming begins with one recursive Lisp substitution through a nested
S-expression. A meta-circular evaluator dispatch follows only after its
recursive material language is accepted.

Topology begins with the quotient construction that identifies the endpoints
of a closed interval to produce a space homeomorphic to a circle. The exemplar
must make endpoint identification, quotient neighborhoods, embedding
choreography, and epistemic status separately inspectable.

Haskell type inference, Forth stack and dictionary construction, C pointer and
machine projection, and later topology rooms remain candidate experiments, not
an execution queue.

## Consequences

- KP gains a durable place to reason about subject-native semantic explanation
  without committing to implementation.
- Shared runtime and provenance contracts remain the architectural center.
- Domain packs can develop distinctive visual identities without creating
  separate clocks or canonical renderer state.
- Exemplar review guards against premature universal scene graphs, metaphors,
  and authoring schemas.
- Future project-memory reviews may schedule one atlas experiment when it fits
  the active product sequence.

## Alternatives Considered

- Defer all design until code or topology becomes active: rejected because the
  accepted ideas would be lost and rediscovered without durable provenance.
- Add programming and topology directly to the active roadmap: rejected because
  the current solve-x and responsive-attention checkpoint remains unfinished.
- Build one universal explanatory scene graph: rejected because language and
  topology semantics require native objects, relations, caveats, and evidence.
- Treat the visual metaphor as the semantic model: rejected because botanical
  code material, type seals, stacks, memory, and deforming surfaces are
  explanatory projections rather than canonical truth.
