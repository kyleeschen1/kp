# Persistent Workspace Composition Sequence

Date: 2026-07-30
Status: accepted

## Decision

KP will retain equation succession as the canonical composition environment for
one native representational state becoming another, and add one bounded
persistent-workspace composition environment through the place-value addition
exemplar.

The project will use three composition environments:

1. **equation succession** for native states such as algebraic rewrites,
   fractions, exponents, and radicals;
2. **persistent workspace** for a stable documentary or spatial substrate with
   local semantic operations, such as written arithmetic, matrix cells, code
   execution, tables, and diagrams; and
3. **synchronized model views** for several persistent views derived from one
   deterministic state and shared clock, such as economics, physics, FTC, and
   BFS.

These are presentation environments, not separate runtimes, clocks, semantic
truths, or renderer systems.

## Immediate Sequence

The active place-value animation remains at a human repair checkpoint. Its next
approved work is:

1. freeze full-timeline documentary, convergence, carry, and handoff laws;
2. define compiler-owned persistent workspace, destination, route, transit, and
   handoff contracts;
3. keep one written scaffold mounted through the full animation;
4. converge column inputs at the measured result slot;
5. keep every carry visibly owned along a measured arch until native endpoint
   handoff;
6. perfect the ones-column exemplar and stop for human review;
7. after approval, compile tens, hundreds, and terminal overflow through the
   same column-operation path;
8. consolidate shared browser conformance helpers;
9. prove a second addition fixture without renderer changes;
10. retire the superseded scene-replacement path and complete release evidence.

The repair must be complexity-negative in the place-value rendering layer by
closeout. A generic change that only adds optional branches or another peer
implementation does not satisfy the decision.

## Concrete And Durable Cadence

KP will alternate by evidence, not by calendar:

```text
canonical exemplar
-> failed invariant
-> smallest durable seam
-> return to exemplar
-> second caller or variation
-> retire the superseded path
-> resume domain expansion
```

A durable abstraction must remove an existing branch or serve at least two
imminent real callers. Ownership and lifetime invariants may be promoted from
one exemplar when bypass would systematically corrupt canonical output, but
they still require an exemplar checkpoint before generalization.

Domain operations remain domain-native. Place-value carry, economics
equilibrium, physics work, and programming enqueue or return events compile
into shared lifetime, destination, route, ownership, sampled-frame, and
handoff contracts; they do not become one universal operation taxonomy.

## Forward Domain Sequence

This decision does not reorder the stable promotion ledger.

- **Economics equilibrium** follows place-value closure and uses a deterministic
  parameter model over persistent curves, intersections, regions, quantities,
  and claims.
- **Constant-force work-energy** follows economics and reuses deterministic
  state, persistent graph/diagram views, cross-view correspondence, and shared
  sampling while adding units, assumptions, vectors, and conservation.
- **Programming** remains later in the stable ledger. BFS is the retained
  cross-view trace exemplar; recursive Lisp substitution remains a separate
  exploratory language-semantics exemplar. Source revision, execution,
  projection, and narrative time remain distinct.
- **Matrix and linear-map work** should be an early proof that persistent grids,
  exact result-slot destinations, and local evaluation overlays generalize
  without written-arithmetic branches.

## LLM Consequence

Models author verified semantic operations and pedagogical intent such as
evaluate a column, carry overflow, shift a curve, accumulate work, visit a
node, or enqueue a value. They do not author DOM, opacity thresholds, pixel
coordinates, arbitrary keyframes, or scene visibility.

The compiler must fail with an explicit capability gap when no promoted
presentation exists. It may not substitute a fade or whole-scene replacement.

## Preservation And Deferral

Preserve the exact semantic trace, place-value proofs, fold plan, shared clock,
base-ten projection, accessibility, export, Review, native KaTeX settlement,
and all promoted readers.

Do not build a universal scene graph, economics solver, physics engine,
programming runtime, new clock, new compositor, or new display page through
this decision. Cross-domain implementation remains ordered by the stable
promotion ledger and independently approved execution contracts.

## Alternatives Considered

- Patch only the current animation: rejected because it would preserve the
  scene-replacement lifecycle and repeat the bug class.
- Generalize every renderer before returning to the exemplar: rejected because
  it lacks concrete pressure and would grow the project without visual proof.
- Replace the native compositor: rejected because measured native paint,
  semantic lineage, and endpoint ownership remain useful; the failure is in
  composition and adapter policy.
- Move directly to economics: rejected because the active arithmetic exemplar
  has exposed a shared ownership and lifetime defect that should be closed
  before another persistent visual domain is added.
