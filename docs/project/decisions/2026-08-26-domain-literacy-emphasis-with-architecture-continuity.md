# Domain Literacy Emphasis With Architecture Continuity

Date: 2026-08-26
Status: accepted

## Decision

Adopt **domain-specific literacy** as KP's current product emphasis and a
primary source of product differentiation. KP should make expert ways of
seeing authentic formal representations explicit, interactive, recoverable,
and progressively unnecessary as learners become fluent.

This is a product-focus decision, not an architectural reset. The current
implementation, canonical authority order, governed authoring pipeline,
semantic/runtime/renderer boundaries, exemplar-first promotion cadence, and
active Animation Catalogue work remain authoritative. When the directional
handoff `../../kinetic_press_domain_literacy_rewrite_handoff.md` conflicts with
those sources, the roadmap, canonical principles and authoring contracts,
accepted decisions, and current implementation override its speculative API,
package, sequencing, or migration suggestions.

Domain literacy also does not narrow KP to symbolic equations. Code, Graph2D,
Graph3D, diagrams, prose, and other domain-owned representations remain part
of the accepted cross-domain envelope. Each domain retains its own semantic
frontend and renderer while sharing only the already-proved upper authoring,
runtime, hosting, URL, review, and publication seams.

## Reason

The domain-literacy framing clarifies the learner outcome: KP succeeds when a
learner can inspect, navigate, and manipulate the authentic artifact with
greater fluency after the temporary scaffolding recedes. It gives the existing
work on semantic identity, provenance, attention, deterministic transformation,
and reversible presentation a coherent product purpose without discarding the
substantial architecture and evidence already accumulated.

The handoff also contains useful implementation hypotheses, especially rule
application, view-only folding, progressive compression, and failed or
ambiguous matching. Those hypotheses should be tested through the existing
architecture and review cadence rather than treated as authority to create a
parallel semantic core, universal rewrite DSL, or math-only queue.

## Consequences

- Use domain-literacy value as a lens for choosing and reviewing exemplars:
  does the artifact reveal expert structure, preserve authentic notation,
  expose provenance, and help scaffolding eventually recede?
- Continue the current integration Rule Application checkpoint. Its
  `match -> bind -> instantiate -> rewrite -> reduce` grammar is one concrete
  expression of the emphasis, not a replacement architecture.
- Preserve Graph2D, Graph3D, code, and other accepted domain work. Evaluate
  them by the same product outcome without forcing them through equation
  semantics or one universal renderer.
- Treat the handoff's TypeScript types, package boundaries, authoring levels,
  and proposed follow-up order as exploratory design material.
- Keep active task order in the roadmap and Theseus, not in a compact Codex
  context paragraph.
- Unsupported generation continues to return typed repair gaps; models do not
  gain semantic or presentation authority from this product emphasis.

## Alternatives Considered

- **Let the handoff supersede the current architecture:** rejected because its
  implementation sketches do not account for the governed compiler,
  presentation profiles, renderer ownership, typed gaps, and promotion
  evidence already present.
- **Treat domain literacy as a math-only pivot:** rejected because the product
  thesis applies to authentic formal representations across existing
  equation, code, graph, diagram, and 3D domains.
- **Keep the idea as an unlinked essay only:** rejected because future work
  needs a durable product-selection lens, while still preserving a clear
  authority boundary.

## Follow-Ups

- Use the accepted emphasis during future product and exemplar reviews.
- Develop measurable transfer criteria before claiming that an artifact
  improves domain literacy.
- Promote new semantic or presentation abstractions only through the existing
  exemplar, human-checkpoint, and structurally-different-caller cadence.
