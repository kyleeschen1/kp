# Checkpoint And Product-Surface Sequence

Date: 2026-08-02
Status: accepted; rank-5 condition satisfied and successor sequence active

## Decision

Record the consolidated six-loop review with these dispositions:

- **Project one vector onto another:** conditionally approved. Its remaining
  defect is an over-broad label exclusion or attenuation radius: the `B` label
  fades its line even when no actual overlap exists. Diagnose that mechanism,
  make the smallest local correction, preserve true collision protection, and
  present the live checkpoint before rank-5 promotion.
- **Verified generated solve and `ExplanationSpineV1`:** approved as KP's first
  human-gold deterministic generated session. This approves the reviewed
  visual treatment, wording, and order; it does not authorize untrusted model
  output or a live model dependency.
- **Graph3D mesh-to-donut:** keep as an internal renderer and continuity
  diagnostic. Do not spend current learner-product effort on its scale, labels,
  fallback parity, or publication treatment.
- **Programming addition trace and comparison:** keep internal. They remain
  native host and synchronized-caller evidence without advancing the rank-23
  BFS family or creating a public programming curriculum.

Adopt the following product topology direction:

```text
framework-neutral KP engine
├── Internal Studio
│   ├── Animation Catalogue
│   └── Internal Editor
└── Public Web
    ├── mission and product site
    ├── lessons and curated content
    └── constrained Public Editor
```

Svelte 5 is the recommended declarative host UI for catalogue, editor, and
first-party player composition. SvelteKit is the eventual application and
publication framework for Internal Studio and Public Web. The public editor
starts as a bounded route within Public Web and splits into a separate
application only if authentication, security, deployment, or scale supplies a
real reason.

`KpAnimationAsset`, semantic objects and transformations, runtime samplers,
playback clocks, renderer-neutral frames, compiler and authoring commands,
publication bundles, and renderer-port contracts remain framework-neutral.
Svelte components own application composition and lifecycle; they do not
become animation assets, semantic truth, or a second animation runtime.

## Recommended Order

1. Correct the rank-5 vector label attenuation, inspect it live, and close the
   current human checkpoint with objective promotion evidence.
2. Run one reversible Svelte 5 catalogue-shell exemplar over the existing
   runtime and renderer ports. Preserve the current route, review composer,
   selected-capability loading, performance ceilings, and static truth.
3. Pressure the approved host with rank 6, the matrix-to-linear-map exemplar,
   before generalizing the framework seam.
4. Build Internal Studio v0 around one framework-neutral typed authoring
   session: catalogue, preview, structured inspection, validated commands,
   undo/redo, review, and export. Adopt SvelteKit for this application only
   after the shell exemplar passes its go/no-go gate.
5. Freeze the portable publication bundle and establish Public Web v0 with a
   mission page and a small curated lesson set. Prerender meaningful prose,
   math, accessibility truth, and static fallbacks; activate animations lazily.
6. Complete M4 context-specific output encoding, then add M5 as an internal
   editorial-candidate workflow over verified claims and human-gold examples.
7. Build the constrained Public Editor only after the internal authoring
   contract, publication boundary, untrusted-text boundary, and public safety
   policy are proven.

The stable animation ranks are not recomputed. Rank 6 remains the next content
frontier after rank 5, followed by the derivative bridge at rank 7. The new
items are platform gates interleaved with those content exemplars so that real
assets pressure each infrastructure choice.

## Consequences

- The bounded vector correction is complete. The next implementation is the
  reversible Svelte 5 catalogue-shell exemplar, not a broad migration or
  public-site build.
- The catalogue remains the internal browse, play, compare, health, and review
  surface. The editor becomes a distinct consumer of the same asset and
  authoring contracts rather than adding editing machinery to every catalogue
  row.
- Internal and public editors share typed commands and compilation. The public
  editor exposes a policy-limited projection rather than becoming a second
  authoring implementation.
- Public Web publishes only explicitly curated assets and lessons; 36/36
  internal hostability does not imply public publication.
- Svelte adoption must be complexity-negative and evidence-gated. A shell
  experiment may not move the shared clock into broad reactive UI state,
  eagerly load KaTeX, Three.js, programming, or diagnostics, or widen the
  existing route and Core Web Vitals targets.
- The first public site is a mission and lesson proof, not a full curriculum,
  account system, classroom product, or learner model.
- The generated solve approval supplies one gold example. M5 still needs the
  M4 boundary and useful negative or revision examples before model-authored
  candidates become a product workflow.

## Follow-up outcome

The bounded endpoint-label correction removed the padded semi-opaque backdrop
that faded the non-overlapping `B` line and replaced it with a tightly bounded
transparent halo. The seven-state review command passed, and the user approved
the live result on 2026-08-02. Rank 5 is therefore promoted through
`animation.dot-projection.basic`; the reversible Svelte 5 catalogue-shell gate
is next, immediately before rank-6 matrix-to-linear-map pressure.

## Rejected Alternatives

- Build three independent applications immediately. Rejected because Internal
  Catalogue plus Editor belong in one Studio, while the public site, lessons,
  and initial public editor can share one application and publication policy.
- Rewrite animation renderers as Svelte components. Rejected because it would
  compromise export, embed, test, and framework-neutral host contracts.
- Build the public editor before the internal editor. Rejected because it would
  force safety and UX decisions before the authoring command model is proven.
- Begin broad public-site or LLM work before closing rank 5. Rejected because
  one tiny known visual defect is the only remaining current checkpoint gate.
