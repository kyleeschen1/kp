# Stable Animation Promotion Order And Demo Breadth

Date: 2026-07-28
Status: accepted

## Decision

KP will maintain one persistent animation-promotion order in
`threads/animation-library-promotion.md`. Future sessions must retrieve that
order instead of synthesizing a new sequence from older plans.

The next content exemplar remains exact fraction quantity identity through
`1/3 + 1/6 = 1/2`. Arithmetic place-value exchange, a bounded economics
equilibrium shift, and a bounded constant-force work-energy explanation move
directly behind it for visible demo breadth. Vector/matrix, derivative,
integral, quadratic learner promotion, remaining arithmetic algorithms,
precalculus closure, diagrams/data, programming, and governed cross-domain
generation follow in the stable thread order.

Short harvest promotions may interleave after their prerequisite exemplar is
approved. They do not silently reorder the capability-opening frontier.

The next approved implementation loop must include a bounded project-memory
repair prelude before content work:

1. reconcile the roadmap, active/supporting threads, and current Theseus plan
   projection with the stable ledger;
2. mark older sequences as superseded for ordering while retaining rationale;
3. derive current progress from catalog and release evidence;
4. add a consistency check for current/next/status drift.

This records work for the next loop; it does not activate a run contract.

## Reason

Recent records preserved valuable rationale but disagreed about whether
foldable distribution, derivatives, or exact quantity models were current.
That allowed a model to produce a plausible but stale recommendation.

A stable dependency-informed order improves:

- cross-session continuity;
- visible library progress;
- user control over priority;
- honest promotion status;
- repeatable model planning;
- separation between durable direction and executable authorization.

Arithmetic, economics, and physics are advanced because the library should
demonstrate versatility before every symbolic or calculus family is complete.
The chosen exemplars are deliberately bounded: exact arithmetic rather than a
curriculum, parameterized supply and demand rather than an economics solver,
and constant-force work/energy rather than a physics engine.

## Consequences

- The promotion thread owns rank and progress; the roadmap only summarizes it.
- Theseus owns only approved executable slices and evidence.
- A model may recommend a reordering, but may not enact one without an accepted
  decision.
- New domain breadth must reuse one semantic trace, shared clock, canonical
  renderer boundaries, and existing promotion laws.
- A failed generic invariant may pause a row, but does not silently replace the
  rest of the queue.
- Faster family harvests are expected once a frontier exemplar establishes the
  needed capability.

## Alternatives Considered

### Recompute the order at every planning session

Rejected because equally plausible source documents produced inconsistent
answers and obscured progress.

### Freeze one total order permanently

Rejected because exemplar evidence can expose a real dependency or product
opportunity. Reordering remains possible through an explicit accepted
decision.

### Finish all algebra before cross-domain demos

Rejected because it delays proof that KP is a general semantic animation
medium and encourages equation-specific architecture.

### Move broad economics and physics systems forward

Rejected. Only bounded vertical exemplars move forward; domain engines and
curriculum remain out of scope.
