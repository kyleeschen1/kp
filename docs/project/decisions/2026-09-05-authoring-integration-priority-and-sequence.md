# Authoring Integration Priority And Sequence

Date: 2026-09-05
Status: ACCEPTED DIRECTION; new execution contract requires separate approval

## Decision

Proceed with the architecture through the authoring experience. The immediate
product test is whether an author can define a model, apply verified changes,
compose an explanation, bind prose and attention, preview exact historical
states, and publish from one coherent source. Reader delivery remains the
destination; external reader or educator discovery does not gate this
architecture integration sequence.

The user accepted the detailed authoring-first revision on 2026-09-05 and
requested a Theseus long-loop proposal plus durable recording. That accepts
this direction, not an unseen slice contract or unrestricted execution.

## Architecture To Preserve

- Domain-owned typed objects and verified operations establish meaning.
  Generic state updates do not establish mathematical equivalence, operation
  legality, animation support, or publication readiness.
- Immutable aggregate snapshots, explicit transactions, derived graphs,
  applied families, and logical composition retain state authority. Sampling
  is ephemeral; durable history consists of meaningful endpoints/checkpoints.
- Typed math and optics join that aggregate through an adapter. A semantic
  selection path is not entity identity. Legacy scene APIs may project a
  compatibility view; they must not create a second authoritative history.
- Serializable mathematical structure is distinct from callable evaluation
  capabilities. Functions remain local capabilities with explicit identity
  and version pins; they are not persisted inside snapshot values.
- Verified domain material enters the existing governed canonical compiler
  through a source-authority adapter. There is no second animation compiler,
  renderer-independent CAS, global salience store, or replacement clock.
- Article owns prose and explanation order; typed companion declarations may
  bind values, formulas, operations, and semantic focus where current grammar
  is insufficient. Derive score/runtime inputs instead of authoring duplicate
  beat lists. Arbitrary JavaScript in Markdown and automatic verification of
  free prose are not accepted shortcuts.
- Existing domain renderers express medium-specific paint. Preserve approved
  choreography and semantic-scene, salience-plan, reader-focus,
  attention-projector, and cross-view-attention ownership.
- Constructible, verifiable, animatable, and publishable are separate
  capability dimensions. Unsupported paths return typed repair gaps.

## Revised Milestone Sequence

These are outcomes and dependencies, not an executable slice queue or a
promise that each milestone fits one loop. Loops 1–4 remain completed history.
The earlier three/five/seven-loop estimate is superseded by this sequence.

1. **Correctness and author-task baseline.** Bound independent composition to
   the evidence actually checked; freeze representative author tasks and
   current setup cost. Tasks cover parameter edits, demand/tax composition,
   selected rewrites, historical selection, prose/focus binding, and publication.
2. **Internal authoring assembly.** Assemble model definitions, explicit
   transformations, named explanations, graph/handle wiring, recovery, and
   evaluation without forcing authors to coordinate the low-level pipeline.
   Measure orchestration reduction and disclose helper cost. Do not promote
   a public facade on one market caller.
3. **Bounded typed-math/state bridge.** Retain callable/data separation,
   immutable selection correspondence, pinned recovery, static shape
   inference, and honest dynamic dimensions. Use the existing affine Jacobian
   and quadratic Hessian as nonvisual pressure, not new renderer migrations.
4. **First model-to-preview vertical.** Connect an isolated supply-tax author
   specimen to canonical economics, existing compiler authority, reader clock,
   Graph2D SVG, and KaTeX labels. First reproduce the reviewed inputs exactly;
   then prove a separately identified parameter variation with correct prose,
   labels, welfare, and static facts. Stop for authoring/API and visual review.
5. **Structural equation pressure.** Under a separate approved contract, carry
   an already reviewed distribution transition from the canonical
   fraction-composition asset through the seam, then pressure it with
   carrier-preserving simplification. Reuse operation-specific legality and
   native compositor mechanisms. This is the second structural proof required
   before public API promotion or migration waves.
6. **Everyday author workflow and publication.** Unite typed model/bindings,
   Article editing, derived score, diagnostics, source navigation, last-valid
   preview, historical inspection/explicit branching, and local compile into
   the existing versioned vignette/static-publication path. Extend Article
   grammar only for demonstrated friction. Preserve authored prose on rebuild.
7. **Bounded reusable knowledge and procedures.** Introduce referable
   definitions, claims with evidence/assumptions, formula schemas, and typed
   procedures without flattening them into one ontology. First prove
   distribute-then-evaluate with nested trace granularity; later pressure
   matrix multiplication invoking dot products. Reuse Jacobian/Hessian macro
   descriptors and separate compact/expanded presentation from semantic truth.
8. **Authoring frontends and domain pressure.** Converge bounded LaTeX,
   TypeScript, and model-authored inputs on the proved objects and verified
   operations. Run a small real-model smoke after the API stabilizes, then a
   pinned benchmark; handwritten generation-shaped fixtures are not live-model
   evidence. Generate repetitive plumbing only. Bring existing code and
   Graph3D frontends through shared upper boundaries one domain at a time.
9. **Narrow public promotion and adjacent retirement.** Promote only tiers
   demonstrated by market and structural-equation callers. Migrate existing
   consumers in independently reversible waves, retiring each obsolete
   authority path with its last migrated caller. Publication and capability
   evidence must remain explicit; do not equate a convenient facade with
   catalogue-wide support.

Public promotion may proceed incrementally after milestone 5 for a proved
tier; it need not wait for every knowledge or domain feature. Conversely,
completion of a market preview alone does not justify it.

## Correctness Qualification From Review

The independent-group declaration permits arbitrary cohort size while endpoint
validation compares authored and reversed order. That comparison is insufficient
for three or more members. The review reproduced a counterexample from zeroed
drivers: A writes a=1; B writes b=Number(a!==c); C writes c=1. ABC and CBA agree
on b=1, while ACB produces b=0. The current certificate accepted the first
comparison. Relevant sources are:

- `src/semantic-state/state-family-composition-declaration.ts`
- `src/semantic-state/state-family-composition-endpoints.ts`

The next run must turn the reproduction into a committed regression and
reject cohorts larger than two with a typed gap before authoring integration.
Two-member endpoint checking must not be described as a universal confluence
proof. Pressure its existing alias/read boundaries without inventing dynamic
proxy authority. Arbitrary independent groups require a separately reviewed
read/write capability contract, including aliases and derived dependencies;
runtime observation can verify that contract, not replace it.

This qualifies an overbroad certification claim; it does not discard the
completed ordered composition, exact addressing, immutable history, or
domain-model work. The implementation is not repaired by this document.
