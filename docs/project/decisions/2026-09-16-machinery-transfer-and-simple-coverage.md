The broader trajectory is: equation transfer and authoring cost evidence;
persistent text coordination in the existing centroid code example; selected
assumption/contrast, representation and provenance-use experiments; modest
formative checks of understanding against strong static explanations. Later
items express direction, not automatic execution of a large programme.

## Reason and consequences

An experiment earns engineering time by establishing a reusable capability,
exposing a precise unsupported boundary, or rejecting a treatment. A finished
chapter is optional. Preserve domain-owned semantics, stable identities,
assumptions and provenance while keeping layout and motion replaceable. Share
interaction expectations across media without forcing one renderer or geometry.

Alternatives considered: more polished mechanics lessons, an exhaustive motif
buildout, and an all-purpose reader/editor rewrite. Defer those until concrete
transfer evidence justifies their cost. No new curriculum, renderer, recursive
proof-tree framework, user study recruitment or deployment is authorised here.

## 2. A deliberately simple coverage dashboard

The user wants predicted semantic moves and visual motifs by discipline, with
checks beside implemented items. Earlier dashboards became too complicated.

Use [small Markdown checklists](../repertoire/README.md) as the editable source.
Each checked row names a bounded capability and links to evidence. Keep semantic
moves separate from their visual treatments. Predictions are planning hypotheses;
unchecked means implementation has not been confirmed at that scope. A check
does not imply arbitrary authoring, certification, promotion or every browser.

The approved view is discipline → topic → two checklists: semantic moves and
visual motifs. One discipline selector and evidence links provide navigation;
the lists sit side by side on wide screens and stack on narrow screens.

Keep one index and one small file per discipline, plus shared reading motifs.
No database, scores, percentages, status taxonomy, duplicate generated catalogue,
or mandatory full-inventory regeneration. Update only the affected row/file.
The implemented web view at `/experiments/repertoire/` renders these files and
packages linked evidence as plain text, without creating another status source.
Existing technical inventories remain authoritative for technical claims.

Dashboard verification: `npm run test:repertoire` checks parsing and linked
evidence; `npm run visual:repertoire` checks discipline navigation, reload,
evidence delivery, phone overflow and reading without JavaScript. Typecheck,
architecture gates and the production bundle also pass. Human review of the
initial dashboard remains the next visual checkpoint.
