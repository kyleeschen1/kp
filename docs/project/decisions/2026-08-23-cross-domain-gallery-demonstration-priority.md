# Cross-Domain Gallery Demonstration Priority

Date: 2026-08-23
Status: accepted direction; production-seam maturation and programming light
mode added; exact graph exemplars remain proposed

## Decision

Prioritize one bounded cross-domain generation gallery for demonstration next
week. Show equation, Graph2D, Graph3D, and code artifacts entering the same
governed request, capability, sequencing, hosting, URL, Review, and evidence
envelope while retaining domain-owned truth and rendering.

Build the collection through intended production seams rather than a
gallery-only facade. Its pinned requests and expected result dispositions
should remain useful as cross-domain conformance cases after the demonstration.
Only promote a local seam after a reviewed exemplar and a structurally
different caller establish the reusable boundary.

Keep integration, trigonometric representation rewrites, inequality reversal,
limits, and the other post-derivative family candidates as live options. They
are paused by the demonstration deadline, not rejected or superseded.

## Meaning Of “Same Pipeline”

The shared pipeline is an upper contract, not one semantic compiler:

```text
content brief
-> LLM instructional proposal and domain requests
-> kp.animation-generation-request.v1 validation
-> capability discovery and exact frontend routing
-> domain-owned verification and canonical semantic trace
-> pedagogical score plus domain-owned presentation recipe
-> one deterministic animation asset, vignette, and grounded explanation
-> KaTeX, SVG, WebGL, or code renderer adapter
-> Catalogue/gallery, Article, URL, and Review projection
```

Equation solvers and operation binders, Graph2D function/model compilers,
Graph3D semantic-scene compilers, and code compiler/AST/interpreter frontends
remain separate authorities. They may share accepted, semantic-plan-only, and
typed-repair result projections, but not syntax, geometry, scene topology,
execution truth, or renderer implementation.

## Demonstration Boundary

Use pinned, deterministic requests for the gallery. A live LLM may propose the
same requests during development, but the demonstration must not depend on a
network call or treat model output as authority.

The target collection contains:

1. the approved `2^x = 7` logarithmic solve as the recommended equation
   reference, because it composes balanced application, exponent/log rewrite,
   persistence, isolation, and a fractional exact result;
2. one bounded Graph2D function transformation, preferably
   `y = x^2 -> y = (x - 2)^2`;
3. one bounded Graph3D parameter transformation, preferably a fixed-camera
   saddle surface flattening as its denominator increases;
4. the approved TypeScript extract-helper refactor routed through the shared
   request envelope and shown in an explicit light optical theme without
   changing syntax, semantics, or motion; and
5. one explicit unsupported request that returns a useful typed gap.

Python may appear as a second code caller if it requires no new choreography.
The existing Graph2D economics model and Graph3D mesh-to-donut host proof are
fallback demonstrations only. If used, label their actual maturity and do not
present them as general function or scene generation.

## Guardrails

- Do not build a universal graph parser, scene graph, renderer, or arbitrary
  code animator for the deadline.
- Do not add a second clock, scheduler, review system, or gallery-only semantic
  store.
- Do not make the Catalogue a planned-work dashboard or hide missing frontend
  evidence behind executable-looking cards.
- Keep Three.js lazy, resource-leased, and paired with semantic SVG fallback.
- Keep code parsing and compiler work build-time-only; a verified code variant
  without a governed artifact remains `semantic-plan-only`.
- Treat light and dark code themes as separate optical systems over shared
  semantic roles. Do not derive light mode through color inversion or reuse
  dark-only glow, brightness, or saturation effects without review.
- Keep every explanation claim grounded in the domain trace.
- Preserve static truth, direct seek/rewind, accessibility, and exact URLs.

## Stop Condition

Stop first at a human review of the TypeScript light-theme exemplar, then at a
human review of the curated cross-domain collection. The first checkpoint may
authorize Python as a structurally different code-theme pressure caller; it
does not authorize a global theme migration. Do not use the deadline to
promote graph families, generalize unrelated renderers, migrate every caller,
build live editorial generation, or discard the retained mathematical family
options.
