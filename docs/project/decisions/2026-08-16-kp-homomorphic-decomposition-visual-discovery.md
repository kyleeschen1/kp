# Decision 2026-08-16: Homomorphic-Decomposition Visual Discovery

Date: 2026-08-16
Status: accepted

## Decision

Amend the clean-path log-product human checkpoint with one bounded visual
discovery pass before symbolic migration wave A. The canonical exemplar is
`ln(xy) -> ln(x) + ln(y)`.

Preserve the already accepted semantic law:

- factor occurrences are the identity continuants;
- the source `ln(...)` application occurrence withdraws;
- target logarithm applications are derived successors belonging to the same
  logarithm concept, not copies of the source occurrence; and
- the source product relation and target sum relation are distinct structural
  relationships rather than one persistent glyph identity.

Test this provisional visual rhythm:

```text
hold the source
-> withdraw the outer application as one cohesive shell
-> redistribute the persistent factors
-> grow target parentheses around the settled factors
-> introduce each function name just after its parentheses
-> resolve the target connector
-> hold the native target
```

The handoff must remain continuous. Shell withdrawal overlaps the beginning of
factor redistribution, and target reception begins before the learner can read
an empty or mathematically misleading intermediate expression. Exact timing,
paths, opacity, easing, and staggering remain exemplar-local and provisional.

## Execution Timing

This is part of the existing mandatory log-product checkpoint, not polish to
perform after migration. Migration wave A remains gated until the revised
binary exemplar receives human visual approval.

Use the two-factor product as the only tuning authority. The existing
three-factor caller checks cardinality without becoming a second tuning
surface. After binary approval, pressure the same rhythm with the quotient
caller `ln(x/y) -> ln(x) - ln(y)`: persistent operands redistribute, the
fraction relationship withdraws, target applications receive the operands,
and the subtraction relationship appears. Only that structurally different
caller can justify promoting a reusable homomorphic-decomposition recipe.

## Discovery Contract

- **Canonical exemplar:** `animation.algebra.log-product.product-to-sum`.
- **Observable acceptance:** the learner follows the factors without mistaking
  wrapper fan-out for identity duplication, cancellation, or a generic fade;
  parentheses visibly receive each factor before `ln` completes the wrap; the
  connector arrives only after the target applications are legible.
- **Durable checks:** semantic identity and provenance, exact native endpoints,
  deterministic direct seek, rewind, interruption, and reduced-motion
  settlement remain unchanged.
- **Preservation boundary:** family data, semantic contract, transformation
  compiler, native endpoint ownership, catalogue identity, clock, host, and
  accessibility truth.
- **Rollback unit:** one presentation-recipe/transit-policy change for the
  binary exemplar.
- **Promotion criterion:** human approval of the binary choreography followed
  by successful three-factor cardinality pressure and quotient structural
  pressure without a new clock, renderer, semantic identity rule, or
  caller-authored geometry.

## Iteration Cadence

Subjective motion discovery and infrastructure promotion are separate lanes.

During discovery, change only exemplar-local presentation policy and run the
smallest semantic preservation test plus one deterministic visual capture.
Do not regenerate the catalogue, rebuild every architecture ledger, run the
complete browser matrix, or generalize a type family merely to compare two
choreographies.

After human approval, encode motif-specific regressions, exercise the
contrasting caller, generate inventories, run broader browser and bundle
checks, and propose promotion separately. A visual alternative that still
requires semantic, catalogue, or host changes fails the intended discovery
seam and should stop for architectural diagnosis.

## Reason

The prior wrapper-splitting treatment was semantically valid but visually
dense: multiple `ln` glyphs overlapped before separating, making occurrence
lineage difficult to read. The revised rhythm gives persistent operands
continuous motion while treating derived applications as visible reception.
It also reuses the established function-wrapping visual word.

The previous checkpoint amendment touched 54 files because semantic
generalization, a new caller, generated inventories, catalogue ratchets,
verification, and visual tuning happened in one pass. That promotion work was
useful, but repeating it for every aesthetic choice would make human discovery
too slow and give future LLMs incentives to bypass the canonical path.

## Consequences

- Symbolic migration wave A does not begin from the current provisional
  wrapper-splitting choreography.
- The semantic identity correction and multi-factor family remain accepted;
  only presentation choreography is reopened.
- Homomorphic decomposition is a candidate visual recipe, not a universal
  motif or catalogue-wide rule.
- A future LLM selects the semantic operation and role bindings; it does not
  author the dissolve, paths, timing, geometry, or renderer behavior.
- A successful iteration-speed architecture should make another choreography
  candidate primarily a presentation-policy edit with focused evidence.

## Alternatives Considered

- **Keep overlapping wrapper fan-out:** rejected as the selected direction
  because the source and successors are difficult to distinguish during the
  overlap.
- **Make one source `ln` persist into every target:** rejected because one
  occurrence cannot preserve identity through one-to-many fan-out.
- **Tune product and quotient simultaneously:** rejected during discovery;
  it obscures which choreography is being judged and promotes too early.
- **Defer the visual change until after migration:** rejected because migration
  should preserve an approved exemplar rather than distribute provisional
  presentation behavior.

## Follow-Ups

1. Insert a bounded log-product visual-discovery slice before migration wave A.
2. Implement only the binary candidate and stop for human visual review.
3. After approval, pressure the existing three-factor caller and the quotient
   caller before deciding whether to promote the recipe.
4. Measure changed source files, generated-file churn, focused-check duration,
   and time to a reviewable capture as iteration-speed evidence.
