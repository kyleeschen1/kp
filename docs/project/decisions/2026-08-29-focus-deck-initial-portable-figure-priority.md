# Focus Deck as the Initial Portable Kinetic Figure Projection

Date: 2026-08-29
Status: accepted

## Decision

Make the **Focus Deck** KP's active learner-facing product experiment. A Focus
Deck presents a document-backed sequence of compact attentional beats, each
with one clear instructional claim and, when needed, one executable Kinetic
Figure. It is the initial format for testing the vision of small,
interoperable, executable teaching artifacts that can be read alone, embedded,
linked, combined, and revisited.

The Focus Deck is a projection of existing Article, vignette, semantic-focus,
and motion-block authority. It is not a new source format, animation runtime,
or semantic model. The existing `kp.article-deck.v1` derivation is the leading
implementation seam, but the first exemplar must pressure it before it is
renamed, generalized, or treated as a complete product contract.

Preserve flashcards as a sibling projection from the same durable semantic
material. A later card may hide a selector, ask for the next checkpoint, or
request an explanation of a transformation without copying the deck's prose
or animation. This priority does not authorize an SRS scheduler, learner
accounts, or a second flashcard model.

## First Exemplar

Use the approved whole-equation log-product figure
`animation.algebra.log-product.equivalence-frame` in the existing paragraph
Kinetic Figure experiment. Add an opt-in Focus Deck projection that reuses the
same canonical operation, native endpoints, reading-state identities,
deterministic clock, and Native KaTeX owner. The retained left side makes the
transformation read as an equality, not an unexplained replacement.

The deck should expose four stable attentional beats:

1. orient to `ln(xy)`;
2. identify the product inside the logarithm;
3. make the product-law pattern available while the source remains settled;
4. apply the existing rewrite and settle on
   `ln(xy) = ln(x) + ln(y)`.

The transition belongs between beats 3 and 4. Back and Next navigate beats;
playback controls appear only when the current beat owns motion. The pattern
is contextual support for its beat, not permanent stage furniture.

After human approval, pressure the projection with the already-approved
`2^x = 7` logarithmic solve. It is the preferred second caller because its
longer sequence tests navigation, checkpoint restoration, and local playback
without reopening choreography. Graph2D demand shift and the approved
TypeScript extract-helper transformation are the preferred later cross-domain
callers.

## Reason

The deck is KP's most atomic and portable presentation shape: it makes
discrete conceptual states easy to navigate, discuss, embed, and recombine.
Unlike a conventional slideshow, it can remain document-backed, semantically
addressable, searchable, and executable. Unlike continuous scrollytelling, it
does not make scroll geometry the primary way to control a transformation.

The log-product exemplar is deliberately small. Its animation and native
rendering have already passed review, and its current paragraph, split,
scrollytelling, and stacked projections provide direct comparison evidence.
That isolates the new question: whether the Focus Deck is a clearer host for
joint attention and portable reuse. Beginning with the unresolved integration
template would confound projection design with an unfinished animation motif.

## Consequences

- Keep Article source, animation assets, vignettes, semantic IDs, and clocks as
  authority; derive deck beats instead of separately authoring slides.
- Keep scene navigation distinct from motion playback, scrubbing, and speed.
- Give every beat a semantic URL and restore it directly without replaying
  intermediate motion.
- Retain a real searchable transcript and exact return path to the source
  Article passage. Inactive visual presentation must not erase source text
  from native find, selection, or accessibility.
- Keep the deck quiet: one default ink system, localized semantic focus, no
  auto-advance, and no permanent control chrome unrelated to the active beat.
- Preserve phone, reduced-motion, static, direct-seek, reverse, and theme
  behavior through existing renderer and host contracts.
- Keep the Paragraph Kinetic Figure, Stacked Station, Rule Ledger Passage,
  integration Rule Application candidate, Catalogue, Graph2D, Graph3D, and
  code work as preserved evidence or sibling projections. This decision does
  not delete or globally replace them.

## Non-Decisions

- Do not define one universal slide size or require full-screen presentation.
- Do not equate an attentional beat with a runtime animation keyframe.
- Do not add a deck-specific semantic store, animation clock, or renderer.
- Do not make all Articles automatically good decks; derivation may return a
  typed editorial gap when a passage lacks a coherent beat boundary.
- Do not promote a shared Focus Deck component or authoring grammar before the
  log-product checkpoint and a structurally different second caller.
