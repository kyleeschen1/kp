# Generation, Editorial, and Pruning Roadmap Placement

Date: 2026-07-28
Status: accepted

## Decision

Keep animation promotion rank in
`docs/project/threads/animation-library-promotion.md`, and add platform
integration milestones between its ranked exemplars:

1. repair promotion-memory drift before the exact-fraction exemplar;
2. complete exact fraction, place-value addition, economics equilibrium, and
   constant-force work-energy as the early visible demo tranche;
3. declare stable authoring, internal runtime/compiler, and experimental API
   tiers;
4. compile the existing verified linear-equation generator trace into canonical
   `KpAnimationAsset` output with stable selectors and lineage, an
   instance-aware reader descriptor, conformance coverage, and fail-closed
   unsupported presentations;
5. make the first generated solve-x session carry a deterministic
   `ExplanationSpineV1`, learner state, an approved vocabulary contract, and
   verified claim references;
6. introduce context-specific output encoders before untrusted or
   model-produced editorial text ships;
7. add an LLM editorial candidate service only after deterministic generated
   sessions and human gold and negative examples stabilize; and
8. introduce a versioned shared-motif implementation boundary only when an
   intentional redesign supplies concrete caller pressure.

Pruning remains incremental and adjacent to migrations. Retire compatibility
facades, legacy presentation metadata, and superseded display routes when their
last real caller moves, while retaining semantic fixtures, conformance tests,
and historical evidence.

## Reason

The project needs both visible library growth and a credible path from verified
generated problems to polished explanations. Placing the bridge after four
bounded demonstrations prevents another infrastructure-only detour while still
testing the public authoring boundary before vector, matrix, and calculus
families multiply its callers.

The deterministic explanation spine separates mathematical truth and
pedagogical structure from editorial wording. It gives an LLM a constrained,
inspectable input after the underlying generated session works without a
model. Context-specific encoding is a security and correctness prerequisite
for that output, not a generic string utility.

Motif versioning and pruning benefit from real migration pressure. Introducing
them beside an intentional redesign or last-caller migration makes them
measurable and reversible; a universal registry or detached cleanup program
would add architecture before its required variation is known.

## Consequences

- Platform gates do not renumber or silently delay the stable animation
  promotion sequence.
- The verified problem generator becomes a canonical animation producer, not a
  parallel renderer or concept-room-only projection.
- LLMs can select wording only from verified claims, learner context, approved
  vocabulary, available visual arguments, and the deterministic explanation
  spine.
- A model outage or changed model output cannot alter playback, seeking,
  export, mathematical validity, or an already accepted session.
- HTML text-node, attribute, and script-JSON contexts remain distinct at the
  type and utility boundary.
- Shared motif redesigns can update certified callers centrally once a
  versioned implementation boundary is justified.
- Simplification work removes obsolete paths without discarding useful
  semantic evidence.

## Alternatives

- Bridge the problem generator immediately before the early demonstrations.
  Rejected because it would resume platform work before the newly stable
  content-led order proves breadth.
- Delay the generator until all domain promotions are complete. Rejected
  because too many callers would accumulate before the public authoring
  boundary is tested.
- Let an LLM generate explanations directly from raw problem text. Rejected
  because it merges mathematical truth, pedagogical structure, and prose into
  an unverifiable runtime dependency.
- Create one universal motif registry and one generic HTML sanitizer now.
  Rejected because motif variation is not yet concrete and output contexts
  require different encoders.
- Run a standalone pruning rewrite. Rejected because caller-adjacent retirement
  provides safer rollback units and clearer evidence.
