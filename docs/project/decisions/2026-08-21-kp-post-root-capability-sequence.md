# Post-Root Capability Sequence

Status: accepted as durable ordering; each execution tranche still requires an
approved Theseus run contract
Accepted: 2026-08-21
Applies to: Animation Catalogue capability expansion after narrow root promotion

## Decision

KP will advance through the following sequence:

1. close the existing TypeScript and Python refactoring capabilities through
   language-owned generation frontends;
2. build one finite sum/product binder exemplar and stop for human review;
3. add a structurally different binder caller, derive its case ledger, and
   consider narrow promotion;
4. build one bounded Graph3D semantic-scene transformation;
5. establish a differentiation transformation family; and
6. establish a distinct integration transformation family.

The first selected tranche is TypeScript/Python frontend closure. It should
reuse the approved free-shipping refactor assets without changing their
choreography. Its purpose is to prove that KP's request, capability, evidence,
sequencing, hosting, URL, Review, and bundle boundaries remain useful outside
native KaTeX.

## Rationale

- Code frontend closure is the lowest-subjectivity cross-domain proof now
  available: parsers, semantic operations, and exemplars already exist.
- Binder work follows because bound variables, scope, indices, expansion, and
  large-operator paint are foundational for sequences and calculus.
- Graph3D follows binder pressure so KP tests a different renderer and resource
  lifecycle without conflating that work with the next symbolic primitive.
- Differentiation and integration follow as separate families. Neither may be
  treated as generic large-operator spelling.

The seven older Direct equation families remain explicit case-ledger migration
debt. Migrate them when a family is touched or when a concrete gap requires
it; do not make historical bookkeeping block new semantic pressure. Root's
case ledger likewise remains the authority for selective follow-up rather than
forcing every visual case to precede expansion.

## Governing Cadence

- Existing approved code choreography is a preservation boundary. If frontend
  closure requires a visible change, stop and request a separate exemplar
  checkpoint.
- Every new visual family begins with one reversible exemplar and a human
  checkpoint.
- A structurally different second caller is required before extracting or
  promoting shared presentation machinery.
- New symbolic Direct families require a typed case ledger before promotion.
- Domain frontends own syntax, truth, operations, and invalid cases. Shared
  infrastructure owns only the request envelope, sequencing, hosting, URL,
  Review, and evidence projection.
- Unsupported work returns typed diagnostics. No generic fade, inferred
  correspondence, arbitrary code execution, or silent fallback is permitted.

Public layout, curriculum, educator tooling, live LLM editorial generation,
Scheme expansion, Graph2D function translation, and fraction structural repair
remain outside this sequence.
