# Decision 2026-08-15: Exhaustive Symbolic-Equation Convergence

Date: 2026-08-15
Status: accepted

## Decision

After proving the canonical semantic-motion compiler with quotient fusion,
distribution fan-out, cancellation, and one new clean-path logarithm-product
caller, migrate every supported symbolic-equation animation through that
compiler in the same convergence program.

Do not leave historical equation assets to migrate only when later feature
pressure happens. The equation catalogue is compositional and cumulative;
parallel authority paths would allow the same identity, ownership, timing,
endpoint, and motif-selection regressions to recur at later composition seams.

This is exhaustive within the equation domain, not a repository-wide universal
animation rewrite. Graphs, code, diagrams, Canvas, and WebGL retain their own
semantic and presentation compilers over the shared asset, clock, sampled
frame, capability, and host laws.

## Required End State

Every current equation-surface asset must have one generated inventory record
and exactly one disposition:

- `canonical`: all moving transitions enter through the canonical compiler;
- `adapter-backed`: a temporary typed adapter enters the canonical compiler and
  names its remaining retirement condition;
- `static-only`: intentional nonmoving truth with no animation fallback;
- `unsupported`: an explicit typed gap or human-review outcome; or
- `retired`: no production caller remains and the old path is removed.

No supported moving equation may select a raw motif, author local timing,
infer meaning from glyph text or DOM geometry, own a private clock, or silently
fall back to a generic fade. Each compatibility path retires beside the
migration that removes its final caller.

## Canonical Change Axes

Keep the following decisions independently replaceable:

```text
mathematical meaning
-> pedagogical intent
-> capability-selected presentation recipe
-> nominal deterministic tracks
-> renderer adapter
-> host and layout
```

- Semantic states, identities, lineage, operation bindings, and rewrite
  frontiers own mathematical truth.
- Pedagogical intent owns focus, explanation depth, and requested emphasis.
- Presentation recipes own operation-specific paths, phase ordering, easing,
  and optical treatment.
- Renderer-neutral tracks own deterministic direct sampling and history.
- KaTeX owns settled mathematical typography and accessibility; other
  renderers retain equivalent endpoint authority inside their domains.
- Svelte and page layout own application composition only.

## Migration Touch Tax

Every migrated equation asset must provide or inherit:

1. durable semantic IDs and exact source/target states;
2. total correspondence, provenance, lifecycle, role, cohort, and attachment
   coverage inside an explicit rewrite frontier;
3. compositional closure: a target state can become the next transition's
   source without identity reconstruction;
4. one canonical compiler call and one nominal executable authority;
5. one shared deterministic clock with direct seek, rewind, interruption, and
   reduced-motion settlement;
6. explicit lazy capabilities, static truth, and accessibility truth;
7. renderer-neutral tracks and renderer-owned measurement/paint;
8. generated generic conformance checks plus only family-specific semantic and
   choreography tests;
9. an inventory disposition, compatibility owner, and retirement condition;
10. removal of the superseded entry point when its final caller migrates.

## Shared Abstractions To Establish

- one minimal versioned equation-asset manifest;
- one semantic-motion compiler request and fail-closed result;
- one composition contract over stable semantic states and history;
- one semantic event vocabulary for causal precedence without authored
  normalized timing;
- capability-based recipe resolution rather than asset-authored motifs;
- stable semantic addresses shared by animation, prose links, URLs, review,
  tutoring, and later retrieval projections;
- central theme, typography, measurement, settlement, and reduced-motion
  policy where caller evidence proves the value is general;
- generated conformance tests and inventory from the same source of truth; and
- typed diagnostics suitable for humans and governed LLM draft repair.

Do not promote a universal trajectory, universal scene graph, cross-domain
renderer, plugin framework, new authoring language, or directory reorganization
as part of this convergence.

## Execution Order

1. inventory all equation assets and authority paths;
2. freeze semantic, visual, bundle, and accessibility baselines;
3. establish the compiler, composition, diagnostics, asset-manifest, and
   architecture boundaries from the seven promoted invariants;
4. route the three approved pressure callers without visual change;
5. build `ln(xy) -> ln(x) + ln(y)` through the clean path and stop for human
   review before generalization;
6. migrate all supported equation assets in family-sized reversible waves;
7. retire bypasses beside their final callers and prove zero unclassified
   equation authority paths;
8. connect governed LLM drafts only after the migration surface is stable;
9. run release, bundle, browser, accessibility, deterministic, and visual
   closure; and
10. resume symbolic breadth only after the measured migration demonstrates
    lower marginal authoring cost and fewer renderer/runtime changes.

## Reason

The former incremental strategy reduced immediate migration risk, but it
allowed correct shared abstractions to coexist indefinitely with competing
historical authorities. That is especially costly for cumulative derivations:
the target of one operation becomes the source of the next, so a latent
identity or ownership defect resurfaces at composition time rather than within
the original isolated animation.

The current equation catalogue is finite—24 equation surfaces—and already has
strong native KaTeX, semantic lineage, operation-presentation, deterministic
clock, accessibility, and catalogue infrastructure. A bounded exhaustive
cutover is therefore more likely to reduce total risk than a long period of
mixed authority.

## Consequences

- Equation convergence becomes the only active repository implementation lane.
- The clean-path visual checkpoint remains mandatory before broad migration.
- Existing reviewed choreography is preservation evidence, not an invitation
  to redesign every asset.
- Static, unsupported, diagnostic, and retirement dispositions are legitimate;
  exhaustive convergence does not mean forcing every row to animate.
- LLM presentation compilation waits until supported equation assets share the
  stable front door.
- The catalogue registry, conformance suite, compatibility ledger, and bundle
  evidence should derive from one inventory rather than parallel lists.
- User-authored economics files and non-equation product/layout experiments
  remain untouched.

## Alternatives Considered

- **Migrate only when later pressure appears:** superseded because cumulative
  composition repeatedly exposes old authority-path defects.
- **Rewrite all 40 catalogue assets through one compiler:** rejected because
  graph, code, diagram, and 3D callers require distinct semantic lowerers and
  presentation recipes.
- **Preserve adapters indefinitely:** rejected because adapters without named
  retirement conditions recreate the parallel system.
- **Migrate all assets before validating the public compiler:** rejected; the
  clean-path log-product caller is a short design gate before generalization.
- **Use migration as a visual redesign:** rejected; reviewed output is the
  preservation boundary unless a separately approved human checkpoint changes
  it.

## Follow-Ups

1. Review and approve the exhaustive convergence long-loop proposal.
2. Materialize one Theseus next action and run contract from that exact plan.
3. Stop at the log-product human checkpoint before migration waves.
4. After approval, complete every inventory disposition and compatibility
   retirement before connecting governed LLM drafts.
5. Measure whether subsequent symbolic animation work is primarily semantic
   content and bindings rather than renderer or runtime machinery.
