## Trial boundaries

Freeze ten cases before trial execution: three fraction cases (two supported
variations and one invalid/unsupported case); two existing algebra-task cases
(one supported variation, one presentation boundary); two momentum–energy cases
(one declared-assumption case, one assumption violation); three code cases
(two editorial/source-pin-preserving variations and one changed-source negative).
Select exact inputs through existing task contracts, save raw proposals and
expected outcomes, and do not replace failures with easier examples.

This is a current-agent engineering trial, not a blind model benchmark or an
estimate of general LLM precision. Record prior implementation knowledge.
Separate semantic checks, preview eligibility, selected-source application,
runtime behavior and human explanatory judgment. A reference-only host cannot
count as successful application of the proposed input.

For each case retain: raw input/revision, expected and actual checked outcome,
preview/apply result, located repair, source/adapter/engine edits, editorial
correction, commands and elapsed work. Separate measurement from estimates and
exclude unrelated waits. Use small repo-owned fixtures and a stable scoped test
command, not a new dashboard, database, telemetry service or agent platform.

## Verification and stop conventions

F = focused deterministic checks of the affected owner/fixtures plus diff review.
S = F, affected project types and `theseus workspace validate`.
B = S plus affected integration/browser cohorts, architecture and build/closure
checks where runtime imports change. Use `verify:impact` to select checks, not
to excuse known consumer coverage. Broad full-project release checks occur at
slices 3 and 24, not for every fixture change.

Each numbered row is one reversible commit boundary, including completed-slice
evidence. A result-only slice commits retained evidence, not invented code changes.
No-op repairs are recorded honestly. Routine failures and measured engineering
budget repairs are diagnosed, repaired and rechecked under standing authority.

Every slice stops for genuine safety/external authority, exceeded scope, expired
time ceiling, user pause or a necessary new visual judgment. Unsupported trial
inputs, semantic rejection and missing presentation are data, not stop conditions.
Rows below specify additional stops or the absence of one. Do not weaken a gate.

cards already accepted by the user. Existing checked domain artifacts own meaning;
native KaTeX and TypeScript renderers own paint; current hosts own clocks and
source application. Preserve fonts, choreography, selection, exact return and
co-visibility within their documented limits. No redesigned larger-code UI.

correctness and preservation. If a repair necessarily changes visual treatment,
stop at one independently reversible exemplar with its working server URL and
concrete inspection actions. Human acceptance precedes wider application; then
pressure the approved treatment with a second caller and the affected browser
cohort. Do not ask again about unchanged accepted visuals. Rollback is the
responsible slice commit, never removal of semantic guarantees.
